# 비슷한 서비스의 UX/UI 컴포넌트 조사 — hathway ChatGPT 플러그인

작성일: 2026-10-18 · 범위: 기업 분석 · 재무 · 공시 · 밸류에이션 서비스 15곳과 ChatGPT 의 표시 규칙

## 0. 이 문서를 읽는 법

- **디자인 시스템은 그대로 둡니다.** tyohnn graphite(어둡고 촘촘한 대시보드 톤)의 토큰과 컴포넌트를 바꾸지 않습니다.
  여기서 참고하는 것은 **무엇을 먼저 보이고, 어떤 컴포넌트를 어떻게 묶는가**뿐입니다.
- 각 패턴마다 서비스 · 컴포넌트 · 맨 먼저 보이는 것 · 배치 · 숫자와 단위 · 색의 뜻 · 빈 상태와 기다리는 상태 · 효과가 있는 까닭 ·
  우리 위젯 자리를 적었습니다.
- 우리 위젯 자리는 다섯입니다.
  - **인라인 카드**: 단추는 둘까지(주 하나, 보조 하나). 카드 안에서 스크롤하지 않고, 탭이나 깊은 이동을 두지 않습니다.
  - **캐러셀**: 3~8개. 항목마다 단추는 하나까지, 글은 두 줄 안쪽. 항목마다 그림이나 시각 요소가 있어야 합니다.
  - **풀스크린 보고서**: 지도 · 깊은 탐색처럼 넓은 자리가 필요한 일. 아래 입력창(composer)이 늘 보이므로 대화로 이어지게 짭니다.
  - **사이드바 홈**: 앱을 처음 열었을 때의 시작 화면.
  - **스레드 패널(서랍)**: 대화 옆에 머무는 작업면. 리서치 보드처럼 계속 쌓이는 것.
- 출처는 URL 로 달았습니다. 출처 문서에서 확인하지 못하고 화면을 써 본 일반적 관찰에 기댄 내용은 「관찰」이라고 표시했습니다.
  관찰 표시가 있는 줄은 구현 전에 실제 화면을 한 번 더 보고 확정합니다.

## 1. ChatGPT 가 정한 그릇의 규칙 (모든 설계의 바닥)

출처: OpenAI Apps SDK UI guidelines — https://developers.openai.com/apps-sdk/concepts/ui-guidelines ,
design guidelines — https://developers.openai.com/apps-sdk/concepts/design-guidelines

| 규칙 | 원문 요지 | 우리에게 뜻하는 것 |
|---|---|---|
| 인라인 카드 단추 | "Support up to two actions maximum, with one primary CTA and one optional secondary CTA" | 카드마다 주 단추 「대화에 추가」 또는 보내기 동작 하나, 보조 하나 |
| 중첩 스크롤 금지 | "No nested scrolling. Cards should auto fit their content" | 재무 표는 카드에 5행 정도만, 나머지는 풀스크린으로 |
| 카드 안 깊은 이동 금지 | 여러 drill-in, 탭, 깊은 내비게이션을 피한다 | 카드에 탭을 두지 않음. 기간 전환(연간/분기)은 칩 하나 정도로 제한하거나 대화로 넘김 |
| 캐러셀 | "Keep to 3–8 items", 항목마다 CTA 하나, 글은 두 줄(한 곳은 세 줄) | 피어 비교는 5~6개가 알맞음. 항목마다 미니차트가 「시각 요소」 역할 |
| 풀스크린 | 넓은 자리가 필요한 일, 입력창과 함께 동작 | 산업 지도 · 재무 전체 표 · 분석 작업대 |
| PiP | 대화와 나란히 도는 일. 끝나면 닫는다. 정적 내용을 넣지 않는다 | 우리 제품에는 쓸 일이 거의 없음 |
| 글꼴 | "Always inherit the system font stack", 커스텀 글꼴 금지(풀스크린 포함) | graphite 의 글꼴 토큰 대신 시스템 글꼴로 덮어야 함. 밀도 · 깊이 · 질감 토큰은 그대로 |
| 색 | 텍스트 · 아이콘 · 구분선은 시스템 색, 브랜드색은 주 단추에만. 그라디언트 · 패턴 금지 | 상승/하락 색은 「의미 색」이라 허용 범위. 배경을 칠하지 않고 숫자 글자색과 작은 막대에만 씀 |
| 로고 | 응답 안에 로고를 넣지 않는다(ChatGPT 가 앱 이름과 로고를 붙임) | 카드 머리에 hathway 로고를 두지 않음 |
| 뒤따르는 말 | 위젯 뒤의 모델 응답은 카드와 겹치는 내용을 반복하지 않는다 | 카드가 숫자를, 모델이 해석과 다음 질문을 맡게 역할을 가름 |

⚠ graphite 는 어두운 톤이지만 ChatGPT 는 밝은 모드에서도 위젯을 띄웁니다. 토큰의 밝은 모드 짝이 있는지 먼저 확인합니다.

### ChatGPT 자체의 금융 답변

- 관찰: ChatGPT 검색은 종목을 물으면 맨 위에 시세 카드(현재가 · 등락 · 기간 칩이 달린 선 차트)를 띄우고 그 아래에 글로 답합니다.
  이번 검색으로는 OpenAI 의 공식 설명을 찾지 못했습니다. 우리 플러그인의 카드는 이 시세 카드 **바로 아래나 대신** 서게 되므로,
  시세(주가 · 차트)를 다시 그리는 데 자리를 쓰지 말고 **DART 재무와 공시처럼 ChatGPT 가 갖지 못한 것**을 앞에 둡니다.
- MCP Apps 로 차트 · 폼 · 대시보드를 대화 안에 그리는 사례: https://glama.ai/mcp/servers/thinkchainai/stock-intelligence-mcp

### 2.1 Simply Wall St — 스노플레이크 · 적정가 막대 · 내러티브

출처: https://support.simplywall.st/hc/en-us/articles/360001740916 ,
https://support.simplywall.st/hc/en-us/articles/7240286929167 ,
밸류에이션 페이지 예 https://simplywall.st/stocks/ca/real-estate-management-and-development/tsx-wfc/wall-financial-shares/valuation

| 항목 | 내용 |
|---|---|
| 컴포넌트 | ① 스노플레이크: 다섯 축(가치 · 미래 성장 · 과거 실적 · 재무 건전성 · 배당) 레이더. 축마다 점검 6개, 통과 1점 실패 0점으로 0~6. 점수가 모양 · 크기 · 색을 정함 ② 적정가 막대: 주가와 적정가를 한 막대 위에 두고 「n% 저평가/고평가」를 크게 씀 ③ 내러티브: 사용자가 쓴 이야기 + 가정 + 거기서 나온 적정가 |
| 먼저 보이는 것 | 모양 하나(스노플레이크), 그다음 「62.3% 저평가」 같은 한 숫자 |
| 숫자 · 단위 | 적정가와 주가는 통화 단위, 괴리는 %. 20% 넘게 싸면 「Significantly Below Fair Value」, 그 안쪽이면 덜 센 말 |
| 색 | 점수가 높을수록 초록 쪽, 낮을수록 빨강 쪽. 적정가 막대는 저평가 구간 초록 · 적정 노랑 · 고평가 빨강 |
| 효과 | 점검표(pass/fail)를 모양 하나로 접어 「왜 이 모양인가」를 클릭해 따라가게 한다. 점수가 근거(점검 항목)로 풀린다 |
| 약점 | 리뷰에서 「모양이 투자 판단처럼 읽힌다」, 「밸류 · 배당 데이터 논란이 점수 신뢰를 깎는다」는 지적 (https://quantroutine.com/tools/simply-wall-st/ , https://stockunlock.com/simply-wall-st-review.html) |
| 우리 자리 | 적정가 막대 → **적정가 계산 카드**(인라인). 점검표를 모양으로 접는 방식 → **해자 · 피셔 점검 카드**. 내러티브의 「가정 → 결과값」 구조 → **매출 추정 · 적정가 풀스크린** |

우리에게 맞게 고칠 점: 스노플레이크는 다섯 축이 미리 정해진 점수표라 교재의 방법론(능력범위 → 해자 → 가격)과 어긋납니다.
모양 대신 **점검 항목의 통과 수를 막대로 세운 목록**이 정직합니다. 「점수」라는 말 대신 「통과한 점검」을 씁니다.

### 2.2 Morningstar — 적정가 · 별점 · 해자 배지 · 불확실성

출처: https://global.morningstar.com/en-gb/stocks/morningstar-s-guide-to-investing-in-stocks ,
https://www.morningstar.in/posts/28684/6-key-stock-investing-concepts-explained.aspx

| 항목 | 내용 |
|---|---|
| 컴포넌트 | 머리 줄에 배지 넷: 별점(1~5) · 적정가 · 해자(None/Narrow/Wide) · 불확실성(Low~Extreme). 주가/적정가 비율 |
| 먼저 보이는 것 | 별점. 그 옆에 「Fair Value 120.00 USD」, 해자 배지 |
| 규칙 | 불확실성이 낮으면 적정가의 95% 근처에서 매수 구간, 극단이면 50% 정도까지 내려가야 함. 즉 **안전마진이 불확실성에 따라 달라진다** |
| 해자 | Narrow = 10년 이상 초과수익 가능성이 더 큼, Wide = 10년은 매우 확신, 20년도 가능성 있음. 해자 추세(positive/stable/negative)를 따로 표시 |
| 효과 | 결론(별)과 근거(적정가 · 해자 · 불확실성)를 한 줄에 놓아, 결론을 읽는 순간 근거의 이름이 함께 보인다 |
| 우리 자리 | 해자 배지 → **종목 요약 카드**의 배지 줄. 「적정가 ÷ 3 = 매수가」는 Morningstar 의 「불확실성별 할인」과 같은 자리의 개념이라, 카드에 **적정가 · 매수가 · 현재가 셋을 한 막대 위에** 둔다 |

### 2.3 Seeking Alpha — 퀀트 등급 · 요인 성적표

출처: https://help.seekingalpha.com/premium/quant-ratings-and-factor-grades-faq ,
https://seekingalpha.com/article/4263303-quant-ratings-factor-grades-faq

| 항목 | 내용 |
|---|---|
| 컴포넌트 | 요인 성적표: Valuation · Growth · Profitability · Momentum · EPS Revisions 다섯 줄, 줄마다 A+~F 글자 등급. 같은 섹터 안에서 견준 값 |
| 먼저 보이는 것 | 종합 등급(Strong Buy~Strong Sell), 그 아래 다섯 글자 등급 |
| 숫자 · 단위 | 글자 등급이라 숫자가 없다. 펼치면 섹터 중앙값 · 이 회사 값 · 차이(%)의 표 |
| 색 | 관찰: A 계열 초록, C 회색, D~F 빨강의 칩 |
| 효과 | 「섹터 안에서」라는 기준을 고정해 서로 다른 산업의 값을 같은 잣대로 재지 않는다 |
| 우리 자리 | 요인 성적표의 **줄 구조**(요인 · 이 회사 · 피어 중앙값 · 차이)는 **피어 비교 캐러셀**의 상세와 **스크리너 결과 표**에 쓴다. 다만 매수/매도 등급은 쓰지 않는다(분석 연습이고 투자 자문이 아님) |

⚠ 우리 데이터는 KSIC 깊이가 제각각이라 「섹터 안에서」의 섹터를 기계로 정하면 피어가 빠집니다. 피어 집합은 사람이 확정한 것만
「피어 중앙값」에 씁니다(hathway AGENTS.md 「sector_code 는 그대로 쓰면 안 된다」).

### 2.5 TIKR — 재무 표 · 멀티플 이력 · 추정치

출처: https://support.tikr.com/hc/en-us/articles/5381611885851-How-to-best-navigate-the-TIKR-Terminal ,
https://www.tikr.com/blog/best-free-tools-to-analyze-valuation-multiples-across-peers

| 항목 | 내용 |
|---|---|
| 컴포넌트 | 재무제표 표(연간/분기/LTM 전환), 멀티플 이력(15년 넘게: 지금 PER 이 과거 대비 높은가), 컨센서스 추정과 그 변화 |
| 먼저 보이는 것 | 관찰: 표. 열이 기간, 행이 계정. 행을 고르면 표 위에 막대 차트가 생긴다 |
| 숫자 · 단위 | 관찰: 단위를 표 머리에 한 번만(「In Millions of USD」) 두고 셀에는 숫자만. 성장률은 별도 행(% YoY) |
| 효과 | 단위를 머리로 올려 셀을 가볍게 하고, 「행 고르기 → 차트」로 표와 차트를 한 동작으로 잇는다 |
| 우리 자리 | **재무 추이 풀스크린**(fin_periods 전체 표). TTM 열을 맨 오른쪽에 둔다. 멀티플 이력은 **적정가 계산 카드**의 「과거 PER 범위」 근거 |

### 2.6 Finviz — 스크리너 표 · 히트맵 · 매트릭스

출처: https://finviz.com/blog/new-stock-market-maps-for-market-cap-52-week-highs-lows-themes-and-insider-trading ,
https://finviz.com/blog/the-finviz-matrix-market-breadth-visualized/ , https://fffinstill.com/learning/concepts/s-p-500-heatmap

| 항목 | 내용 |
|---|---|
| 컴포넌트 | ① 히트맵: 트리맵, 칸 크기 = 시총, 칸 색 = 그날 수익률, 섹터로 묶음 ② 매트릭스: 행 = 산업, 열 = 시총 구간 ③ 스크리너: 위에 필터 칩 줄, 아래에 촘촘한 표 |
| 먼저 보이는 것 | 히트맵은 색의 덩어리(시장이 오늘 어떤가), 스크리너는 걸린 종목 수 |
| 색 | 미국식 초록 = 상승, 빨강 = 하락. 0 근처는 회색에 가깝게 → **세기가 색의 진하기로** 드러남 |
| 효과 | 두 변수(크기 · 색)를 한 칸에 실어 수천 종목을 한 장으로 접는다 |
| 우리 자리 | 트리맵 → **산업 지도 풀스크린**의 한 보기(칸 크기 = 매출, 색 = 영업이익률 변화). 필터 칩 + 표 → **스크리너 결과 표**(풀스크린, 인라인에는 상위 5행 미리보기) |

출처: https://yespress.io/finchat , https://iocharts.io/fr/blog/Filtre-de-partage-bas%C3%A9-sur-l%27IA-fiscale-MI-qui-affiche-tout/

## 3. 색: 한국은 빨강 = 상승, 파랑 = 하락

출처: https://wikidocs.net/132129 , https://view.asiae.co.kr/article/2026071309151503447

- 한국 시장은 양봉(상승)이 빨강, 음봉(하락)이 파랑입니다. 미국 · 유럽은 초록 = 상승, 빨강 = 하락이라 **빨강의 뜻이 정반대**입니다.
- **권장**: 한국 종목을 보는 이 제품은 빨강 = 상승 · 파랑 = 하락을 기본으로 씁니다. 사용자 대부분이 토스 · 네이버 · HTS 에서 그 관례로 익숙합니다.
- 다만 두 가지를 지킵니다.
  1. **색만으로 말하지 않습니다.** 늘 부호(+/−)와 화살표(▲/▼)를 같이 씁니다. 색각 이상과 국제 사용자, 그리고 밝은/어두운 모드에서
     색이 흐려지는 경우를 함께 막습니다.
  2. **빨강을 「위험 · 오류」에 쓰지 않습니다.** 상승이 빨강인 화면에서 부채비율 경고까지 빨강이면 뜻이 충돌합니다.
     경고는 노랑(주의) 계열과 아이콘으로, 오류는 문구로 말합니다. graphite 의 `destructive` 토큰을 상승 색으로 재활용하지 말고
     상승 · 하락 전용 의미 토큰(`--up` · `--down` 같은 이름)을 제품 층에 따로 둡니다(디자인 시스템 층은 고치지 않음).
- 「좋음/나쁨」(마진 개선, 부채 증가)은 상승/하락 색과 섞지 않습니다. 영업이익률이 「내려간」 것은 파랑이지만 그것이 「나쁜」지는 해석의 몫입니다.
  수치의 방향만 색으로, 좋고 나쁨은 글로 말합니다. Finviz · Seeking Alpha 처럼 초록=좋음을 쓰는 서비스를 그대로 옮기면 한국 관례와 부딪힙니다.

## 5. 제안하는 컴포넌트 세트

공통 규칙

- **맨 위는 한 가지**입니다(토스 · Morningstar 별점). 카드마다 「이 카드가 답하는 질문」 하나를 정하고 그 답의 숫자를 가장 크게 둡니다.
- 바닥 줄은 늘 같습니다: 출처 칩(「DART · 2025A · 연결」) · 기준일 · 면책 한 줄.
- 주 단추는 **「대화에 추가」**(카드 내용을 대화 맥락으로 보내 모델이 이어 해석) 또는 **보내기 동작**(「피어와 비교해 줘」 같은 다음 질문을
  대신 보냄). 보조 단추는 하나, 대개 「자세히 보기」(풀스크린 열기) 또는 「보드에 담기」.
- 숫자: 금액 억원 · 조원, 비율 % 소수 한 자리, 배수 x 소수 한 자리, 오른쪽 정렬 · 고정폭 숫자(`tabular-nums`). 단위는 머리에 한 번.
- 기다리는 얼굴: 같은 컴포넌트의 loading 상태로 값 자리만 막대(PendingText), 틀은 그대로(scaffold 「정적 껍데기」 3번 원칙과 같음).
- 빈 상태: 「없다」를 데이터의 사실로 말합니다. 「이 회사는 종속회사가 없어 별도 재무만 있어요」, 「최근 1년 공시된 지분 변동이 없어요」.
  hathway 데이터의 함정(연결 없음 · events 0행)을 화면이 정직하게 드러내는 자리입니다.

### 5.1 종목 요약 카드 (인라인)

- 답하는 질문: 이 회사는 어떤 곳이고 지금 숫자는 어떤가
- 참조: Koyfin 스냅숏 · Morningstar 배지 줄 · Yahoo 요약 2열 표 · 토스 「한 가지 먼저」
- 위계
  1. 머리: 회사명 · 종목코드 · 시장(KOSPI/KOSDAQ) · 산업(사람이 확정한 이름, KSIC 코드 원문 아님)
  2. **가장 큰 숫자: TTM 매출과 영업이익률** (ChatGPT 시세 카드와 겹치지 않게 주가가 아니라 실적을 앞에)
  3. 숫자 격자 6칸(라벨-값): 매출 성장률(YoY) · 영업이익률 · ROE · 부채비율 · 영업현금흐름 · 순차입금
  4. 배지 줄(있을 때만): 「해자 점검 4/6 통과」, 「연결 없음 · 별도 기준」
  5. 바닥 줄: 출처 · 기준 기간 · 면책
- 단추: 주 「대화에 추가」 · 보조 「재무 자세히」(풀스크린)
- 빈 상태: 상장폐지 · KONEX 등 범위 밖이면 「이 종목은 아직 다루지 않아요」 한 줄과 함께 카드 대신 글

### 5.2 재무 추이 미니차트 카드 (인라인) → 재무 풀스크린

- 답하는 질문: 최근 4~5년 어떻게 움직였나
- 참조: TIKR 「행 고르기 → 차트」 · FnGuide 재무 하이라이트 · Koyfin 겹친 지표
- 위계
  1. 지표 이름 하나(기본 매출) + 최근 값 + 4년 연평균 성장률
  2. 막대(매출) + 선(영업이익률) 복합 미니차트, 연도 5개 + TTM 막대는 테두리만
  3. 그 아래 숫자 한 줄: 연도별 값 5칸(억원)
- 단추: 주 「대화에 추가」 · 보조 「전체 재무 보기」
- 풀스크린: FnGuide 식 표(열 = 연도 · 분기 · TTM, 행 = fin_periods 컬럼), 연결/별도 칩, 행을 고르면 위 차트가 바뀜. 결측(`cogs` · `ebitda` 등)은 「—」와 「원본에 없음」 툴팁
- 색: 막대는 중립색, 전년 대비 오른 해만 상승 색 점 하나(색 남용 금지)

### 5.3 피어 비교 캐러셀 (캐러셀 3~8)

- 답하는 질문: 같은 승부의 축에서 누가 더 잘하나
- 참조: Perplexity 피어 줄 · Seeking Alpha 요인 표(섹터 안 비교) · Robinhood 「n건 기준」
- 항목 하나(두 줄 규칙)
  - 시각 요소: 영업이익률 5년 스파크라인
  - 1줄: 회사명 · 영업이익률(최근)
  - 2줄: 매출 성장률 · ROE
  - 항목 단추 하나: 「이 회사 요약」(보내기 동작)
- 첫 항목은 기준 회사(테두리 강조), 나머지는 사람이 확정한 피어. 5~6개 권장
- 캐러셀 위 제목 줄: 「게임 · 피어 5곳 · 2025A 연결 기준」
- 풀스크린 상세(Google Finance 식): 겹친 추이선 + 같은 값 표 + 피어 중앙값 행

### 5.4 적정가 계산 카드 (인라인)

- 답하는 질문: 교재 방식으로 계산하면 적정가와 매수가는 얼마인가
- 참조: Simply Wall St 적정가 막대 · Morningstar 주가/적정가와 불확실성별 할인
- 위계
  1. **한 막대(가장 큼)**: 왼쪽부터 매수가(적정가 ÷ 3) · 현재가 표식 · 적정가. 현재가가 어느 구간에 있는지가 한눈에
  2. 식 한 줄: 「적정 PER 15.0x × 추정 EPS 3,200원 = 적정가 48,000원 → ÷3 = 매수가 16,000원」
  3. 입력의 출처: PER 근거(피어 · 과거 범위), EPS 근거(매출 추정 카드에서), 현재가 출처와 시각(주가는 DB 에 없으므로 외부 출처 URL)
- 단추: 주 「가정 바꿔 다시 계산」(보내기 동작, 예: 「PER 12로 다시」) · 보조 「대화에 추가」
- 문안: 「저평가」 대신 「교재 매수가보다 n% 위」처럼 **방법에 대한 위치**로 말합니다
- 빈 상태: 적자 회사는 PER 가 서지 않으므로 「적자라 PER 로는 계산하지 않아요. PSR 로 볼까요?」(교재 C4 로 넘기는 보내기 단추)

### 5.5 매출 추정 카드 (인라인) · 분석 작업대 (풀스크린)

- 참조: Simply Wall St 내러티브(가정 → 결과값) · Robinhood 예상/실제 점
- 인라인: 「2026E 매출 1조 2,000억원」 한 숫자, 아래 가정 셋(수량 · 단가 · 점유율 같은 축) 칩, 지난 추정 대비 실제를 점 두 개
- 풀스크린 작업대: 교재 단계(능력범위 → 해자 → 산업 → 매출 추정 → 5단계 · 9칸 → PER → 매수가)를 왼쪽 세로 단계 표시로,
  오른쪽은 지금 단계의 표. 입력창으로 「점유율 20%로」라고 말하면 표가 바뀌는 구성(ChatGPT 풀스크린의 「composer 와 함께」 규칙)

### 5.6 공시 타임라인 카드 (인라인) → 공시 풀스크린

- 답하는 질문: 최근 무슨 일이 공시됐나
- 참조: 알파스퀘어 「종목 이슈」 · Fiscal.ai 원문 인용
- 위계
  1. 머리: 「최근 90일 공시 12건 · 주요사항 2건」
  2. 세로 타임라인 5행(중첩 스크롤 금지): 날짜 · 종류 배지(주요사항 · 정기 · 지분) · 보고서명 한 줄
  3. 주요사항(유상증자결정 · 전환사채발행결정 등)은 배지를 강조, 정기공시는 흐리게
- 단추: 주 「대화에 추가」 · 보조 「전체 공시」
- 각 행은 DART 원문(`dart.fss.or.kr/dsaf001/main.do?rcpNo=…`)으로 나감
- ⚠ `events.event_type` 과 `filings.report_nm` 을 섞지 않습니다. 배지 분류는 event_type, 행의 이름은 report_nm

### 5.7 지분 변동 카드 (인라인)

- 답하는 질문: 누가 사고 팔았나
- 참조: Robinhood 「n건 기준」 · TIKR ownership · 네이버 「내 주식」의 간결한 수치 줄
- 위계
  1. 큰 숫자: 「최근 6개월 내부자 순매수 +3.2만 주」(부호 · ▲ · 색)
  2. 막대 줄: 월별 순매수/순매도(상승 색 위, 하락 색 아래)
  3. 상위 3건: 이름(직위) · 날짜 · 수량 · 변동 후 지분율
- 단추: 주 「대화에 추가」 · 보조 「전체 내역」
- 빈 상태: 「최근 1년 지분 변동 공시가 없어요」(시드 종목은 ownership_txns 0행이라 이 상태가 흔함)

### 5.8 스크리너 결과 표 (인라인 미리보기 → 풀스크린)

- 참조: Finviz 필터 칩 + 촘촘한 표 · Seeking Alpha 요인 열 · TIKR 필터 묶음
- 인라인: 머리 「조건 3개 · 걸린 종목 27곳」, 걸린 조건 칩 줄, 상위 5행 표(회사 · 매출 성장 · 영업이익률 · ROE · 부채비율)
- 단추: 주 「조건 바꾸기」(보내기 동작) · 보조 「27곳 모두 보기」
- 풀스크린: 정렬 · 열 고르기 · 행 체크 후 「보드에 담기」. 전체 행 수와 「페이지네이션으로 다 읽었음」을 표 바닥에 적음(조용히 잘린 표본 방지)

### 5.9 산업 지도 (풀스크린)

- 참조: Finviz 트리맵 · 매트릭스, 알파스퀘어 테마
- 두 보기
  1. **가치사슬 보기**: 원리 → 수요 → 중간재 공급 → 병목 → 전이 순의 왼쪽→오른쪽 열, 열마다 기업 칩(industry-map 스킬의 구조)
  2. **트리맵 보기**: 칸 크기 = 매출, 색 = 영업이익률 전년 대비 변화(상승 빨강 · 하락 파랑, 진하기 = 크기)
- 칩을 고르면 오른쪽 서랍에 5.1 종목 요약이 뜸. 입력창으로 「병목만 보여 줘」라고 말할 수 있게
- 인라인 진입 카드: 산업명 · 기업 수 · 미니 트리맵 썸네일 · 주 「지도 열기」

### 5.10 리서치 보드 패널 (스레드 패널 서랍)

- 참조: Koyfin 맞춤 대시보드 · 네이버 「내 주식」 · 사이드에 머무는 작업면
- 구성
  1. 머리: 보드 이름 · 담긴 카드 수 · 마지막 수정
  2. 담긴 카드의 축약 목록(종류 아이콘 · 제목 · 핵심 숫자 하나 · 담은 날짜)
  3. 메모 칸(사람의 판단을 적는 자리, 숫자와 분리)
- 동작: 대화의 카드에서 「보드에 담기」 → 패널에 쌓임. 패널 항목을 고르면 그 카드를 다시 대화에 붙임
- 권한: 보드는 테넌트의 것이고 구성원만 고치고 지움(hathway AGENTS.md). 읽기 전용 사용자에게는 담기 단추를 꺼진 상태로

### 5.11 사이드바 홈

- 참조: 토스 첫 화면(내 것 먼저, 시장은 작게) · 증권플러스 관심 목록
- 위에서부터: 최근 본 종목 3 · 내 리서치 보드 · 「이렇게 물어보세요」 예시 질문 3개(누르면 보내기) · 아래에 작게 데이터 기준일(「공시 2026-07-29 까지」)

## 7. 남은 확인

- ChatGPT 의 기본 시세 카드가 국내 종목(KRX)에도 뜨는지, 뜬다면 우리 카드와 위아래 자리가 어떻게 되는지 실제 화면으로 확인.
- 사이드바 홈 · 스레드 패널은 OpenAI 공식 UI 지침 페이지에서 규칙을 찾지 못했습니다. 실제 지원 표면과 크기 제한을 SDK 문서에서 따로 확인.
- 「관찰」로 적은 줄(FnGuide 표 짜임, Koyfin 격자, 토스 등락 표기 등)은 구현 전 실제 화면 캡처로 확정.
- graphite 의 밝은 모드 짝과, 시스템 글꼴로 바꿨을 때의 밀도 차이를 시안으로 먼저 봄.
