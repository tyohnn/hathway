# 개발 방법론

> 이 문서는 **이 저장소의 코드를 쓰는 방법의 정본**이다. 루트 `AGENTS.md` 는 저장소 전체의 지도이고 여기를 가리킨다.
> 방법론은 resolv-ai 가 세우고 스캐폴드(`tyohnn/scaffold`)가 물려받은 것을 2026-10-02 에 이 저장소에 맞춰 옮겼다.
> 스캐폴드와 스택이 다른 자리는 옮기지 않았고, 무엇을 옮기지 않았는지는 끝의 「스캐폴드와 다른 자리」에 적었다.
> 교재 · 리서치 · 파이프라인의 규약은 `AGENTS.md` 가 그대로 갖는다. 이 문서는 `apps/web` · `packages/*` 의 코드만 다룬다.

| 묻는 것 | 정본 |
|---|---|

| 코드가 지금 무엇을 하나 | **테스트 이름.** 절차는 `.claude/skills/spec-by-test/SKILL.md` 가 갖는다 |

| 화면의 글 | `.claude/skills/ux-writing/` |

## 작업 순서

1. **되돌리기 비용부터 본다.** 화면 배치와 문안처럼 되돌리기 싼 것은 바로 만든다. 재무 수치의 계산과 표기, 적정가 계산,
   스키마와 적재 함수, 원격 DB 에 쓰는 일은 아래를 전부 지난다. 기준은 `spec-by-test` 스킬에 있다.
2. **테스트 이름을 먼저 짓고 확인받는다.** `it(...)` 목록과 그것이 붙을 공개 인터페이스를 적어 사용자에게 보인다.
3. **빨간 것을 먼저 세운다.** 테스트 하나를 실패시키고 그것만 지나가도록 고치는 일을 되풀이한다. 테스트를 몰아 쓰고
   구현을 몰아 쓰지 않는다. 절차는 `tdd` 스킬에 있다.
4. **판정과 계산은 순수 함수에 둔다.** 화면과 질의 안에 넣으면 그것을 확인하려고 매번 DB 를 올려야 한다.
   자리는 `packages/schema`(여러 곳이 함께 쓰는 타입 · 표기 · 분류)와 `apps/web/src/lib/<영역>` 이다.
5. **커밋은 책임 하나다.** 아래 「커밋」의 순서로 나눈다. 문서는 코드와 같은 커밋에 넣지 않는다.
6. **고친 뒤에 돌린다.** 아래 「자기 검증」의 명령을 지난다.

⚠ **건너뛰기 쉬운 자리가 둘이다.** 간단해 보이는 변경과, 테스트가 아직 없는 파일을 고치는 때다. 이 저장소는 규약을
들이기 전에 쓴 코드가 대부분이라 둘째가 거의 언제나 해당한다. 비싼 쪽을 고칠 때는 그 파일의 첫 테스트를 함께 세운다.

## 절대 하지 말 것

- ❌ **접속 문자열 · service role 키와 그것으로 읽은 모듈을 클라이언트로 내리는 것.** `src/lib/platform/db.ts` 를 클라이언트 컴포넌트에서
  import 하면 빌드가 깨져야 한다. 그 게이트(`server-only`)를 지우지 않는다. 클라이언트는 타입만 `import type` 으로 읽는다.
- ❌ **`public` 스키마를 anon 이 읽게 여는 것.** anon 키는 번들에 실려 나가므로 anon 이 읽는 것은 인터넷 전체가 읽는다
  (마이그레이션 `20260802000005`).
- ❌ **계정명을 직접 맞추는 것.** `fin_periods` 가 이미 했다.
- ❌ **앱의 롤에 표를 통째로 여는 것.** `web_app` 은 RLS 를 건너뛰므로 GRANT 가 유일한 경계다. 읽을 표와 쓸 표를 마이그레이션에
  하나씩 적는다. 리서치에서 원격 PostgREST 를 직접 부를 때 1000행에서 조용히 잘리는 것은 그대로다(`AGENTS.md`).
- ❌ **재무 수치를 세어 올리는 연출.** 그 사이 화면에 틀린 숫자가 선다. 값은 즉시 확정해 보이고 연출은 카드 단위로 한다.
- ❌ 렌더 중 `new Date()` / `Date.now()` / `Math.random()`. 시각과 식별자는 렌더 밖에서 정해 인자로 넘긴다.
  순수 함수는 시각을 스스로 읽지 않고 `now` 를 인자로 받는다.
- ❌ 모듈 스코프에 요청별 상태 보관. 요청 사이에 교차 오염이 생긴다.
- ❌ `forwardRef` / `useContext`: React 19 에서는 `ref` 를 일반 prop 으로 받고 컨텍스트는 `use()` 로 읽는다.
- ❌ `space-x-*` / `space-y-*` → `flex` + `gap-*`. `w-10 h-10` → `size-10`.
- ❌ shadcn 컴포넌트 안 아이콘에 사이즈 클래스. 버튼 아이콘은 `data-icon="inline-start|inline-end"`.
- ❌ 오버레이(Dialog/Sheet/Popover…)에 수동 `z-index`.
- ❌ 원시 색(`bg-blue-500`) → 시맨틱 토큰(`bg-primary` · `text-muted-foreground` · `bg-warning-soft`).
- ❌ `npx shadcn add`, 그리고 `packages/ui/src` 의 CLI 소유 파일을 손으로 고치는 것.
- ❌ `any`. `unknown` 과 타입 가드를 쓴다.

새 코드에 거는 규칙이다. 규약을 들이기 전의 코드에는 어긴 자리가 남아 있고(`space-y-*` · `useContext` 등),
그 파일을 다른 일로 고칠 때 함께 고친다.

## 서버 액션

서버 액션은 API 라우트와 똑같이 **공개 엔드포인트**다. 화면이 단추를 세웠는지, 미들웨어가 무엇을 봤는지를 믿지 않는다.
순서를 고정한다.

```
① Schema 로 입력 파싱         ← 밖에서 온 값은 믿지 않는다
② 인증 (세션 · 소속)           ← 세션에서 행위자를 확정한다. 없으면 핸들러에 닿지 않는다
③ 행 단위 판정                ← 도메인 패키지의 순수 함수. 매 요청 다시 한다
④ 도메인 규칙 적용             ← 순수 함수. DB 없이 검증할 수 있는 유일한 자리
⑤ 저장                        ← 문장이 판정의 조건(테넌트 · 판)을 한 번 더 건다
⑥ 캐시 무효화                  ← 바뀐 화면의 경로를 revalidatePath 로
```

⚠ **액션을 직접 `export` 하지 않는다. 관문 `appAction`(`apps/web/src/lib/action.ts`)을 지난 것만 내보낸다.**
관문이 ①②를 강제하고 핸들러에 `{ input, actor }` 만 준다. 핸들러는 세션 · 쿠키 · 헤더를 받지 않는다.

- ③의 입력을 지어낼 수 없다. `Actor` 는 브랜드 타입이라 객체 리터럴이 그 타입이 되지 못한다. 운영에서 행위자가 생기는 길은
  `actorForApp` 하나이고(INV-ACCESS-04) `packages/access` 의 경계 검사가 그것을 잰다.
- ⚠ **`"use server"` 파일에는 관문을 지난 액션만 둔다. 조립은 `src/usecases/` 에 둔다.** 그 파일의 export 는 전부 공개
  엔드포인트가 된다. 조립을 밖으로 빼면 메모리 저장소로 도커 없이 검사할 수 있다. 참조 구현은 `src/actions/research.ts` 와
  `src/usecases/research.ts` 다.
- ⚠ **`getUser()` 를 쓴다. `getSession()` 이 아니다.** 후자는 쿠키에 든 것을 그대로 돌려준다. 권한도 세션에서 읽지 않고
  `org.membership` 에서 읽는다.
- ⚠ 개발용 우회나 익명 폴백을 두지 않는다. `src/lib/action.test.ts` 가 「핸들러에 닿지 못한다」를 고정한다.
- 상태를 바꾸는 쓰기는 **열었을 때의 판**을 함께 보내고, 그사이 바뀌었으면 덮어쓰지 않는다(INV-RESEARCH-03).
- 관문을 지나지 않는 액션은 로그인과 로그아웃(`src/actions/session.ts`)뿐이다. 도메인 데이터를 만지지 않는다.

### 읽기는 공개다

이 앱이 스캐폴드와 갈리는 자리다. 스캐폴드는 셸 안쪽이 전부 로그인 뒤지만 여기서는 **읽기가 공개이고 쓰기만 로그인 뒤다**
(2026-10-02 사용자 결정).

- 프록시(`src/proxy.ts`, 옛 미들웨어)는 세션을 갱신할 뿐 아무도 돌려보내지 않는다. 인가를 거기 넣지 않는다.
- 화면은 `viewer()`(`src/lib/viewer.ts`)로 지금 보는 사람을 얻는다. 없으면 `null` 이고 화면은 그대로 선다. 이 값은 쓰는 단추를
  세울지를 정하는 **표시용**이고, 쓰기는 관문이 다시 판정한다.
- 관문이 끊은 요청은 액션이 어휘(`sign-in`)로 바꿔 돌려주고 화면이 로그인으로 안내한다(`src/lib/gateRefusal.ts`).
- **설정(`/settings/team` · `/settings/account`)만 로그인한 사람의 화면이다.** 그 화면의 조회는 `appRead`(`src/lib/read.ts`)를 지나고,
  세션이 없으면 로그인으로, 명부에 없으면 `/no-access` 로 보낸다. 소유자와 관리자가 사람을 초대하고 역할을 바꾸고 팀에서 뺀다
  (INV-ACCESS-09 · 10). 판정은 `packages/access` 의 `access/team.ts` 가 한다.
- 읽는 메서드가 행위자를 받기 시작하면 그것은 가려야 할 행이 생겼다는 뜻이다. 그때는 술어를 도메인 패키지에 먼저 세우고
  계약 테스트가 「질의 결과 = 술어의 결과」를 잰다.

### 조회의 길

종목 · 공시 · 재무의 조회는 `packages/market` 의 포트 넷(`CompanyDirectory` · `FinancialPeriods` · `FilingLedger` ·
`FilingDocuments`)을 지난다. 앞의 셋은 Postgres 어댑터가 `web_app` 으로 읽고, 공시 본문 조각만 저장소 어댑터가 읽는다.

```
화면(서버 컴포넌트) → src/lib/platform/db.ts(입구) → src/usecases/market.ts(조립) → 포트 → 어댑터
                                                         └ 접고 고르는 판단은 packages/market/rules
```

- **조회를 더할 때**는 포트에 메서드를 더하고, 메모리 구현과 계약 테스트(`packages/market/src/testing`)를 먼저 고친 뒤에
  Postgres 구현을 맞춘다. 새 표를 읽으면 마이그레이션에 `grant select … to web_app` 을 더한다.
- **연결과 별도를 고르는 것, 계약의 칸만 싣는 것** 같은 판단은 `rules/` 의 순수 함수다. 어댑터와 화면에 두지 않는다.
- **차례가 정해져 있다.** 같은 날짜의 공시는 접수번호가 큰 것이 먼저다. 화면이 조회마다 흔들리지 않는다.
- **읽지 못하면 던진다.** `WEB_DATABASE_URL` 이 없으면 로컬 주소로 떨어지지 않고 실패한다. 셸의 종목 검색처럼 비어도 되는
  자리는 부르는 쪽이 잡는다. 공시 본문 조각만은 없는 것이 흔해서 `null` 로 답한다.

## 테스트

무엇이 어떻게 동작하는지의 정본은 테스트 이름이다.

| 층 | 도구 | 도커 | 지키는 것 |
|---|---|---|---|
| 도메인 | vitest (`packages/access` · `packages/research` · `apps/web/src/usecases`) | ❌ | 문을 여는 판정 · 행 단위 판정 · 판 대조 · 입력의 모양. **TDD 루프가 도는 곳** |
| 통합 | vitest (`packages/adapters-postgres` · `adapters-storage`) + 로컬 Supabase | ✅ | 질의가 계약대로 답하는가, GRANT 와 제약이 걸리는가 |
| e2e | Playwright | ✅ | 화면이 그 판정을 드러내는가. 아직 세우지 않았다 |

- **같은 사실을 두 층에서 검사하지 않는다.** 그 사실을 확인하는 데 필요한 가장 싼 도구를 쓴다.
- **테스트 이름 합의가 먼저다.** 코드를 쓰기 전에 `it(...)` 목록을 사용자에게 확인받는다.
- **수직 슬라이스.** 테스트 하나를 쓰고 구현 하나를 쓰는 일을 되풀이한다.
- **red before green.** 실패하는 테스트를 먼저 세우고, 그것을 통과시킬 최소 코드만 쓴다.
- 모킹은 **시스템 경계에서만**(외부 API · 시간 · 파일시스템) 한다. 우리 모듈은 모킹하지 않는다.
- 서버 모듈(`import "server-only"`)을 부르는 테스트는 `apps/web/vitest.config.ts` 의 별칭이 빈 모듈로 바꿔 읽는다.
- **계약 테스트 한 벌이 메모리 구현과 Postgres 구현을 함께 잰다**(`packages/research/src/testing/contracts/`).
- ⚠ **통합 층은 앱의 롤(`web_app`)로 붙는다.** 소유자 롤로 돌리면 권한이 모자라도 통과한다. 기본 접속은 로컬 스택의
  DB(54362)이고 `WEB_DATABASE_URL` · `OWNER_DATABASE_URL` 로 바꾼다. 로컬 호스트가 아니면 러너가 거부한다.
- ⚠ **`pnpm test` 는 로컬 스택이 떠 있고 로그인 시드가 들어 있어야 통째로 초록이다**(`platform/README.md` 「로그인과 앱 롤」).
  스택이 없으면 건너뛰지 않고 실패한다.
- 테스트 이름에 불변식 id 를 넣는다(`INV-RESEARCH-02 …`). `pnpm check:invariants` 가 카탈로그와 인용을 대조한다.

## UI

정본 문서는 `docs/design-system/README.md` 다. 자주 부딪히는 것만 여기 적는다.

- **화면을 조립하는 단위는 `packages/blocks` 의 블록이다**(AppShell · PageHeader · SectionHeader · StatCard · StatusBadge · ItemList · EmptyState 등).
  블록은 데이터를 가져오지 않고 도메인 타입을 모른다. 규약은 `packages/blocks/CLAUDE.md` 에 있다.
- **블록에 없는 것은 `@investment/ui` 를 조합한다.** 기본 컴포넌트 61개가 이미 있다. 화면을 만들 때는 `packages/ui/src/components/` 를 먼저 훑어보고 조합한다.
- **Base UI 는 Radix 와 API 가 다르다**: `asChild` 대신 **`render`**, 버튼이 아닌 `render` 에는 `nativeButton={false}`,
  `Select` 는 `items` prop 필수, Toast 는 `toast.add()`. `form` 은 없고 `field` 다.
- 값이 마음에 들지 않으면 화면이 아니라 토큰을 고친다. 시스템의 값은 tyohnn 에서, 이 제품의 값은 `packages/ui/src/product.css` 에서 고친다.
- **사이즈 이름이 곧 높이다.** 숫자를 화면에 적어 넣지 않는다.
- 타입 스케일은 Tailwind 기본(`text-xs` ~ `text-4xl`)을 쓴다.
- 폰트의 배선은 CLI 가 갖는다(`layout.tsx` 의 `tyohnn:begin fonts` 블록). 손으로 `next/font` 를 선언하지 않는다.
- 긴 글은 `.typeset` 에 넣고 손으로 꾸미지 않는다.
- **화면의 글을 쓸 때는 `ux-writing` 을 읽는다.** 코드가 선 다음 글만 따로 한 번 보고, 기계 검사를 돌리고,
  서브에이전트 `ux-writing-reviewer` 에게 **볼 범위만** 넘겨 검토받는다.

## 컴포넌트 설계

- boolean prop 으로 동작을 분기하지 않는다 → 명시적 variant 컴포넌트.
- 복합 컴포넌트는 서브컴포넌트가 **props 가 아니라 context** 로 상태를 읽는다.
- `renderHeader` 같은 render prop 대신 `children`.
- `use client` 는 잎사귀에만 둔다. 클라이언트 경계로 넘기는 데이터는 최소로 한다.
- 데이터는 RSC 에서 가져와 streaming 으로 내려보낸다. 독립 작업은 `Promise.all` 로 묶는다.
- LCP 엘리먼트(보통 메인 헤딩)는 `<Suspense>` **밖**에 둔다.

## 코드 스타일

- **Allman brace, 4-space indent, 큰따옴표, 세미콜론을 쓴다.** 여는 중괄호는 반드시 다음 줄에 둔다. 2026-10-02 에 저장소 전체를
  이 스타일로 다시 찍었다. 포매터는 저장소에 없으므로 쓰는 사람이 지킨다.
- `packages/ui/src/components` · `icons` · `strings` · `systems` 는 tyohnn 원본이고 수정 금지 구역이다.
- 새 주석과 커밋 메시지는 한국어로 쓴다. 사람이 읽는 한국어 산문(문서 · PR · 코드 주석)은 `.claude/skills/fluent-korean/` 지침을 따른다.
  `pnpm check:comments` 가 기계로 잴 수 있는 셋(엠대시 · 명사형 종결 · 연결어미 종결)을 보고, 적용 범위는 그 스크립트의 `SCOPE` 가 갖는다.
  교재의 문장은 대상이 아니다. 그쪽은 `korean-bestseller-prose` · `humanize-korean` 이 맡는다.

## 커밋

한 커밋은 **한 가지 책임**만 바꾼다.

| 순서 | 책임 | 예 |
|---|---|---|
| 1 | 도구 · 환경 | 스킬, `.gitignore` |
| 2 | 의존성 | 버전 핀 |
| 3 | 패키지 골격 | 새 패키지, CLI 가 만든 것 |
| 4 | 순수 규칙 | 계산 · 표기 하나 + 그 테스트 |
| 5 | 데이터 접근 | 포트 · 어댑터 · 계약 테스트 |
| 6 | 앱 배선 | 라우트 · 레이아웃 · 서버 액션 · 화면 |
| 7 | 인프라 설정 | `platform/supabase/`, 마이그레이션, 배포 설정 |
| 8 | 문서 · 규약 | `AGENTS.md`, `docs/` |

- **각 커밋이 타입체크를 통과**해야 한다.
- **생성물과 수정본을 나눈다.** CLI 가 만든 것을 먼저 커밋하고 우리가 손댄 것은 다음 커밋에 넣는다.
- **문서는 코드와 같은 커밋에 넣지 않는다.**
- 커밋 메시지는 한국어로 쓴다. **제목에는 무엇을, 본문에는 왜를 적는다.**
- 타입은 `feat` / `fix` / `refactor` / `chore` / `docs` / `test` / `build` 이고, 스코프는 워크스페이스나 영역의 이름이다:
  `feat(web):`, `build(ui):`, `fix(plugin):`. 교재와 리서치의 커밋은 종전대로 제목만 적는다.
- PR 본문은 `.github/pull_request_template.md` 의 절을 채운다.

## 자기 검증

```
pnpm types:check        # 타입 오류 0
pnpm test               # vitest + 토큰 스캔 + 불변식 인용. 로컬 스택이 떠 있어야 통째로 초록이다
pnpm check:invariants   # 불변식을 더하거나 인용을 고쳤을 때
pnpm check:tokens       # 디자인 시스템이나 화면의 var() 를 고쳤을 때
pnpm check:comments     # 주석을 고쳤을 때
pnpm build              # 라우트 · 레이아웃 · 진입 CSS 를 고쳤을 때
```

화면을 고쳤으면 개발 서버에서 그 화면을 실제로 열어 본다. `/stocks/analysis/**` 는 로컬 Supabase 스택이 떠 있고
`WEB_DATABASE_URL` 이 있어야 한다(`platform/README.md` 「로그인과 앱 롤」).

## 스캐폴드와 다른 자리

규약을 옮기면서 이 저장소의 사정 때문에 옮기지 않은 것이다. 들일 때는 스캐폴드의 그 절을 다시 읽는다.

| 스캐폴드 | 이 저장소 | 까닭 |
|---|---|---|
| 조회한 행도 Effect `Schema` 로 파싱 | 조회한 행의 계약은 `packages/schema` 의 zod 그대로 | 적재와 플러그인이 같은 계약을 쓴다. 어긋난 행은 버리지 않고 로그만 남긴다 |
| 도메인마다 새 스키마 | 보드와 시장 데이터의 표는 `public` 그대로 | 먼저 있던 표이고 적재(`platform/ingest`)가 PostgREST 로 쓴다 |
| 셸 안쪽은 전부 로그인 뒤. 미들웨어가 로그인으로 보내고 `appRead` 가 조회를 지킨다 | 읽기는 공개, 쓰기만 관문 뒤. 화면은 `viewer()` 로 보는 사람을 얻고, `appRead` 는 설정(팀 · 내 계정)에만 쓴다 | 2026-10-02 사용자 결정 |
| 요금제 한도 · MCP · agent 앱 | 없음 | 이 제품에 없는 것이다. 팀 관리(`/settings/team`)는 옮겼고 초대 메일은 보내지 않는다 |
| 정적 껍데기(`cacheComponents`) | 없음 | 아직 켜지 않았다. 들일 때는 `next-cache-components-adoption` 스킬로 한다 |
| `check:dependencies` · `check:modules` · `check:migrations` | 없음. `check:invariants` 만 옮겼다 | 층 표와 모듈이 아직 없다 |
| `docs/decisions/` | Notion 의 ADR | 문서 정본이 Notion 이다 |
| npm + Turborepo | pnpm | 종전 그대로다 |
| 스킬 `security-check` · `scaffold-add` · `scaffold-remove` · `stripe-best-practices` | 옮기지 않음 | 스캐폴드 자신의 경계와 모듈을 다룬다. PR 전에는 내장 `security-review` 를 돌린다 |
