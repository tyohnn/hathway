# 개발 방법론

> 이 문서는 **이 저장소의 개발 방법론 정본**이다. 루트 `CLAUDE.md` 는 저장소 전체의 지도이고, 앱마다 있는
> `CLAUDE.md` 는 그 앱의 사정을 적는다. 방법론이 서로 다르게 읽히면 이 문서가 우선한다.
> 방법론은 resolv-ai 가 세우고(스택 · 금지 목록 · 서버 액션 순서 · 테스트 3층 · 커밋 순서) agent-campus 가 물려받은
> 것을 2026-09-29 에 스캐폴드로 옮겼다. 예시는 스캐폴드의 `org` · `notes` · `agent` 스키마와 `apps/web` · `apps/agent`
> 로 다시 적었다. 규약을 손볼 일이 있으면 이 문서만 고친다.

## 기본 전제 셋

1. **레이어 방향.** 별도의 API 서버가 없다. 서버 액션이 도메인 패키지의 순수 규칙과 포트를 부르고, 어댑터가
   DB 로 간다.
2. **DB 자격증명.** 어댑터가 **DB 접속 문자열**을 쥐므로 진입 파일 최상단에 **`import "server-only"`** 를 강제한다.
   규약이 아니라 **컴파일 게이트**로 만드는 것이 요점이다. 클라이언트 번들에 섞이면 빌드가 깨져야 한다.
   (Service Role 키가 아니다. 앱은 PostgREST 를 지나지 않는다.)
3. **코드 스타일.** Allman brace / 4-space / 한국어 주석이다. 주석의 한국어는 `.claude/skills/fluent-korean/` 지침을
   따르고(2026-09-16 부터), 문체는 평서체 그대로다. 단 **`packages/ui/src/components/**` 는 예외**다.
   tyohnn 이 내려 준 원본이고 수정 금지 구역이다.

## 절대 하지 말 것

Next 16 · React 19 · 디자인 시스템에 걸린 것이다.

- ❌ `export const dynamic | revalidate | fetchCache`: `cacheComponents` 와 함께 쓰면 **에러**다.
- ❌ `unstable_cache`: `use cache` 로 대체됐다.
- ❌ 레이아웃/페이지 최상단에서 `await getSession()` / `cookies()` / `headers()` / `await params` / `await searchParams`
  → 라우트가 blocking 이 되어 빌드가 실패한다. `<Suspense>` 안쪽 자식으로 내릴 것.
- ❌ 렌더 중 `new Date()` / `Date.now()` / `Math.random()` / `crypto.randomUUID()`
  → sync-IO 로 판정된다. 시각과 식별자는 렌더 밖에서 정해 인자로 넘긴다. 도메인의 순수 함수는 시각을 스스로
  읽지 않고 `now` 를 인자로 받는다. 워크플로 본체도 시각 · 난수 · 환경 변수를 읽지 않고 인자와 스텝으로 받는다.
- ❌ `use cache` 트리 안에서 세션 읽기 → **빌드는 통과하고 `next start` 에서 터진다.**
- ❌ 모듈 스코프에 요청별 상태(세션·토큰·사용자·행위자) 보관 → 요청 사이에 교차 오염이 생긴다.
- ❌ `forwardRef` / `useContext`: React 19 에서는 `ref` 를 일반 prop 으로 받고 컨텍스트는 `use()` 로 읽는다.
- ❌ `space-x-*` / `space-y-*` → `flex` + `gap-*`. `w-10 h-10` → `size-10`.
- ❌ shadcn 컴포넌트 안 아이콘에 사이즈 클래스. 버튼 아이콘은 `data-icon="inline-start|inline-end"`.
- ❌ 오버레이(Dialog/Sheet/Popover…)에 수동 `z-index`.
- ❌ 원시 색(`bg-blue-500`) → 시맨틱 토큰(`bg-primary`, `text-muted-foreground`).
- ❌ `npx playwright install`: 클라우드 개발 환경에서는 브라우저가 `/opt/pw-browsers` 에 이미 있고 재다운로드는
  egress 에서 막힌다.

도메인 규칙은 불변식 카탈로그가 정한다. 코드에서 가장 자주 부딪히는 것만 여기 적는다.

- ❌ **행 단위 판정을 앱 안에 다시 적는 것**(REQ-02). 판정 술어는 도메인 패키지의 순수 함수 하나이고 화면과
  에이전트의 도구와 MCP 가 그것을 부른다. 예를 들어 쪽지가 누구에게 보이는지는 `packages/notes/src/rules/visibility.ts`
  의 `canSeeNote` 하나가 정하고 화면과 에이전트의 도구와 MCP 가 함께 그 함수를 지난다. "여기선 좀 다르게" 가 들어오는 순간
  감사가 불가능해진다.
- ❌ **"이 앱으로 들어왔으니 안전하다" 는 전제**(REQ-06). 앱은 UX 경계이지 보안 경계가 아니다. 조회와 쓰기는
  매번 행 단위로 판정한다.
- ❌ **보여서는 안 되는 칸을 응답에 싣는 것.** 화면에서 그리지 않는 것으로는 부족하다. 서버가 응답에서 지운다.
- ❌ **기록의 UPDATE/DELETE 경로.** 대화의 말은 쌓이기만 한다(INV-AGENT-02). 바로잡는 방법은 바로잡는 기록을 더하는 것이다.

## 서버 액션 규약

서버 액션은 API 라우트와 똑같이 **공개 엔드포인트**다. 미들웨어·레이아웃·페이지에서 이미 검사했다는 이유로
건너뛰지 않는다. 순서를 고정한다.

```
① Schema 로 입력 파싱         ← 외부계는 믿지 않는다 (defense in depth)
② 인증 (세션 · 소속)
③ 행 단위 판정                ← 도메인 패키지의 순수 함수. 매 요청 다시 한다
④ 도메인 규칙 적용             ← 순수 함수. DB 없이 검증할 수 있는 유일한 자리
⑤ 저장 + 기록을 한 트랜잭션에   ← 둘 중 하나만 되는 상태를 만들지 않는다
⑥ 알림을 밖으로                ← 본 작업을 되돌리지 않고, 실패는 오류로 남긴다
```

⚠ **액션을 직접 `export` 하지 않는다. 관문 `appAction`(앱마다 `src/lib/action.ts`)을 지난 것만 내보낸다.**
tRPC 의 `businessCenterProcedure` 같은 빌더가 없어서 `export async function` 하나면 클라이언트가 바로 호출할 수 있다.
즉 ①②를 **잊을 수 있는 구조**이고, 관문이 그 자리를 메운다.

- 관문이 ①파싱·②인증을 강제하고 핸들러에 `{ input, actor }` 만 준다.
  ⚠ 핸들러는 **세션·쿠키·헤더를 받지 않는다.** 받을 수단이 없어야 "위에서 이미 봤으니" 라는 분기가 생기지 않는다.
- ③의 입력을 **지어낼 수 없다.** `Actor` 는 브랜드 타입이라 객체 리터럴이 그 타입이 되지 못한다
  (`packages/access/src/domain/Actor.ts`). 운영에서 행위자가 생기는 길은 하나이고(INV-ACCESS-04) 그 길은
  `canEnterApp` 을 지난다.
  ⚠ **행 단위 판정을 끄는 스위치를 만들지 않는다.** 환경 변수로 게이트를 끄는 길이 생기면 그것이 배포까지 따라간다.
- ②는 **배선되어 있다**(`ActorResolver` · 앱마다 `src/lib/auth.ts`). 인증은 세 계층이고 실패마다 가는 곳이
  다르므로 오류도 둘이다. `NoSession` 은 `/login` 으로, `NotAppMember` 는 `/no-access` 로 간다.
  셋째 계층(행 단위)은 관문이 아니라 **모든 조회·쓰기마다** 도메인 술어가 한다.
  - ⚠ **`getUser()` 를 쓴다. `getSession()` 이 아니다.** 후자는 쿠키에 든 것을 그대로 돌려주므로 위조된
    쿠키를 믿는다. 서버에서는 전자만 쓴다.
  - ⚠ **권한을 세션에서 읽지 말 것.** 역할은 `org.membership` 에서 읽어 확정한다. JWT 클레임을 믿으면 토큰을
    쥔 사람이 자기 권한을 적어 넣는 것과 같다.
  - ⚠ 개발용 우회나 익명 폴백을 두지 말 것. 두면 그 우회가 배포까지 따라간다. `src/lib/action.test.ts` 가
    "핸들러에 도달하지 못한다" 를 실패의 **종류**로 고정한다.

참조 구현은 `apps/web/src/actions/notes.ts` 와 그 조립인 `apps/web/src/usecases/notes.ts` 다. 스트림을 돌려줘야 하는 자리(대화 · MCP)는 라우트 핸들러이고, 관문과 같은 순서(① 파싱 · ② 행위자)를 손으로 지난다.
파서는 **모듈 스코프에서 한 번** 만들어 재사용한다. `appAction` 을 모듈 스코프에서 부르면 자동으로 그렇게 된다.

⚠ **`"use server"` 파일에는 관문을 지난 액션만 둔다. 조립은 `src/usecases/` 에 둔다.** 그 파일의 export 는 **전부**
공개 엔드포인트가 되므로, 조립을 액션 파일에 두고 테스트가 부를 수 있게 export 하는 순간 엔드포인트가 하나 더 생긴다.
조립을 밖으로 빼면 도메인 Layer(in-memory)로 도커 없이 검사할 수 있다는 것도 같은 선택에서 얻는 이득이다.

`lib/` 가 아니라 `usecases/` 에 두는 이유는 `lib/` 가 관문·런타임·인증·라우트처럼 앱이 딛는 기반을 담는 자리라서다.
기능 모듈과 섞이면 무엇을 어디에 두는지가 흐려진다. 이렇게 두면 액션 파일은 언제나 관문 한 줄이고 본체는 유스케이스다.

관문을 지나지 않는 액션은 로그인과 로그아웃처럼 행위자가 아직 없거나 사라지는 자리뿐이다. 그런 액션은 파싱만
직접 하고 도메인 데이터를 만지지 않는다. 어느 파일이 그런지와 그 이유는 앱의 `CLAUDE.md` 가 갖는다.
⚠ 이 예외를 다른 액션으로 넓히지 말 것.

⚠ **관문 테스트가 초록일 때 그 이유가 맞는지 본다.** 런타임이 기동 단계에서 설정 누락으로 죽으면 관문 테스트는
"세션이 없어서" 가 아니라 "설정이 없어서" 초록이 되고, 그것은 검사가 없는 것과 같다.

- 볼 수 없는 행은 **거부가 아니라 부재**로 답한다. 목록에서 빠지고 상세는 없는 것으로 나온다. 거부 사유는
  감사에만 남긴다. 행이 있다는 사실 자체가 정보이기 때문이다.
- 판정을 우회하는 행위자(테넌트의 `owner`·`admin` 같은 역할)도 **판정 함수 안을 지난다.** 바깥에서
  "관리자니까 건너뛰자" 로 분기하지 않는다. 우회의 술어도 한 곳에 두고 순수 함수와 어댑터의 질의가 그것을 함께 읽는다.
- 상태를 바꾸는 쓰기는 **열었을 때의 버전**을 함께 보내고, 그사이 바뀌었으면 덮어쓰지 않는다. 기록 추가는 멱등 키를 받는다.
- 부수효과(메일·알림·캐시 무효화)는 `after()` 로 비차단 처리한다. 밖으로 나가는 발송의 실패는 오류로 올리고,
  정상적인 거절(받을 주소가 없는 경우 등)은 올리지 않는다(REQ-04).
- 밖으로 나가는 글에 사람이 적은 문자열(이름·제목·요청 내용)이 들어가면 본문과 미리보기 **둘 다** 이스케이프한다.
- 캐시 무효화는 즉시 반영이 필요하면 `updateTag` 를, 아니면 `revalidateTag` 를 쓴다.

## 패키지 구조와 의존 방향

```
apps/web   ──▶ @hathway/access ──▶ @hathway/shared
apps/agent     @hathway/notes        도메인이 아닌 공용. React/DB/Next 의존 금지
 (서버 액션 ·   @hathway/agents
  라우트 ·      타입 + 순수 규칙 + 포트
  워크플로)           │
                      ▼
          @hathway/adapters-postgres   access · notes · agents 포트의 Postgres 구현. server-only 게이트
          @hathway/adapters-storage    Supabase Auth 설정을 읽는 어댑터
@hathway/blocks  블록 층. @hathway/ui 와 @hathway/shared 만 부른다
@hathway/ui      shadcn(Base UI). tyohnn 이 내려 준 원본이라 손으로 고치지 않는다
```

- **도메인 패키지가 앱의 도메인이다.** `packages/access` 는 테넌트·계정·멤버십으로 앱의 문을 판정하고,
  `packages/notes`(예시 도메인)와 `packages/agents` 는 자기 스키마의 타입(Effect `Schema`)과 순수 규칙과 포트(연산별
  메서드)를 둔다.
  **effect 외 런타임 의존 금지.** 새 도메인 패키지는 빈 채로 미리 세우지 않고 그 도메인의 첫 화면을 만들 때 세운다.
- **순수 규칙을 자기 파일로 떼어놓는 것이 패키지를 나누는 것보다 중요하다.** 그것이 DB 없이 도는 층을 만든다.
  판정을 질의나 화면 안에 넣으면 그것을 확인하려고 매번 스키마를 올려야 한다.
- **도메인 사이 의존은 한 방향이다.** 지금 `notes` 와 `agents` 는 둘 다 `access` 의 `Actor` 를 받을 뿐 서로를 부르지 않는다.
  에이전트의 도구가 쪽지를 읽을 때도 `agents` 가 `notes` 를 부르지 않고 앱의 스텝이 둘을 잇는다. 두 도메인이 서로를
  필요로 하면 그 조각은 둘 중 하나가 아니라 아래(`shared`)에 있어야 한다.
- **이 방향은 `turbo test` 가 잰다.** `packages/shared/scripts/check-dependencies.mjs` 가 선언하지 않은
  `@hathway/*` import 와 층을 거스르는 의존과 도메인의 `effect` 밖 런타임 의존을 막고, 순환은 turbo 가 막는다.
  층은 그 스크립트의 `LAYER` 표가 정하고 표에 없는 패키지는 실패하므로, 새 패키지는 그 표에 줄을 더하는 것이 첫 작업이다.
  (`ALLOWED` 표에는 `core` 와 `tool` 층의 자리가 남아 있지만 지금 그 층에 속한 패키지는 없다.)
- 포트는 `query(sql)` 같은 범용이 아니라 **연산별 메서드**로 나눈다. 범용 포트는 테스트 더블 안에 조건 분기를 만들게 한다.
- 계약 테스트 한 벌이 메모리 구현과 Postgres 구현을 함께 잰다(`packages/notes/src/testing/contracts/` · `packages/agents/src/testing/contracts/` ·
  `packages/access/src/testing/contracts/`).
- 런타임은 앱마다 `ManagedRuntime` 하나(`src/lib/runtime.ts`)다. ⚠ 거기에는 **요청과 무관한 불변 어댑터만** 올린다.
  행위자·세션은 액션 안에서 `Effect.provide` 로 요청마다 주입한다.

## DB

정본은 `supabase/migrations/` 하나이고 절차 전문은 `docs/supabase-migrations/README.md` 다. 그 위에 이 저장소의
규칙을 더한다. 스키마는 지금 셋이다.

| 스키마 | 무엇 | 붙는 롤 |
|---|---|---|
| `org` | 테넌트 · 계정 · 멤버십. 앱의 문이 여기서 열린다 | `web_app` · `agent_app` (컬럼 단위 SELECT) |
| `notes` | 예시 도메인의 쪽지 | `web_app`(읽고 쓴다) · `agent_app`(읽기만) |
| `agent` | 에이전트와 나눈 대화의 장부 | `agent_app` |

### 마이그레이션은 손으로 쓴다

`supabase migration new <이름>` 으로 껍데기를 만들고, SQL 과 **의도 주석**을 파일에 적고, `supabase db reset` 으로 빈 DB 재생을
확인한다. `db pull`·`db diff` 로 파일을 만들지 않는다(사유는 `docs/supabase-migrations/README.md` §2).
파일명·타임스탬프는 CLI 가 붙인 것을 쓴다. 테이블 하나가 마이그레이션 하나다.

이미 어디에든 적용한 파일은 고치지 않고, 바꿀 것이 있으면 새 파일을 더한다.

### 식별자

신규 규약(`docs/supabase-migrations/README.md` §8)은 `bigint identity` 다. 밖에서 id 가 오는 자리만 그 값의 타입을 따른다.

| 자리 | 타입 | 이유 |
|---|---|---|
| 우리가 행을 만드는 테이블의 PK | `bigint generated always as identity` | B-tree 삽입이 시간순이고 조인 키가 8바이트다 |
| 스키마 안팎에서 그 행을 가리키는 FK | `bigint` | 부모의 PK 를 그대로 가리킨다 |
| 밖에서 정한 id | 그 값 그대로(`text`) | 대화의 id 는 Workflow 의 실행 번호다(`agent.conversation.id`) |
| Supabase Auth 의 사용자 | `uuid` | `org.account.auth_user_id`. FK 를 걸지 않고 unique 만 둔다 |

- ⚠ `bigint` 는 `pg` 에서 문자열로 온다. 어댑터가 그것을 전제하고 계약 테스트가 그 왕복을 잰다.

### 스키마는 업무 영역으로 이름 짓는다

스키마를 앱 이름으로 짓지 않는다. 스키마를 앱 이름으로 지으면 둘째 앱이 그 표를 읽는 날 이름이 사실과 어긋난다.

`org` 과 `agent` 는 업무 영역 이름이 아닌 것을 알고 고른 예외다. 둘 다 업무 영역을 가로지른다. 업무 영역 안의
갈래는 스키마가 아니라 컬럼이다. 도메인마다 고유한 데이터가 생겨 새 스키마를 세울 때 이 규칙을 따른다(`notes` 가 본보기다).

### 접근 모델: RLS 는 항상 켜고 항상 deny-all

우리 스키마에는 **HTTP 로 들어오는 경로를 두지 않는다.** `config.toml` 의 `[api] schemas` 에도 없다. 앱은
PostgREST 가 아니라 `pg` 로 직결한다(아래 「DB 접속」). 권한 판정은 서버 액션 안의 도메인 함수가 한다.
anon·authenticated 에는 스키마 USAGE 를 주지 않고, 테이블마다 두 줄이 따라붙는다.

```sql
alter table <schema>.<table> enable row level security;
create policy deny_all on <schema>.<table> as permissive for all to public using (false) with check (false);
```

- GRANT 는 `service_role`(스키마 기본 권한)과 **앱의 롤**(`web_app` · `agent_app`)에 준다.
  `service_role` 은 Supabase 에서 **LOGIN 속성이 없어** `pg` 로 붙을 수 없다(아래 「접속 롤」).
- GRANT 만으로도 막히지만 정책을 함께 둔다. 나중에 GRANT 한 줄이 더해질 때 데이터가 열리는 대신 0행이 나온다.
- `force row level security` 는 쓰지 않는다. 소유자(postgres)까지 막아 마이그레이션이 걸린다.
  ⚠ 대신 **앱의 롤에 `bypassrls` 를 준다.** 주지 않으면 `deny_all` 에 걸려 0행이나 정책 위반이 된다.
  `service_role` 이 그렇게 되어 있는 것과 같은 이유다.
- 구매자의 앱처럼 다른 앱이 뒤에 같은 스키마를 읽게 되어도 같은 모델이다.
- ⚠ **DB 는 "지금 이 쿼리가 누구 것인지" 모른다.** 사람의 로그인(Supabase Auth)과 DB 접속(앱의 롤)은 다른
  층이고 둘 사이에 연결이 없다. 모든 사용자의 요청이 **같은 롤 하나**로 나간다. 그래서 행 단위 판정을 한 번
  빠뜨리면 그대로 유출이고 DB 가 받아 줄 두 번째 방어선이 없다. 계약 테스트가 "질의 결과 = 도메인 판정 결과" 를
  대조하는 것이 그 자리를 지키는 장치이고, 행을 읽는 포트를 더할 때마다 같은 대조를 붙인다.

### DB 접속: `pg` 직결, 트랜잭션 모드 풀러

구현은 `packages/adapters-postgres/src/connection.ts` 다.

⚠ **전송은 도메인이 아니다.** 풀·TLS·트랜잭션은 앱이 붙는 방식이므로 `src/connection.ts` **하나**이고,
도메인 어댑터는 `src/agent/` · `src/org/` 처럼 그 아래로 나눈다. 앱이 새 스키마를 읽게 되어도 접속 롤이
하나이듯 이 전송도 하나다. 도메인마다 커넥션 풀을 만들지 말 것.

**PostgREST 를 쓰지 않는 이유는 둘이다.** ① 요청 하나가 트랜잭션 하나라서 여러 행을 함께 넣으려면 plpgsql
함수를 두어야 하고, 그것은 **규칙을 DB 로 옮기는 것**이다. ② 노출하지 않는 편이 위 접근 모델과 맞는다.

- ⚠ **DB 에 절차(함수·트리거)로 업무 규칙을 두지 않는다.** 원자성이 필요하면 **앱이 문장을 조립한다.**
  데이터 수정 CTE 하나면 단일 문장이 곧 트랜잭션이고, 여러 문장이면 `SqlExecutor.transact` 로 묶는다.
  기록을 쌓이기만 하게 하는 트리거는 예외다(규칙이 아니라 append-only 라는 성질이다). 지금 `agent` 의 트리거는
  판 행과 장부 줄의 불변을 지키는 것, 닫힌 실행에 줄이 더해지지 않게 하는 것, 산출물 본문이 마지막 판을 따르게
  하는 것이다. 새로 더할 때는 그것이 규칙인지 성질인지 먼저 묻는다.
- ⚠ **풀러는 트랜잭션 모드(6543)** 를 쓴다. 세션 모드(5432)는 클라이언트가 끊을 때까지 Postgres 커넥션을 붙잡는데,
  서버리스 인스턴스는 요청 사이에 **얼어 있을 뿐 끊지 않는다.** 얼어 있는 인스턴스 수만큼 커넥션이 잠긴다.
- ⚠ **이름 있는 prepared statement 를 쓰지 말 것.** 질의에 `name` 을 주면 뒤 커넥션이 바뀌면서
  "prepared statement does not exist" 가 난다. 트랜잭션 밖 `set`·`listen`·세션 수명 advisory lock 도 같다.
- 풀은 `globalThis` 에 둔다(HMR·따뜻한 인스턴스 재사용). 인스턴스마다 `max: 3` 이고 실제 부하는 **인스턴스 수 × max** 다.
- ⚠ **`statement_timeout`·`application_name` 을 풀 설정으로 두지 말 것.** 트랜잭션 모드에서 시작 파라미터는
  백엔드에 도달하지 않는데 **거부당하지도 않아** 걸려 있다고 믿게 된다(로컬 Supavisor 실측: `statement_timeout=0`,
  `application_name=Supavisor`). 실제로 거는 자리는 **롤 설정**(`alter role web_app set statement_timeout`)이고
  그것은 풀러를 통과한다. 비밀번호와 같이 배포 때 넣는다.
- ⚠ **트랜잭션을 연 채 밖을 기다리지 말 것**(외부 API 호출 등). 그동안 뒤 커넥션이 묶인다. 읽기를 트랜잭션에 넣지 않는다.

### 접속 롤: 앱마다 하나

마이그레이션 `20260929000000_create_app_roles.sql` 이 이름(`web_app` · `agent_app`)을 만든다.

- **마이그레이션은 이름과 GRANT 만** 만든다. LOGIN·BYPASSRLS·비밀번호는 마이그레이션에 두지 않는다.
  비밀번호는 커밋되고 `schema_migrations.statements` 에도 남기 때문이다. GRANT 는 스키마를 세우는 마이그레이션이 함께 갖는다.
- 로컬의 그 셋은 `supabase/seed.sql` 이 넣는다(`db reset` 에서만 돌고 `db push` 는 타지 않는다).
  원격은 Management API 로 `alter role <앱>_app login password '…' bypassrls;` 를 실행한다.
- ⚠ **계약 테스트도 앱의 롤로 붙는다.** 소유자 롤로 돌리면 권한이 모자라도 통과해서 "로컬은 되는데
  배포하면 권한 부족" 을 잡지 못한다.
- ⚠ **롤은 앱당 하나이지 스키마당 하나가 아니다.** 이름이 `<앱>_app` 인 이유다. 앱이 새 스키마를 읽게 되면
  **이 롤에 GRANT 를 더한다.** 스키마마다 롤을 새로 만들지 말 것(같은 프로세스가 접속 문자열을 둘 들면 풀만
  곱해지고 보안은 그대로다). 롤이 나뉘는 자리는 앱이 나뉘는 자리다. 앱이 늘면 그 앱의 롤이 따로 선다.
- ⚠ **`org` 에는 컬럼 단위로 SELECT 만** 준다. 예외는 둘이다. 처음 로그인한 사람이 자기 계정과 세션을 잇는
  `org.account.auth_user_id` 의 UPDATE(INV-ACCESS-08)와, web 의 팀 화면이 쓰는 계정 `email` · `name` INSERT · `name`
  UPDATE 와 멤버십 INSERT · `role` · `active` UPDATE 다(INV-ACCESS-09, `*_grant_team_writes.sql`). 멤버십의 DELETE 와
  `account_id` · `tenant_id` 의 UPDATE, 계정의 `email` · `deactivated_at` UPDATE, 테넌트의 쓰기는 주지 않는다. RLS 모델을
  하나로 유지하려는 선택이다. 인가는 언제나 앱이 하고 DB 는 언제나 deny_all 이다.
  - ⚠ **컬럼 단위로 준다.** 앱의 롤은 `bypassrls` 라 상대 스키마의 정책도 지나므로 **GRANT 가 유일한 경계**다.
    `phone`·`slack_user_id` 처럼 앱이 쓰지 않는 칸은 넣지 말 것.
- ⚠ **DDL 을 주지 않는다.** 스키마 변경은 마이그레이션(`postgres`)의 일이다.
- `date` 는 타입 파서를 손으로 지정해 **문자열로** 받는다(`connection.ts`). `pg` 기본 파서는 로컬 시간대의 `Date` 로
  접어 그 값을 다시 날짜로 적을 때 하루가 밀린다. 지금 우리 스키마에는 `date` 칸이 없고 시각은 전부
  `timestamptz` 다. `timestamptz` 는 파서를 손대지 않고 어댑터가 `toISOString()` 으로 되돌린다.
- ⚠ **값은 반드시 `$n` 파라미터로 넘긴다. SQL 문자열에 값을 보간하지 말 것.** 템플릿 리터럴의 `${}` 는
  **모듈 상수 조각**(고정 select 문·자격 술어)만 허용하고 사용자 입력·도메인 값은 어떤 경우에도 넣지 않는다.
  테이블·컬럼명을 동적으로 조립해야 한다면 그것은 포트를 다시 볼 신호다(`query(sql)` 같은 범용 포트를 두지 않는
  이유와 같다).
- TLS 는 `?uselibpqcompat=true&sslmode=require` 를 붙인다. 누락이나 `disable` 은 기동을 막는다(풀러가 평문을 거부하지 않는다).
  `pg` v8.22+ 가 `require` 를 `verify-full` 로 읽는 것을 `uselibpqcompat` 이 되돌린다. 로컬 호스트는 이 검사에서 빠진다.

### 신규 테이블 규약

`docs/supabase-migrations/README.md` §8 을 따른다. 특히 다음은 빠뜨리기 쉽다.

- 모든 FK 에 인덱스. 행 단위 판정의 질의가 붙는 칸(계정·테넌트·도메인)은 특히 그렇다.
- 기록 테이블은 트리거로 UPDATE/DELETE 를 거부한다. 앱 코드에도 그 경로를 만들지 않는다.
- 읽을 때 계산할 수 있는 값은 저장하지 않는다. 합계처럼 저장해야 하는 파생값은 원본과 한 트랜잭션에 갱신한다.
- 뷰가 필요하면 `security_invoker = true`.
- 어휘(갈래·종류)에 check 제약을 걸지 않는 자리가 있다. 값의 어휘를 코드가 갖고 맞지 않는 행을 순수 함수가
  걸러 내는 경우다.
- 식별자는 위 「식별자」 표를 따른다.

### 로컬 스택에서 실측한 것

- `config.toml` 의 `[api] schemas` 에 스키마를 노출하는 것은 **그 스키마를 만드는 마이그레이션과 한 커밋**이어야 한다.
  스키마가 없는 채로 노출만 있으면 PostgREST 가 스키마 캐시를 만들지 못해 503 을 내고 `supabase start` 자체가 실패한다.
- `supabase stop` 은 기본으로 DB 볼륨을 백업하고 다음 `start` 가 복원한다. 그 경로에서는 마이그레이션이 다시 적용되지 않는다.
  재생을 확인하려면 `supabase db reset` 을 돌리거나 `stop --no-backup` 뒤에 `start` 한다.
- `supabase db query` 는 한 호출에 한 문장만 받는다. 점검용 조회에만 쓰고 스키마 변경에는 쓰지 않는다.
- 클라우드 개발 컨테이너에는 도커 데몬이 기본으로 떠 있지 않다. `nohup dockerd &` 로 직접 띄우면 로컬 스택이 돈다.
  쓰지 않는 서비스는 `supabase start -x realtime,imgproxy,mailpit,studio,edge-runtime,logflare,vector,supavisor,postgres-meta`
  처럼 뺀다.
- 포트는 5436x 다(API 54361 · DB 54362).

## 테스트

불변식의 정본은 도메인마다의 `src/invariants.ts` 이고, 무엇이 어떻게 동작하는지의 정본은 테스트 이름이다.
아래는 그 요약이 아니라 **저장소에서 지키는 절차**다.

### 3층

| 층 | 도구 | 도커 | 지키는 것 |
|---|---|---|---|
| 도메인 | vitest (`packages/access` · `packages/agents`) | ❌ | 문을 여는 판정 · 행 단위 판정 · 상태 전이 · 실행 장부의 접기. **TDD 루프가 도는 곳** |
| 통합 | vitest (`packages/adapters-postgres`) + 로컬 Supabase | ✅ | 질의가 정말 그 행만 돌려주는가, 유일성·제약·트리거·GRANT 가 걸리는가 |
| e2e | Playwright (`apps/*/e2e`) | ✅ | 화면이 그 판정을 드러내는가. **스토리 하나가 e2e 하나** |

**같은 사실을 두 층에서 검사하지 않는다.** 그 사실을 확인하는 데 필요한 가장 싼 도구를 쓴다. e2e 가 볼 것은
전이가 막혔을 때 화면이 그것을 보여 주는가이지 전이 규칙 그 자체가 아니다.

통합 층은 스키마가 막기로 된 것과 **행을 읽는 질의가 도메인 판정과 같은 집합을 돌려주는 것**에만 쓴다. 뒤의
것이 가장 중요하다. 둘이 갈라지면 단위 검사가 전부 통과하는데 화면에는 볼 수 없는 행이 나온다.

### 절차 (`.claude/skills/tdd`)

1. **테스트 이름 합의가 먼저다.** 코드를 쓰기 전에 `it(...)` 목록과 그것이 붙을 공개 인터페이스를 적어
   사용자에게 확인받는다. 무엇을 캐내야 하는지는 `.claude/skills/spec-by-test/SKILL.md` 가 갖는다.
   - ⚠ **계획은 한 층·한 여정만 골라 내지 않는다.** 대상 범위(기능 하나든 플로우 하나든)에 걸린 **다섯 층**(순수 함수 · 포트 ·
     스키마 제약 · 서버 액션 · 화면)을 **전부 한 표**로 낸다. 어느 층에 만들 것이 없으면 빈칸이 아니라 「없음」과 이유를 적는다.
     resolv-ai 에서 판정 함수 셋만 제안했다가 계획을 다시 만든 적이 있고, 그것이 이 규칙의 이유다.
   - 출처도 하나만 훑지 않는다. 불변식 카탈로그 · 이미 있는 테스트 이름 · 라우트 디렉터리 셋을 전부 대조해
     같은 판정이 두 곳에 생기지 않게 합친다(REQ-02).
   - 공개 인터페이스(함수 이름과 시그니처 초안 · 지나는 판정과 포트 · 지키는 것)는 PR 본문에 적고, 리뷰를 받는
     동안 코멘트가 아니라 본문을 고쳐서 최신으로 둔다.
   - 설계가 갈리는 선택은 `docs/decisions/` 에 한 파일씩 남긴다. 한 번 적고 고치지 않는다.
     코드 주석과 마이그레이션도 그 파일로 결정을 가리킨다.
   - 무엇이 구현됐는지는 코드와 테스트 파일이 사실이다. 따로 어딘가에 「구현됨」을 적지 않는다.
2. **수직 슬라이스.** 테스트 하나를 쓰고 구현 하나를 쓰는 일을 되풀이한다. 테스트를 몰아 쓰고 구현을 몰아 쓰지 않는다.
3. **red before green.** 실패하는 테스트를 먼저 세우고, 그것을 통과시킬 최소 코드만 쓴다.
4. 리팩토링은 루프 밖(리뷰 단계)이다.

모킹은 **시스템 경계에서만**(외부 API·시간·식별자·파일시스템) 한다. 우리 모듈·내부 협력자는 모킹하지 않는다.

**통합 층은 도커 Supabase 로만 돈다.** 마이그레이션과 시드가 `service_role` 같은 Supabase 의 롤과 `auth.users` 에
기대므로 맨 Postgres 나 PGlite 로는 재생할 수 없다.

- 어댑터 테스트는 `WEB_DATABASE_URL` · `AGENT_DATABASE_URL` 로 로컬 스택의 **DB(54362)** 를 가리킨다. API(54361)가 아니다.
  앱이 PostgREST 를 지나지 않기 때문이다. **앱이 늘면 변수도 는다.** 앱마다 롤이 다르기 때문이다.
- ⚠ 접속 롤은 **앱의 롤**이고 소유자 `postgres` 가 아니다. 운영과 같은 롤이어야 GRANT 가 검증된다.
  소유자 롤(`OWNER_DATABASE_URL`)은 앱 롤로 심을 수 없는 행을 심는 배경에만 쓰고, 재는 질의는 앱 롤이 낸다.
- 두 변수의 **로컬 기본값은 `packages/adapters-postgres/vitest.config.ts` 가 깔아 둔다.** 스택만 올라가
  있으면 `npx turbo test` 가 그대로 돈다. 원격이나 다른 포트를 가리키려면 변수를 주면 그것이 이긴다.
  ⚠ 기본값이 검사를 무르게 하지는 않는다. 스택이 없으면 접속이 거절되어 빨강이고, 로컬 호스트가
  아니면 `localDb`(`src/testing/local-db.ts`)가 거부한다.

```bash
supabase start -x realtime,imgproxy,mailpit,studio,edge-runtime,logflare,vector,supavisor,postgres-meta
supabase db reset
cd packages/adapters-postgres
npx vitest run
```

⚠ **패키지 안에서 돌린다.** 루트에서 `--dir packages/adapters-postgres` 로 부르면 그 패키지의
`vitest.config.ts` 를 읽지 않아 `server-only` 별칭이 빠지고, 검사가 시작되기도 전에 모든 파일이
import 단계에서 실패한다.

- 부모 행(테넌트·계정·멤버십)은 `supabase/seed.sql` 이 심는 **합성** 데이터이고 id 가 고정이다. 검사는 그 값을 참조한다.
  검사가 재는 행은 테스트마다 새로 만들고 부모는 공유한다. 테스트가 부모를 고치지 않으므로 섞이지 않는다.
- ⚠ **DB 는 행이 남는다.** 유일 컬럼은 실행마다 다른 값에서 세고(예: `freshName`), 목록 단언은 그 테스트가 심은 것만 본다.
  고정 대역에서 세면 두 번째 실행이 통째로 깨진다.
- ⚠ env 가 없을 때 **건너뛰지 않고 실패한다.** `describe.skip` 으로 조용히 초록이 되면 통합 검사가 없는 것과 같다.
  CI 에도 로컬 스택을 올린다(`supabase start` 뒤 `db reset`).
- prod 를 가리키면 실제 행이 생기므로 URL 이 로컬 호스트가 아니면 러너가 거부한다.

### 채우는 순서

```
① 문을 여는 판정과 행 단위 판정 → ② 상태 전이와 합산 → ③ 통합 → ④ e2e
```

①과 ②는 화면이 하나도 없는 상태에서 쓸 수 있다. 행 단위 판정은 틀리면 남의 데이터가 새는 판정이고 여러 스토리가
같은 함수를 본다. 가장 먼저 쓰고 가장 많은 경우를 넣어 볼 함수다.

### 불변식 레지스트리와 잇는다

- 테스트 이름에 불변식 id 를 넣는다. 예: `it("INV-AGENT-01 초안은 실리지 않는다 …", …)`
  (`packages/notes/src/rules/visibility.test.ts`). 레지스트리의 「검증」칸이 그 파일과 이름을 가리킨다.
- 레지스트리는 **테스트에서 뽑지 않는다.** 결정과 도메인 규칙에서 문장을 먼저 뽑고 테스트와 대조한다. 빈칸이 나오는 것이 정상이다.
- 강제 지점이 「사람(리뷰)」인 행(지금은 `REQ-*` 여섯)은 기계가 막지 않는다. 그 수가 늘면 위험 신호다. 새 문장을 적을 때는
  기계가 막는 모양으로 바꿀 수 없는지 먼저 본다.
- 도메인이 늘면 그 패키지가 자기 카탈로그(`INV-<도메인>-NN`)를 갖고 `packages/shared/scripts/check-invariants.mjs` 의
  목록에 줄을 더한다.

### 시드 원칙 넷

1. 검사마다 자기 시드를 만든다. 공유 가변 픽스처를 두지 않는다. 시드 함수 이름에 검사 id 를 넣는다.
2. 시드는 **도달 가능한 상태**여야 한다. 실제 경로로는 생길 수 없는 행(닫혔는데 뒤가 자라는 실행, 판을 가리키지 않는
   다른 테넌트를 가리키는 쪽지)을 심지 않는다. 장애를 흉내 내는 시드(`degraded`)는 예외다.
3. e2e 는 데이터로 격리한다. 스펙마다 자기 행을 만들고 **정리하지 않는다.**
4. 시각과 식별자는 결정적이다. 도메인 층은 시각을 인자로 받으므로 테스트가 그 값을 고정한다.
   e2e 는 시계를 고정할 수 없으므로 정확한 시각을 단언하지 않고 "지난 것으로 표시됨" 수준으로만 본다.

시드 조립기는 기본값을 가지고, 검사가 신경 쓰는 범위만 골라 받는다.

⚠ 클라우드 개발 환경에는 **chromium 만** 설치돼 있다. Playwright `projects` 를 chromium 단독으로 둔다
(앱마다 `playwright.config.ts`).

## Effect

이 저장소는 Effect TypeScript 라이브러리를 쓴다. Effect 코드를 쓰기 전에 먼저 `node_modules/effect/AGENTS.md` 를 **완독**하고,
필요하면 `node_modules/effect/src` 를 검색할 것.

- **v4 다. v3 기억으로 쓰지 말 것.** `Context.Tag` 가 아니라 **`Context.Service`**, `Schema.decodeUnknownSync` 가 아니라
  **`decodeUnknownEffect`** 이고, `Schema.minLength` 는 **없다**.
- 서비스는 `Context.Service` + `static readonly layer` 로 만든다. 함수는 `Effect.fn("name")`, 흐름은 `Effect.gen` 으로 쓴다.
- 에러는 `Schema.TaggedError` 로 정의하고 `Effect.catchTag` 로 잡는다.
- 시간은 `DateTime` 모듈을 쓴다. 타입 가드는 직접 만들지 말고 `Predicate` 모듈을 쓴다.
- 로그는 `Effect.logWarning` 계열로 남긴다. Effect 밖이라면 `runFork` 로 띄운다.

## UI

`packages/ui` 는 앱이 함께 쓴다. 안의 컴포넌트와 3층 CSS 는 **tyohnn 에서 받아 둔 것**이고(스캐폴드의 기본은 `loam`),
정본 문서는 `docs/design-system/README.md` 다.

- **`@hathway/ui` 만 쓴다.** 기본 컴포넌트 61개가 이미 전부 설치돼 있다. 화면을 만들 때는 `packages/ui/src/components/` 를 먼저
  훑어보고 있는 것을 조합한다. ⚠ **`npx shadcn add` 를 돌리지 않는다.** 컴포넌트는 tyohnn 이 한 벌로 갖고 CLI 가 통째로
  받아 온다. 새 컴포넌트가 필요하면 tyohnn 에 더한 뒤 다시 받는다.
- 화면을 조립하는 단위는 `packages/blocks` 의 블록(DataTable·DetailPanel·StatCard·ItemList 등)이다. 블록은 데이터를
  가져오지 않고 도메인 타입을 모른다. 규약은 `packages/blocks/CLAUDE.md` 에 있다.
- ⚠ **`form` 컴포넌트는 없다. 찾지 말 것.** Base UI 계열에서 그 자리는 **`field`** 다. Radix 판 `form` 을 손으로 옮겨 오지 말 것.
- ⚠ **`packages/ui/src/**` 는 손으로 고치지 않는다.** 컴포넌트도 3층 CSS 도 tyohnn CLI 소유이고, CLI 는 자기가 쓴 파일의 해시를
  `tyohnn.json` 에 적어 둔다. 손으로 고치면 다음 실행이 그 파일을 비켜 가고 우리 저장소와 시스템이 조용히 갈라진다. 고칠 일이면
  tyohnn 저장소에서 고쳐 다시 받는다. 컴포넌트는 구조·행동 유틸리티 + `cn-*` 클래스만 갖고 보이는 성질은 전부 CSS 가 정한다.
- **`cn-*` 클래스 이름은 업스트림과 같은 계약이다.** 바꾸면 다시 받은 컴포넌트가 스타일 없이 렌더된다.
- 스타일은 3층이고 자리는 `packages/ui/src/systems/<system>/` 다. `globals.css`·`theme.css`(1층, 모양과 색) →
  `tokens.css`(2층, 컴포넌트 토큰) → `style.css`(3층, `components/*.css` 의 `cn-*` 규칙을 모은 배럴). 앱의 `globals.css` 가
  이 순서로 읽고 **3층만 `layer(base)`** 로 읽는데, 그 순서를 적는 것은 CLI 의 `tyohnn:begin system` 블록이다.
  긴 글 조판(`typeset.css`·`typeset-preset.css`)은 3층과 별개다.
- 값이 마음에 들지 않으면 화면이 아니라 2층 토큰을 고친다. **여기가 아니라 tyohnn 에서** 고쳐 다시 받는다.
  hover 색을 `color-mix()` 로 계산하지 말고 토큰으로 명시한다. 시스템에 속하지 않는 제품 치수는 `packages/ui/src/product.css` 가 갖는다.
- **사이즈 이름이 곧 높이다.** 그 높이는 시스템이 정하므로 시스템을 갈면 함께 바뀐다. 숫자를 화면에 적어 넣지 말 것.
  작게 쓰려면 한 단계 내려 잡지 말고 `size="sm"` 을 준다.
- **Base UI 는 Radix 와 API 가 다르다** (`.claude/skills/shadcn/rules/base-vs-radix.md`): `asChild` 대신 **`render`**,
  비-button `render` 에는 `nativeButton={false}`, `Select` 는 `items` prop 필수, Toast 는 sonner 가 아니라 `toast.add()`.
- 아이콘은 `@hathway/ui/icons` 의 **의미 이름**으로 부른다. 아이콘 패키지(`lucide-react`)를 컴포넌트에서 직접 부르지 않는다.
  라이브러리를 갈면 그 자리만 남기 때문이다. 지금 걸린 라이브러리는 `lucide` 다.
- 타입 스케일은 Tailwind 기본(`text-xs`~`text-4xl`)을 쓴다. 커스텀 `--text-<이름>` 스텝을 더하면 클래스 병합기(`cn`)가
  그것을 색상 유틸로 오인해 함께 준 색을 지울 수 있으므로, 더하기 전에 병합기가 그 스텝을 아는지 먼저 확인한다.
- 폰트는 앱 소유이되 **배선은 CLI 가 갖는다**(`layout.tsx` 의 `tyohnn:begin fonts` 블록, `node_modules/pretendard` 를 가리킨다).
  손으로 `localFont` 를 선언하지 말 것. 같은 이름을 CLI 블록이 다시 선언해 다음 실행이 파싱에서 멈춘다.
- 절대 경로를 문자열로 적지 않고 **경로 헬퍼**(앱마다 `src/lib/paths.ts`)를 지난다. 라우트의 모양이 바뀌면 그 한 곳만 고친다.

## 컴포넌트 설계 (composition)

- boolean prop 으로 동작을 분기하지 말 것 → 명시적 variant 컴포넌트.
- 복합 컴포넌트는 서브컴포넌트가 **props 가 아니라 context** 로 상태를 읽는다. 인터페이스는 `{ state, actions, meta }` 3분할.
- `renderHeader` 같은 render prop 대신 `children`.
- `use client` 는 잎사귀에만 둔다. 클라이언트 경계로 넘기는 데이터는 최소로 한다.

## 데이터·스켈레톤

- 데이터는 RSC 에서 가져와 streaming 으로 내려보낸다. 독립 작업은 `Promise.all` 로 묶는다. 목록의 행마다 딸린 이름을 붙일 때 한 건씩 조회하지
  않는다(N+1).
- **스켈레톤을 따로 그리지 말 것.** 기다리는 얼굴은 같은 컴포넌트의 `loading` 상태다(「Pending 쌍둥이」). 규칙과 본보기는
  루트 `CLAUDE.md` 「정적 껍데기」에 있다. 게이트는 본문을 감싸지 않고, 화면의 조회는 관문 `appRead` 를 지난다.
- `fallback={null}` 은 빈 화면을 만든다. 옳은 경우는 성공 시 아무것도 그리지 않는 조각(게이트 `AuthGate` · 모듈의 자리)뿐이다.
- LCP 엘리먼트(보통 메인 헤딩)는 `<Suspense>` **밖**에 둔다.

## 커밋

한 커밋은 **한 가지 책임**만 바꾼다.

| 순서 | 책임 | 예 |
|---|---|---|
| 1 | 도구·환경 | 스킬팩, `.gitignore`/`.dockerignore` |
| 2 | 의존성 | 버전 핀, 호이스팅 해소 |
| 3 | 패키지 골격 | 새 도메인 패키지 신설 |
| 4 | 도메인/포트 | 순수 규칙 또는 포트 하나 + 그 테스트 |
| 5 | 어댑터 | 포트 구현. 포트와 같은 커밋에 넣지 않는다 |
| 6 | 앱 배선 | 라우트·레이아웃·서버 액션 |
| 7 | 인프라 설정 | `supabase/`, 마이그레이션, 배포 설정 |
| 8 | 문서·규약 | `CLAUDE.md`, `docs/` |

- **저장소의 첫 커밋도 이 순서로 나눈다.** 이미 서 있는 파일을 한꺼번에 들일 때도 한 커밋에 모으지 않는다.
  책임별로 나뉘어 있어야 한 책임만 되돌리거나 다른 저장소로 옮길 수 있다.
- **각 커밋이 빌드·타입체크를 통과**해야 한다.
- **생성물과 수정본을 나눈다.** CLI 가 만든 것을 먼저 커밋하고 우리가 손댄 것은 다음 커밋에 넣는다.
- **문서는 코드와 같은 커밋에 넣지 않는다.** 단, 코드가 규약을 어기는 예외를 만들 때는 함께 넣어 근거를 붙인다.
- 커밋 메시지는 한국어로 쓴다. **제목에는 무엇을, 본문에는 왜를 적는다.** 되돌리면 안 되는 이유와 실측 근거를 본문에 남긴다.
- 타입은 `feat` / `fix` / `refactor` / `chore` / `docs` / `test` / `build` 이고, 스코프는 워크스페이스 이름이다: `feat(agent):`, `feat(agents):`,
  `fix(access):`, `build(supabase):`.

## 이 저장소만의 자리

2026-10-18 에 옛 hathway(pnpm · Next 16.2 · `platform/supabase`)를 스캐폴드 위로 옮겼다. 스캐폴드의 규약을 그대로 따르되
아래 자리만 다르다. 들일 일이 생기면 그 줄을 지우고 이 문서의 해당 절을 따른다.

### 읽기는 공개다

종목 · 부동산 화면(`apps/web/src/app/(market)/`)은 로그인하지 않아도 읽는다. **쓰기만 관문 뒤다**(INV-RESEARCH-01,
2026-10-02 사용자 결정). 스캐폴드의 셸(`(app)/`: 홈 · 쪽지 · 설정)은 그대로 로그인 뒤다.

- 미들웨어의 `PUBLIC_PATHS` 에 `/stocks` · `/real-estate` 가 있다. 미들웨어는 문 앞의 안내일 뿐이다.
- 화면은 `viewer()`(`src/lib/viewer.ts`)로 지금 보는 사람을 얻는다. 없으면 `null` 이고 화면은 그대로 선다. 이 값은 쓰는 단추를
  세울지를 정하는 **표시용**이고, 쓰기는 관문 `appAction` 이 다시 판정한다.
- 관문이 끊은 요청은 액션이 어휘(`sign-in`)로 바꿔 돌려주고 화면이 로그인으로 안내한다(`src/lib/gateRefusal.ts`).
- 읽는 메서드가 행위자를 받기 시작하면 그것은 가려야 할 행이 생겼다는 뜻이다. 그때는 술어를 도메인 패키지에 먼저 세우고
  계약 테스트가 「질의 결과 = 술어의 결과」를 잰다.

### 조회의 길

종목 · 공시 · 재무의 조회는 `packages/market` 의 포트 넷(`CompanyDirectory` · `FinancialPeriods` · `FilingLedger` ·
`FilingDocuments`)을 지난다. 앞의 셋은 Postgres 어댑터가 `web_app` 으로 읽고, 공시 본문 조각만 저장소 어댑터가 읽는다.

```
화면(서버 컴포넌트) → src/lib/platform/db.ts(입구) → src/usecases/market.ts(조립) → 포트 → 어댑터
                                                         └ 접고 고르는 판단은 packages/market/rules
```

- **조회를 더할 때**는 포트에 메서드를 더하고, 메모리 구현과 계약 테스트(`packages/market/src/testing`)를 먼저 고친 뒤에
  Postgres 구현을 맞춘다. 새 표를 읽으면 마이그레이션에 `grant select … to web_app` 을 더한다.
- **읽지 못하면 던진다.** `WEB_DATABASE_URL` 이 없으면 로컬 주소로 떨어지지 않고 실패한다. 셸의 종목 검색처럼 비어도 되는
  자리는 부르는 쪽이 잡는다. 공시 본문 조각만은 없는 것이 흔해서 `null` 로 답한다.
- **시세 조회는 요청마다 돈다.** `runMarket`(`src/lib/marketRuntime.ts`)과 보드 조회(`src/lib/boards.ts`)가 먼저 `connection()` 을
  기다려서 빌드가 그 조회를 굽지 않는다. 빌드 환경에는 DB 접속값이 없다.

### 스캐폴드와 다른 자리

| 스캐폴드 | 이 저장소 | 까닭 |
|---|---|---|
| 조회한 행도 Effect `Schema` 로 파싱 | 조회한 행의 계약은 `packages/schema` 의 zod 그대로 | 적재(`platform/ingest`)와 화면이 같은 계약을 쓴다. 어긋난 행은 버리지 않고 로그만 남긴다 |
| 도메인마다 새 스키마 | 시장 데이터와 리서치 보드의 표는 `public` 그대로 | 먼저 있던 표이고 적재가 PostgREST 로 쓴다. 새 도메인은 새 스키마로 선다 |
| 화면은 모두 정적 껍데기 규칙대로 | 옮겨 온 시장 화면은 `export const instant = false` 로 먼저 섰다 | 한꺼번에 고치지 않고 화면마다 이슈로 고친다(`next-cache-components-adoption` 스킬). 고친 화면은 그 줄을 지운다 |
| 화면은 `@hathway/ui/icons` 의 의미 이름만 | 시장 화면 11곳이 `@phosphor-icons/react` 를 직접 부른다 | 지갑 · 저울 · 과녁처럼 의미 이름이 없는 도메인 아이콘이 많다. 서버에서도 깨지지 않도록 두 앱의 `next.config.ts` 가 phosphor 를 ssr 진입점으로 돌린다 |
| 무엇을 왜 만드나는 `docs/decisions/` | PRD · 스토리 · 계획 · ADR 의 정본은 Notion 이다(`AGENTS.md` 「Oh My Docs」) | 종전 그대로다. 코드의 결정만 `docs/decisions/` 에 둔다 |
| 기법 번호를 약어로 막는다 | 교재의 장 접두(A1 · B3 · D2)는 정본 식별자라 막지 않는다(`check-invariants.mjs` 의 `RETIRED` 가 비어 있다) | `AGENTS.md` 「채 순서」 |
