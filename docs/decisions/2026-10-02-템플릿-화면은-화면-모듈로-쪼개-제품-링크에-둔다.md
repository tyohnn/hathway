# 템플릿 화면은 화면 모듈로 쪼개 제품 링크에 둔다

날짜: 2026-10-02 · 결정한 사람: 사용자(AskUserQuestion)

## 배경

tyohnn 의 데모 템플릿 17종(CRM · Orders · Analytics · Calendar · Inbox · Editor · Team 등)의 화면 조각이 좋아서
새 제품에 기본으로 들어가길 원했다. 템플릿은 고정 영어 데모 데이터와 자기 사이드바를 가진 쇼케이스다. 이것을
스캐폴드로 옮기는 방식을 정했다.

## 결정

1. **데모 갤러리가 아니라 제품 화면이다.** `(app)/<화면>/` 라우트와 사이드바 메뉴로 들어간다. 템플릿의 자체 사이드바 ·
   헤더는 버리고 본문만 셸 안에 옮긴다.
2. **화면 묶음마다 모듈이다.** 파일럿 `orders` 와 묶음 넷(`dashboard` · `workspace` · `planning` · `content`, 화면 넷씩)이고,
   `create.sh --with` 로 고른다. 고르지 않은 묶음은 코드째 걷힌다. 17개를 한꺼번에 켜면 메뉴가 길어지기 때문이다.
   사이드바는 묶음(`NavEntry.section`)마다 구분선으로 갈라 세운다.
3. **공용 조각은 `templates-kit` 모듈이다.** 화면 모듈이 `requires` 로 요구하므로 함께 켜진다. 넓게 뽑는다: 템플릿 둘
   이상에 있는 모양은 하나로 합치고, 한 화면에만 있어도 다른 화면이 그대로 쓸 모양(주간 격자 · 변경 줄 표 · 차트 카드 등)은
   조각으로 둔다. 화면에는 짜임과 도메인 규칙과 글만 남는다. 코어 블록(`packages/blocks`)에 이미 있는 모양은 새로
   만들지 않는다.
4. **데이터는 한국어 본보기이고 읽는 길은 `appRead` 다.** 화면은 모듈의 조회 함수(`loadOrderBoard`)가 돌려주는 모양만
   안다. 지금은 본보기를 돌려주고, 제품은 그 함수만 DB 조회로 바꾼다. 정적 껍데기 규칙과 e2e 가 그대로 선다.
5. **영어 데모 글은 해요체 한국어로 옮기고 화면 글 검사(`scan-copy`)와 검토 에이전트를 지난다.**

## 도구

- `check:modules` 의 3번 규칙은 「그 모듈을 요구하는 모듈의 자리」도 예외로 둔다. 화면 모듈이 kit 을 부르는 길이다.
- 파일은 tyohnn 소유가 아니라 스캐폴드의 것이다. `tyohnn doctor` 가 추적하지 않으므로 템플릿이 바뀌면 손으로 옮긴다.

## 파일럿에서 알게 된 것

- 기다리는 얼굴(`loading`)의 표와 값이 온 표는 서로 다른 인스턴스다. 값이 오기 전에 누른 탭 · 입력은 값이 오면서 사라진다.
  e2e 는 값이 보인 뒤에 누른다.
- 틀이 먼저 구워져 오므로 브라우저 쪽이 붙기 전의 눌림은 사라진다. e2e 는 눌림이 먹을 때까지 다시 누른다.
- 템플릿의 행 메뉴 · 내보내기 · 라벨 인쇄처럼 뒤가 없는 단추는 옮기지 않았다. 동작하는 것만 둔다.

## 전체를 옮기며 알게 된 것

- 화면 16개는 화면마다 에이전트 하나가 옮기고, 조각을 kit 으로 모으는 일은 화면이 겹치지 않게 넷으로 나눠 했다. 같은
  작업 폴더를 함께 쓰므로 빌드와 e2e 는 조정하는 쪽이 끝에 한 번 돌렸다.
- 에이전트끼리 같은 조각을 따로 만든 자리(겹친 얼굴 · 검색 칸)와 공용 코드 상자를 화면 CSS 로 덮어쓴 자리는 끝에 하나로
  합쳤다. 코드 상자는 글자 크기 축(`size`)을 가진다.
- 라디오 메뉴 줄은 눌러도 메뉴를 닫지 않는 것이 Base UI 의 기본이다. 고르는 줄에는 `closeOnClick` 을 준다.
- 라벨(`htmlFor`)이 붙은 체크박스의 이름은 라벨에서 온다. 줄마다 같은 글이면 보이지 않는 글(`sr-only`)로 가른다.
- 문서 · 가이드 · API 문서 · 회의록은 고른 항목이 주소에 남지 않는다. 릴리스 노트만 `?v=` 로 남긴다. 제품에서
  링크로 가리켜야 하면 그 화면을 `[id]` 라우트로 옮긴다.

## 화면을 눈으로 본 뒤 정한 것 (같은 날, 사용자)

- **지적받은 화면 글은 전부 반영한다.** 「거름 지우기」는 「조건 지우기」로, 사람은 「멤버」, 조직은 「팀」으로 부른다. 본보기의
  오늘은 화면마다 다르지 않게 2026-01-14 로 맞춘다.
- **보내기와 저장은 숨기지 않고 실제로 돌게 한다.** 플레이그라운드는 연습 모델이 답하고, 알림은 계정마다 메모리 저장소에
  남는다. 주문의 본보기 조회와 같은 짜임이라 제품은 구현 한 곳(`runtime.ts`)만 바꾼다.
- **템플릿 화면은 tyohnn 템플릿처럼 전체 화면이다.** 들어오면 앱 사이드바가 아이콘만 남기고 접히고, 본문이 판의 가장자리까지
  쓰고, 문서가 구르지 않고 화면 안의 자리(표 · 기둥 · 글)가 따로 구른다. 틀은 kit 의 `ScreenFrame` 이고, 셸은 화면이 단
  `data-screen="fill"` 을 보고 우물을 푼다. 알림 설정은 설정 화면이라 우물 안에 둔다.
- **위 띠는 늘 보인다.** 셸(`well`)을 화면 높이에 묶고 본문이 구른다. 코어 화면도 같다.
- e2e 에서 알게 된 것: 로그아웃은 그 계정의 세션을 모두 끊는다(Supabase 의 기본 범위). 여러 스펙이 함께 쓰는 계정으로
  로그아웃을 재면 나란히 돌던 테스트가 로그인 화면으로 밀려난다. 떠 있는 개발 서버(4400)가 있으면 e2e 가 그것을 닫힌
  서버로 잘못 붙잡는다.
