# scaffold-fit 을 가상 제품으로 끝까지 돌려 고쳤다

날짜: 2026-10-05 · 요청한 사람: 사용자(「가상 제품 하나로 끝까지 돌려 봐. 서브에이전트 사용하기」)

앞의 결정(`2026-10-05-복제-뒤에-에이전트가-제품에-맞춰-다시-짠다.md`)으로 세운 `/scaffold-fit` 을 가상의 동네 의원 예약 제품
「클리닉북」으로 0번부터 8번, 그리고 6번의 첫 명사(진료 기록)까지 돌렸다. 서브에이전트가 스킬을 따랐고, 조정하는 쪽이 사람 자리에서
캐내는 질문에 답하고 지도와 테스트 이름을 확인했다. 마찰 71개를 기록했고 그 가운데 스킬 · 스크립트 · 원본 문서로 고칠 수 있는 것을 고쳤다.

## 결과

- 지도: `/appointments`(주문 화면에서) · `/schedule`(캘린더 화면에서, 하루를 의사마다 한 칸) · `/patients`(고객 관리 표에서) ·
  `/patients/[patientId]` · `/appointments/[appointmentId]` · `/appointments/stats`(분석 화면에서). 모듈 셋을 떼고 셋을 편입했다.
- 진료 기록은 `packages/records` 로 새로 섰다(불변식 여섯, 계약 시험이 메모리와 Postgres 를 함께 잰다).
- 마지막 검사: typecheck 15/15, 단위 · 계약 시험 646개, 검사 스크립트 다섯, 빌드, web e2e 69개가 모두 초록이었다.

## 바꾼 판단

1. **첫 도메인은 `notes` 옆에 새로 세운다.** 앞의 스킬은 「모양이 닮았으면 `notes` 를 옮겨 시작해도 된다」고 했다. 실제로는 결제의
   크레딧 · 분석 이벤트 · MCP 도구 · 에이전트 도구가 모두 쪽지 하나를 타서, 옮기면 넷이 빈다. 결제 모듈이 가진 시험 파일도 쪽지를
   import 하므로 고치면 원본과 어긋난다.
2. **조회는 5번에서부터 행위자를 받는다.** 「조회 함수 하나만 바뀌고 화면은 그대로」라던 약속은 본보기 조회가 행위자를 받지 않아서 지켜지지
   않았다(화면 세 곳을 고쳤다).
3. **라우트의 e2e 는 그 라우트와 같은 커밋에서 옮긴다.** e2e 를 맨 뒤로 미루면 사이의 커밋이 모두 빨갛다.
4. **화면 여럿이 함께 보는 본보기는 세계 하나로 둔다**(`src/boards/<제품>/sample.ts`). 오늘 예약에서 누른 환자가 환자 상세에서도 같아야 한다.
5. **재료 목록은 손으로 쓰지 않고 주석에서 뽑는다**(`scaffold-fit/scripts/materials.mjs`). tyohnn 블록 98개에 목록 문서가 없어 지도를 그릴 수 없었다.

## 고치지 않고 남긴 것

- 화면 글 검사(`scan-copy`)가 도메인의 낱말(예약 상태 「취소」)을 단추로 읽는다. 줄마다 까닭 주석으로 넘겼다.
- 메뉴를 역할로 거르는 길이 셸에 없다(`NavEntry`). 원장만 보는 통계 같은 답이 나오면 셸을 늘리는 일이 된다.
- 머리 블록이 둘(`PageHeader` · `PageHeading`)이고, 새 화면이 어느 쪽을 쓸지 정한 곳이 없다.
- 결제 · 분석 모듈의 시험이 예시 도메인을 import 한다. 모듈 안의 가짜 기능으로 돌게 바꾸는 일은 따로 한다.
- 서버에서 쓸 날짜 포맷 도우미와 제품의 시간대를 정한 곳이 없다. `appRead` 가 요구 없는 Effect 만 받아 도메인마다 도우미가 생긴다.
- 영문으로 끝나는 이름(`clinic-book를`)의 조사는 읽는 소리를 알 수 없어 고치지 않았다.
