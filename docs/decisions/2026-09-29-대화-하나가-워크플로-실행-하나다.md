# 대화 하나가 워크플로 실행 하나다

## 정한 것

- agent 앱의 대화는 Workflow DevKit 의 실행 하나가 든다. 첫 말이 실행을 걸고, 턴 사이에는 훅(`chatMessageHook`)을
  기다리며 컴퓨트를 쓰지 않는다. 이어 말하면 `/api/chat/[runId]` 가 그 훅을 깨운다. 실행 번호가 곧 대화의 주소다.
- 모델이 읽는 맥락은 워크플로가 들고, 사람이 다시 열어 볼 말은 `agent` 스키마의 장부가 든다. 장부에 적는 일은
  전부 워크플로의 스텝이 한다. 대화의 줄을 여는 일도 워크플로의 첫 스텝이다.
- 워크플로는 행위자를 나르지 않는다(INV-AGENT-04). 계정 id 를 나르고 도구가 도는 스텝이 그 순간 행위자를 다시 세운다.
- 턴마다 `finish` 를 스트림에 적고, 라우트가 그 자리에서 응답을 닫는다(`lib/turnStream.ts`).
- 게이트웨이 키가 없는 로컬과 e2e 는 연습 모델(`AGENT_RUNNER=rehearsal`)로 돈다. 워크플로 · 스텝 · 도구 · 장부는
  실물과 같은 길로 돌고 모델 호출 한 자리만 바뀐다.

## 까닭

- 한 실행이 대화를 들고 있으면 지난 말을 매번 다시 실어 보내지 않아도 되고, 사람이 자리를 비운 사이에도
  실행이 죽지 않는다. 서버리스에서 요청 하나를 열어 둔 채 기다리는 모양은 그 둘을 다 잃는다.
- 워크플로의 스트림은 모델의 출력만 담고 훅으로 들어온 사람의 말은 담지 않는다(Workflow 문서 「Chat Session
  Modeling」). 새로 고친 화면이 대화를 다시 세우려면 사람의 말이 따로 적혀 있어야 한다.
- 장부를 실행을 건 라우트가 열면 그 요청과 첫 턴이 경주한다. 스캐폴드를 세우며 연습 모델로 돌렸더니 첫 턴이
  라우트보다 먼저 끝나는 일이 있어 줄을 여는 자리를 워크플로 안으로 옮겼다.
- `createModelCallToUIChunkTransform` 은 스트림이 닫힐 때만 UI 의 `finish` 를 낸다. 스트림을 턴 사이에 닫지 않는
  이 모양에서는 화면이 턴의 끝을 알 수 없어서, 턴의 `finish` 에서 응답을 끊는 변환을 앞에 둔다(실측).
- 연습 모델을 워크플로 밖의 가짜 실행기로 두면 e2e 가 워크플로를 지나지 않는다. 모델 한 자리만 바꿔야 e2e 가
  내구성 있는 실행의 배선을 끝까지 잰다.
