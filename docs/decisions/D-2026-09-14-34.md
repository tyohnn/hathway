# D-2026-09-14-34 · 소속 판정은 앱 이름을 받는 술어 하나로 모으고 어댑터는 사실만 읽는다

> agent-campus 로 옮기며 남긴 기록입니다(2026-09-28). 본문의 resolv · advisor 는 옮기기 전의 이름입니다.

| | |
|---|---|
| 날짜 | 2026-09-14 |
| 앱 | advisor · admin · customer · agent |
| 되돌리는 조건 | 앱마다 읽는 표가 달라져 같은 사실로 판정할 수 없게 될 때. 그때는 술어를 나누지 않고 사실을 읽는 어댑터를 앱마다 둡니다 |

네 앱이 같은 표(`public.admin_users`)를 읽는데 문을 열 조건은 앱마다 다릅니다. 지금까지 그 판정은 어댑터 안(`findActorByUserId`)에 있었고 내용은 advisor 의 것이었습니다. agent 가 그 함수를 빌려 쓰면서 「임팩터스 사람인가」로 에이전트를 운영하는 사람을 판정하는 상태였습니다.

## 정한 것

판정은 `packages/legal` 의 `canEnterApp` 하나이고, 어댑터는 `admin_users` 한 행을 **사실 그대로** 올립니다. 앱은 자기 이름만 넘깁니다.

| 앱 | 지금의 규칙 |
|---|---|
| advisor | 임팩터스 구성원 |
| agent | 임팩터스 구성원. 에이전트를 만들고 시험하는 사람이 리솔브 안에 있습니다(R-002) |
| admin · customer | 아무도. 그 앱의 술어가 아직 서지 않았습니다 |

모르는 앱은 거절합니다. 기본값을 허용으로 두면 기획이 서기 전에 문이 먼저 열립니다.

## 오류 이름도 함께 고쳤습니다

`NotAdvisorUser` 를 `NotAppMember` 로 개명했습니다. 포트는 네 앱이 함께 쓰는데 오류 이름이 한 앱을 가리키면 나머지 셋에서 뜻이 어긋납니다.

## 롤은 앱마다 하나라는 규칙이 여기서도 걸립니다

agent 앱이 `admin_users` 를 읽으려면 `agent_app` 에 그 표의 컬럼 권한을 따로 줍니다(D-2026-09-09-07 과 같은 모양). advisor 보다 좁게 주어 회사·계약·연락처에는 아무 권한도 주지 않았습니다.
