advisor 가 `advisor_app` 으로 붙는 것과 같은 물음이 agent 에도 왔습니다. `advisor_app` 에 `agent` 스키마 권한을 더할지, 롤을 새로 만들지입니다.

## 정한 것

`agent_app` 을 새로 만듭니다. 결정 D-2026-09-09-06 이 정한 「롤은 앱당 하나이지 스키마당 하나가 아니다」를 그대로 따르는 것인데, advisor 와 agent 는 따로 배포되는 서로 다른 프로세스입니다. `advisor_app` 에 권한을 더하면 advisor 가 뚫릴 때 에이전트 정의까지 함께 열리고, 그 반대도 같습니다.

마이그레이션은 이름과 GRANT 만 만듭니다. LOGIN 과 BYPASSRLS 와 비밀번호는 로컬에서는 `supabase/seed.sql` 이, 원격에서는 Management API 가 넣습니다. 비밀번호가 커밋되고 마이그레이션 기록에도 남기 때문입니다.
