# D-2026-09-14-35 · 로그인 액션은 관문 밖에 두고 로컬 계정은 개발에서만 선다

| | |
|---|---|
| 날짜 | 2026-09-14 |
| 앱 | agent |
| 되돌리는 조건 | 관문이 행위자 없는 액션을 따로 다룰 수 있게 될 때. 그때는 로그인도 관문을 지납니다 |

서버 액션은 관문(`appAction`)을 지난 것만 내보낸다는 규약이 있는데, 그 관문은 행위자를 확정한 뒤에야 핸들러를 부릅니다. 로그인은 행위자가 아직 없는 자리입니다.

## 정한 것

세션을 여닫는 액션 셋(구글 로그인 · 로컬 로그인 · 로그아웃)만 관문 밖에 두고, **그 파일은 도메인 데이터를 일절 만지지 않습니다.** 하는 일은 Supabase Auth 에 넘기는 것과 돌아갈 주소를 정하는 것뿐입니다. 도메인을 만지는 액션이 그 파일에 들어오면 관문을 우회하는 길이 생깁니다.

돌아갈 주소는 검사를 지납니다. `?redirect=` 는 사람이 주소창에 적을 수 있는 값이라, 검사 없이 쓰면 우리 로그인 화면이 남의 사이트로 보내는 통로가 됩니다.

## 로컬 계정

배포에는 구글 계정 하나이고, 로컬에는 이메일과 비밀번호 칸이 함께 섭니다. 시연과 개발에서 구글을 지나지 않고 들어올 수 있어야 하고, e2e 가 세션을 만드는 길도 그것입니다.

⚠ **화면에서 감추는 것만으로는 부족합니다.** 서버 액션은 화면을 지나지 않고도 불리므로 비밀번호 로그인 액션이 배포에서 스스로 거절합니다. Playwright 스모크가 프로덕션 빌드에 그 칸이 없는 것을 확인합니다.
