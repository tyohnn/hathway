# IA 는 루프 · 객체 · 라우트 · 그릇 차례로 짓는다

날짜: 2026-10-05 · 문제를 낸 사람: 사용자

## 배경

화면의 모양(UX · UI)은 tyohnn 디자인 시스템이 맡아서 고르게 나오는데, 정보 구조(IA)가 약했다. 클리닉북 시운전에서 메뉴가
템플릿의 분류를 따라 늘었고, 상세는 모두 페이지였고, 같은 셸 안에서 사이드바가 접혔다 펴졌다. 사용자는 사랑받는 SaaS(Viewstats ·
ElevenLabs · Viewtrap · v0 · Figma · Lovable · Flex)처럼 짓는 방법론을 스킬로 두길 원했고, 템플릿 스토어처럼 검색과 탐색이 필요한
제품도 함께 다루길 원했다.

## 바깥 스킬을 찾아본 결과

skills.sh 에서 「information architecture」 · 「sitemap」 · 「ooux」 · 「taxonomy」 · 「route design」 등으로 찾았다.

- `coreyhaines31/marketingskills@site-architecture`(설치 11만여 회)가 가장 가까웠다. 마케팅 사이트의 페이지 위계 · 주소 · 내부 링크 ·
  SEO 를 다룬다. 앱 안의 IA(객체 · 목록 · 상세 · 탭 · 시트 · 다이얼로그 · 셸)는 다루지 않는다.
- `dammyjay93/interface-design` 은 대시보드의 시각적 완성도, `mattpocock/skills@design-an-interface` 는 코드 모듈의 인터페이스를 다룬다.
- 앱 안의 IA 를 루프와 객체로 짓는 스킬은 찾지 못했다. 그래서 스킬을 직접 세웠고, 공개 사이트 쪽은 위 스킬을 참고로만 가리킨다.

## 정한 것

1. **스킬 `ia-design` 을 둔다.** 차례는 핵심 루프(클릭 예산) → 객체(OOUX 의 ORCA) → 라우트 → 그릇이다. 메뉴부터 그리지 않는다.
2. **제품의 꼴을 셋으로 가른다.** 관리형 · 생성형 · 탐색형. 탐색형은 분류 체계 · 공개 주소(경로와 쿼리의 기준은 「검색 엔진의 첫 화면이
   될 값어치」) · 스토어에서 앱으로의 전환을 더 정한다(`references/store.md`).
3. **라우트 그룹은 셸이 바뀌는 자리에서만 나눈다.** 셸은 공개 · 대시보드 · 워크벤치 셋이다. audience 가 바뀌면 그룹이 아니라 앱이다.
4. **깊이는 목록 → 상세 → 탭까지다.** 더 깊으면 시트다. 목록 위에 뜨는 다이얼로그 · 시트는 가로챈 라우트로 지어 링크로 바로 오면
   전체 페이지가 된다.
5. **루프의 클릭 예산을 e2e 로 잰다.** 스펙 이름에 예산을 적는다. IA 의 회귀를 막는 기계는 이것 하나다.
6. **`/scaffold-fit` 2번의 지도는 이 스킬로 그린다.** 셸 · 그릇 · 메뉴의 규칙은 `ia-design` 이 정본이고 `scaffold-fit` 은 재료 · 비용 ·
   걷는 것만 더한다.

## 까닭

- 메뉴를 기능(동사)으로 지으면 기능이 늘 때마다 메뉴가 는다. 객체(명사)로 지으면 새 기능이 객체 안의 탭이나 동작으로 들어간다.
- 몰입감은 상세에 들어가는 순간 셸이 바뀌는 데서 온다(Figma · v0). 같은 일 안에서 판이 바뀌면 오히려 길을 잃는다(클리닉북의 접혔다 펴지는 사이드바).
- 클릭 예산은 숫자라서 리뷰에서 다툴 수 있고, e2e 로 굳히면 「메뉴 하나만 더」가 들어오는 날 빨개진다.
