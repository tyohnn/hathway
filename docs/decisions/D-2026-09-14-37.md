# D-2026-09-14-37 · 실행 런타임은 Workflow DevKit 을 기본으로 깔고 AgentRunner 포트 뒤에서 갈아 끼운다

| | |
|---|---|
| 날짜 | 2026-09-14 |
| 앱 | agent |
| 되돌리는 조건 | beta 인 Workflow 5 가 규격을 크게 바꾸거나 자체 호스팅이 감당되지 않을 때. 그때는 포트 뒤를 ToolLoopAgent 로 갈아 끼우고 대화 상태를 IP-016 의 테이블이 듭니다 — 승인과 서명은 그쪽에도 있으므로 잃는 것은 내구성과 스텝 재시도뿐입니다 |

D-2026-09-14-36 은 「`WorkflowAgent` 가 주는 승인과 내구성을 그대로 쓴다」고 정하면서 근거로 「그 대기가 프로세스 재시작을 견딘다」를 들었습니다. 2026-09-14 에 번들 문서를 읽어 보니 그 문장이 **조건부**였습니다.

승인과 서명은 `ai` 패키지의 `ToolLoopAgent` 에도 있습니다(`toolApproval` · `experimental_toolApprovalSecret`). `@ai-sdk/workflow` 가 더 주는 것은 내구성과 스텝 재시도이고, 그것을 `WorkflowAgent` 혼자 주지 않습니다 — `workflow` 패키지(Workflow DevKit)의 런타임이 함께 서야 합니다. `WorkflowAgent` 는 `'use workflow'` 안에서만 살고 `generate()` 가 아예 없습니다.

## 정한 것

**Workflow DevKit 을 agent 앱의 기본 실행 런타임으로 깔고, 그것을 `AgentRunner` 포트 뒤에 둡니다.**

둘을 함께 정하는 까닭은 하나만으로 부족하기 때문입니다. DevKit 없이는 US-7-4 의 「창을 닫았다가 나중에 다시 열면 같은 승인 지점에서 이어서 정한다」가 프로세스가 살아 있는 동안에만 성립하고, 포트 없이는 beta 런타임이 도메인 규칙에 묶입니다.

## 로컬에서 도는 것을 확인했습니다

`workflow@5.0.0-beta.51` 의 문서가 「Local development uses the bundled backend with no configuration」이라고 적고 있습니다. 로컬은 무설정으로 돌고 `npx workflow web` 이 관측 화면을 냅니다. Next 통합은 `next.config.ts` 의 `withWorkflow({})` 한 줄입니다.

배포는 Vercel 관리형이 기본이고 자체 호스팅은 Postgres 백엔드를 씁니다. 뒤의 길이 열려 있다는 것이 이 선택의 뒷문이고, 이 저장소는 이미 Postgres 를 듭니다.

## 지키는 것

- 갈아 끼우는 자리는 `AgentRunner` 하나입니다. 거기 말고 또 생기면 이 결정의 뒷문이 닫힙니다.
- 연습 실행기(`packages/agents/src/run/rehearsal.ts`)를 지우지 않습니다. e2e 가 모델을 부르지 않고 도는 길이고, 실행 경로의 순수 규칙을 재는 자리로 남습니다.
- `@ai-sdk/workflow` 와 `workflow` 는 `packages/agents` 에 들어가지 않습니다. 그 패키지는 effect 외 런타임 의존이 금지입니다. 어댑터가 설 자리는 앱 안이거나 새 어댑터 패키지이고 IP-015 가 그것을 정합니다.
- IP-016 의 `agent.runs`·`agent.run_steps` 는 **장부로 남습니다.** 실행을 이어 붙이는 상태는 DevKit 이 들므로 두 벌이 되지 않습니다.

## 겹들여 알아 둔 것

AI Gateway 키가 무료 티어면 몇 번의 호출로 429 에 걸립니다. 시간 창이 지나면 풀리지만 e2e 에 상시로 붙일 수는 없습니다. 모델을 실제로 부르는 검사는 크레딧이 붙은 뒤에 세우고, 그전까지 e2e 는 연습 실행기로 돕니다.
