# 배포 설정은 앱마다 둔다

> agent-campus 로 옮기며 남긴 기록입니다(2026-09-28). 본문의 resolv · advisor 는 옮기기 전의 이름입니다.

| | |
|---|---|
| 날짜 | 2026-09-18 |
| 앱 | advisor · admin · customer · agent |
| 되돌리는 조건 | 한 Vercel 프로젝트가 저장소 루트를 루트 디렉터리로 두고 네 앱을 함께 세우게 될 때입니다. 지금은 앱마다 프로젝트가 하나입니다 |

admin 프로젝트의 첫 배포가 빌드를 마치고 죽었습니다. advisor 를 세운 뒤
`apps/admin/apps/advisor/.next` 에서 산출물을 찾았기 때문입니다. 루트 디렉터리는
`apps/admin` 인데 빌드 명령과 출력 경로는 저장소 루트의 `vercel.json` 이 준 것이고, 그 파일은
advisor 를 가리키고 있었습니다.

## 정한 것

저장소 루트의 `vercel.json` 을 지우고 `apps/<앱>/vercel.json` 넷을 둡니다. 각 파일은 자기
워크스페이스만 세우고(`turbo build --filter=@campus/<앱>`) 출력은 루트 디렉터리 기준의
`.next` 입니다.

루트에 한 장을 두는 한 그 파일은 앱 하나만 가리킬 수 있습니다. 앱이 넷인 저장소에서 그것은
새 프로젝트가 설 때마다 남의 앱을 세우는 배포를 한 번씩 낸다는 뜻입니다. 설정을 앱 옆에 두면
그 프로젝트가 무엇을 세우는지 파일 이름이 답합니다.

## customer 와 agent 도 함께 적습니다

두 앱은 아직 Vercel 프로젝트가 없습니다. 그래도 파일을 지금 두는 까닭은, 프로젝트를 만드는
사람이 대시보드에서 빌드 명령을 손으로 채우지 않게 하기 위해서입니다. 손으로 채우면 그 값이
저장소 밖에 남고, 앱 이름을 잘못 적은 것을 배포가 죽고 나서야 압니다.

## 대시보드가 아니라 파일입니다

빌드 명령과 출력 경로를 프로젝트 설정에 적어 두면 저장소를 읽어서는 무엇이 도는지 알 수
없습니다. 설치 명령처럼 프로젝트마다 다를 수 있는 것만 대시보드에 남기고, 어느 워크스페이스를
세우는지는 파일이 답하게 합니다.
