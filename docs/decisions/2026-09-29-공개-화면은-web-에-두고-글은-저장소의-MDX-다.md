# 공개 화면은 web 에 두고 글은 저장소의 MDX 다

## 정한 것

- 로그인하지 않아도 보이는 화면(첫 화면 · 블로그 · 문서 · 새 소식)은 **`apps/web` 안의 `(site)` 묶음**에 둔다.
  공개 앱을 따로 세우지 않는다.
- 글은 저장소에 둔다(`apps/web/src/content/<모음>/`). 제목 · 날짜 · 차례는 모음마다 `index.ts` 가 타입으로 갖고, 본문만
  MDX 다. 본문은 `bodies.ts` 가 정적으로 불러오고, 목록과 짝이 어긋나면 타입(`Record<슬러그, …>`)이 막는다. 파일과 목록이
  어긋나지 않는지는 `content.test.ts` 가 잰다. DB 와 편집 화면은 두지 않는다.
- 공개 경로는 미들웨어의 `PUBLIC_PATHS` 와 뿌리 `/` 하나다. `(site)` 에는 게이트가 없으므로 조직의 데이터를 읽는 화면을
  두지 않는다.
- 「MCP 도구」 문서는 MDX 가 아니라 코드의 도구 목록(`lib/mcp.ts` 의 `TOOLS`)에서 그린다.
- 화면은 tyohnn 의 preview 템플릿을 **그대로 옮겨 심는다.** 문서는 `block-docs`(사이드바 · 경로 표시 · 목차 기둥 · 제목 달린
  코드 블록 · 번호 단계 · 안내 상자 · 앞뒤 카드), 새 소식은 `block-changelog`(오른쪽 목차 사이드바 · 판의 머리 · 화면 조각 · 지난 소식),
  「MCP 도구」는 `block-api-reference`(받는 값의 표 · 부르는 예), 첫 화면은 `block-help-center` 의 짜임이다. 템플릿이 제 안에 둔
  스타일은 `(site)/site.css` 로 옮겼다. 그 템플릿은 CLI 로 받는 것이 아니라 preview 앱 안의 영어 화면이라 글은 우리 말로 다시 쓴다.
  - 2026-09-29 개정. 처음에는 짜임만 빌려 다시 그렸는데, 사용자가 「tyohnn 의 템플릿보다 별로」라고 했다. 템플릿을 나란히 띄워
    보니 빠진 것은 짜임이 아니라 템플릿이 가진 조각(목차 · 코드 블록의 머리 · 단계 · 안내 상자 · 경로 표시)이었다.

## 까닭

- 앱은 audience 로 나눈다. 공개 화면을 보는 사람은 web 을 쓰게 될 사람이고, 따로 세우면 로그인 · 디자인 · 배포가 두 벌이
  된다(사용자 결정: 「지금 site 가 아니고 web 이지 않아?」).
- 글은 PR 로 쓰고 리뷰하는 편이 이 규모에서 가장 싸다. 편집 화면은 운영팀이 코드 밖에서 글을 써야 할 때 세운다.
- 목록을 frontmatter 로 두면 목록을 만들려고 파일을 모두 열어야 하고, 잘못 적은 날짜가 화면에서야 드러난다.

## 실측

- `@next/mdx` 16.3.4 가 Turbopack 에서 그대로 돈다.
- 동적으로 불러오는(`() => import("./x.mdx")`) 본문 안의 클라이언트 컴포넌트는 개발 서버의 프리페치 검증이 찾지 못해
  「module factory is not available」로 깨진다. 그래서 본문을 정적으로 불러오게 바꿨고(`bodies.ts`), 이제 본문이 복사 단추 ·
  `Table` 같은 클라이언트 컴포넌트를 쓴다.
- 목차는 그려진 본문의 h2 · h3 에서 브라우저가 줍는다(`_components/Toc.tsx`). 앵커는 `H2` · `H3` 가 제목 글로 짓는다(`headingId`).
- 조판 CSS 는 레이어 밖에서 읽혀 유틸리티로 덮이지 않는다. 제목과 날짜도 `.typeset` 안에 두어야 본문과 왼쪽 선이 맞는다.
