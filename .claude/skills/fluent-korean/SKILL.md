# 한국어 산문 지침

세 층이다. 쓰는 자리에 따라 읽을 파일이 달라진다.

| 층 | 파일 | 무엇 |
|---|---|---|
| 문장 | `../../output-styles/fluent-korean.md` | 지침 원문. 문장과 구를 어떻게 맺는가 |
| 표현 | `references/expressions.md` | 이 저장소에서 실제로 지적받은 말 |
| 형식 | `references/official-docs.md` | 공식 문서의 골격과 문체 |

## 어느 자리에서 무엇을 읽는가

| 쓰는 것 | 읽을 것 |
|---|---|
| PR 본문·이슈·리뷰 코멘트 | 문장 + 표현 |
| `docs/**`·`CLAUDE.md` 계열 규약 문서 | 문장 + 표현 |
| 사용자에게 보고하는 답변 | 문장 + 표현 |
| 코드 주석 | 문장 + 표현. 문체는 평서체 그대로 두고 규칙만 적용한다 |
| 노션 페이지 | 세 층 전부 |
| 캔버스의 안내문 | 세 층 전부 |

**문장과 표현은 늘 함께 읽는다.** 원문은 사본이라 고칠 수 없어서 우리 조항이 `expressions.md` 에만
있고, 한쪽만 읽으면 규칙의 절반이 빠진 채로 쓰게 된다.

⚠ **원문 본문을 이 파일이나 다른 파일로 옮겨 적지 말 것.** 원문은 조항마다 교정 예시를 붙여 두었고
요약하면 그 예시가 사라져서 조항이 무엇을 의도했는지 알 수 없게 된다. 원문이 그 이유를 직접
밝히고 있다(§상황과 목표).

## 적용하지 않는 자리

| 적용한다 | 적용하지 않는다 |
|---|---|
| PR 제목·본문, 이슈 본문 | 변수명, 로그 문자열 |
| 리뷰 코멘트, PR 코멘트 | 커밋 메시지 |
| `docs/**` 문서 | 인용문 |
| `CLAUDE.md`·`.claude/*.md` 규약 문서 | 영어로 써야 하는 자리 |
| **코드 주석** | 제품 화면의 글(`ux-writing` 이 맡는다) |
| 사용자에게 보고하는 답변 | |
| 노션과 캔버스의 규격과 안내문 | |

⚠ **주석도 적용 대상이다.** 스캐폴드가 2026-09-16 에 정한 규약이고 2026-10-02 에 이 저장소로 옮겼다.
이 저장소의 주석은 왜 그렇게 정했는지와 무엇을 되돌리면 안 되는지를 담는 설계 문서라서 사람이
읽고, 읽기 어려우면 그 경고가 막으려던 사고가 그대로 일어난다. 원문은 주석을 제외하지만 §동작 범위
2번이 주석의 규칙을 프로젝트의 관례에 넘기므로, 이 저장소가 그 관례를 이렇게 정한 것이다.

⚠ **문체는 바꾸지 않는다.** 지침이 요구하는 것은 완결된 서술어와 종결어미이지 `합니다`체가 아니다.
주석은 평서체(`~한다` · `~이다`)로 쓰던 대로 쓰고, 엠대시와 명사형 종결과 생략된 조사만 고친다.
`pnpm check:comments` 가 그 셋을 기계로 대조하며, 적용 범위를 파일 목록으로
들고 다니므로 정리한 자리를 그 목록에 더해 가며 넓힌다.

커밋 메시지가 빠진 것은 두 규약이 어긋나서가 아니다. 원문 §동작 범위 2번이 "코드에 속하는 텍스트는
프로젝트의 기존 관례를 따르라"고 지시하고, 이 저장소의 관례는 루트 `CLAUDE.md` 가 정한 한국어
커밋 메시지다. 관례를 그대로 유지하면 된다.

제품 화면의 글(단추 · 라벨 · 설명 · 빈 화면 · 오류 · 알림)은 이 스킬이 아니라 **`ux-writing` 스킬**이 맡는다.
문체(해요체)도 기준(없어도 되는 말은 넣지 않는다)도 다르다. 두 스킬을 한 글에 섞지 않는다.

## 자주 어기는 조항

작업이 길어지면 아래 넷이 먼저 무너진다. 결과물을 내보내기 직전에 점검한다.

1. **엠대시(—)** 를 접속 관계 대신 쓰는 습관. 콜론이나 접속사로 바꾼다.
2. **명사구로 끝나는 문장.** 서술어와 종결어미로 문장을 맺는다.
3. **조사·어미 생략.** 토큰을 아끼려는 압력이 여기에 가장 강하게 작용한다.
4. **비유적 어휘로 일반 명사·동사를 대체하는 것.** "코드에 박는다", "치운다", "얹는다" 를 피한다.

## 출력 스타일로도 쓸 수 있다

두 파일은 이 플러그인의 `output-styles/` 에 있다. **플러그인을 켜면 출력 스타일로 등록되므로
프로젝트마다 링크를 만들지 않는다.** `/config` 의 output-style 항목에서 고르고, 새 세션을 시작하거나
`/clear` 를 해야 반영된다.

- `fluent-korean` — 코딩 지침을 유지한다. 코드를 고치는 작업에 쓴다.
- `fluent-korean-not-coding` — 코딩 지침이 빠져 있다. 문서만 쓰는 작업에 쓴다.

**같은 파일이 두 몫을 한다.** 출력 스타일로 등록되는 파일이 곧 이 스킬의 「문장」 층 원문이다. 사본을
따로 두면 한쪽만 고쳐진다.

⚠ **출력 스타일은 Claude Code 만의 개념이다.** Cursor 와 Codex 에는 해당하는 기능이 없으므로, 그
도구에서는 이 스킬을 읽는 것으로 대신한다.
