# 검색 · 탐색형(스토어)의 정보 구조

Notion 템플릿 스토어 · Figma Community · 플러그인 마켓 같은 제품이다. 관리형 SaaS 는 「내가 만든 것」을 관리하는 IA 이고,
스토어는 **「남이 만든 것」을 찾아서 내 것으로 가져오는 IA** 다. 그래서 SKILL.md 의 1 ~ 7번에 셋이 더 붙는다.

- 분류 체계(taxonomy)
- 공개 주소 설계(SEO)
- 스토어에서 앱으로 넘어가는 전환 경로

## 1. 사용자는 세 가지 모드로 들어온다

| 모드 | 언제 | 받는 그릇 |
|---|---|---|
| **검색** | 찾는 것이 분명하다 | 위의 검색 칸 · 자동 완성 · 검색 결과 화면 |
| **탐색** | 무엇을 원하는지 아직 모른다 | 큐레이션 선반 · 카테고리 · 컬렉션 |
| **가져오기** | 마음에 드는 것을 찾았다 | 상세의 「사용하기」 → 내 작업 공간 |

그래서 **스토어 홈 한 화면이 검색과 탐색을 함께 받는다.** 위에는 검색 칸, 아래에는 인기 · 새로 나온 것 · 고른 것 · 주제별 컬렉션
선반이다. Notion 과 Figma Community 의 홈이 대체로 이렇게 생겼다.

스토어의 핵심 루프(SKILL.md 1번)는 **찾기 → 미리 보기 → 사용하기 → 앱에서 바로 고치기**다. 클릭 예산은 「상세에서 사용하기를 누른 뒤
첫 편집까지」를 따로 잰다.

## 2. 분류 체계

- **1차 분류(카테고리)는 겹치지 않게, 2단계까지만 둔다.** 업무 > 프로젝트 관리처럼. 셋째 단계부터는 태그다.
- **나머지 기준은 여러 개 고르는 거름(facet)이다.** 유형(템플릿 · 플러그인 · UI 키트) · 가격 · 대상 직군 · 언어, 그리고 정렬.
- **거름 옆에 결과 수를 적는다.** 결과가 0개가 되는 조합은 끈다.
- **카테고리 이름은 검색 기록에서 짓는다.** 사용자가 실제로 넣는 낱말을 카드 소팅으로 묶어 이름을 붙이고, 우리끼리 쓰는 말은 쓰지 않는다.
  출시 전이라 기록이 없으면 경쟁 스토어의 카테고리 이름과 사용자 인터뷰의 낱말로 시작하고, 출시 뒤 검색 기록으로 다시 본다.
- 카테고리 · 거름의 값은 코드의 상수가 아니라 **데이터**로 둔다(운영팀이 늘리고 고친다). 그 표는 새 스키마의 비싼 쪽이다.

## 3. 경로로 둘지 쿼리로 둘지

판단 기준은 **「검색 엔진에 첫 화면으로 걸릴 값어치가 있는가」** 다.

| 무엇 | 어디 | 까닭 |
|---|---|---|
| 카테고리 · 하위 카테고리 · 컬렉션 · 상세 · 크리에이터 | **경로**. 숫자 id 대신 읽을 수 있는 slug, 서버에서 그린다 | 검색 엔진의 첫 화면이 된다 |
| 가격 · 정렬 · 유형 · 쪽 번호 | **쿼리**(`?price=free&sort=popular`) | 조합이 끝없이 늘어 색인할 값어치가 없다 |

- **거름을 바꿀 때는 주소를 `replace` 한다.** 뒤로 가기가 거름을 하나씩 되감지 않게 한다.
- **목록에서 상세를 열면 모달이다.** 뒤로 가기를 누르면 스크롤 자리와 거름이 그대로 남는다. 탐색형에서 가장 중요한 자리다.
  링크로 바로 오면 전체 페이지로 열어 SEO 와 공유를 챙긴다(가로챈 라우트, `nextjs.md`).
- **상세에는 접두사를 단다**(`/templates/t/[slug]`). 없으면 `[category]` 와 `[slug]` 가 같은 자리에서 부딪힌다.
- **정적 세그먼트가 동적 세그먼트를 이긴다.** `search` · `collections` · `t` 는 카테고리 slug 로 쓸 수 없다. 예약어 목록을
  카테고리를 만드는 판정에 넣는다.
- 카테고리 화면은 `?page=` 로 쪽을 나눠 색인되게 하고, 탐색 홈 · 검색 결과는 끝없는 스크롤을 쓴다.

```
app/
├─ (site)/                        공개 셸, 서버에서 그린다
│  └─ templates/
│     ├─ page.tsx                 탐색 홈: 검색 칸 + 큐레이션 선반
│     ├─ [category]/              카테고리 첫 화면 ?type=&price=&sort=&page=
│     │  └─ [sub]/                2단계까지만
│     ├─ t/[slug]/                상세(전체 페이지)
│     ├─ @modal/default.tsx       가로채지 않을 때는 아무것도 그리지 않는다
│     ├─ @modal/(.)t/[slug]/      목록에서 연 상세는 모달
│     ├─ search/                  ?q=&type=&price=&sort=
│     ├─ collections/[slug]/      큐레이션 컬렉션
│     └─ creators/[handle]/       프로필. 탭: 템플릿 · 컬렉션 · 소개
├─ (app)/
│  └─ library/                    가져온 것 · 산 것 · 저장한 것
└─ (판매자 앱 · 별도)              등록한 것 → 상세 → 탭(편집 · 미리 보기 · 분석) · 정산
```

## 4. 셸이 셋이 된다

- **공개 스토어 셸.** 로그인 여부에 따라 머리만 바뀐다. 로그인 전에는 로그인 단추, 로그인 뒤에는 얼굴과 「내 작업 공간」이다.
  **탐색은 로그인 없이 된다.** 이 저장소의 `(site)` 가 그 셸이고, 머리의 계정 단추(`AccountButton`)가 이미 그렇게 바뀐다.
- ⚠ 공개 셸에서는 조직의 데이터를 읽지 않는다(`apps/web/CLAUDE.md` 「공개 화면과 글」). 스토어의 목록은 공개된 것만 담은 별도의
  조회이고, 「내가 저장했는가」처럼 사람에 따라 달라지는 칸은 그 칸의 `<Suspense>` 안에서만 읽는다.
- **판매자 쪽은 따로다.** 등록한 것 목록 → 상세 → 탭(편집 · 분석)이라는 관리형 패턴 그대로다. 사는 사람과 인증 · 데이터 범위가
  통째로 다르면(정산 · 세금) 새 앱이다(루트 `CLAUDE.md` 「플랫폼 계층」).

## 5. 스토어에서 앱으로의 전환

- **「사용하기」를 누른 뒤에는 화면을 갈아타지 않는다.** 로그인하지 않았으면 로그인 다이얼로그, 작업 공간이 여럿이면 고르는 다이얼로그,
  복제가 끝나면 워크벤치(또는 그 객체의 상세)로 바로 간다.
- **같은 데이터에 들어오는 길이 둘이다.** 공개 스토어 화면 하나, 앱 안의 「새로 만들기」에서 뜨는 템플릿 고르기 다이얼로그 하나.
  Figma 와 Notion 모두 이 이중 구조다. 둘은 같은 조회를 부른다.
- **다시 오게 하는 장치.** 저장 · 내 컬렉션 · 크리에이터 팔로우 · 가져온 기록을 앱의 `library/` 로 모은다.
- 「사용하기」(복제)는 상태를 바꾸는 쓰기다. 원본이 공개였는가 · 산 것인가 · 이미 가져왔는가는 도메인 술어가 판정하고(비싼 쪽),
  화면은 그 답을 그린다.

## 6. 탐색형에서 더 생기는 그릇

| 무엇 | 그릇 |
|---|---|
| 거름 | 데스크톱은 왼쪽 패널, 모바일은 아래에서 올라오는 시트(`drawer`) |
| 검색 칸 | 글자마다 결과 화면으로 가지 않는다. 자동 완성 드롭다운에서 템플릿 · 크리에이터 · 카테고리로 묶어 보이고, 최근 검색어 · 인기 검색어를 함께 둔다. 엔터를 쳐야 `search/` 로 간다 |
| 결과 없음 | 비슷한 카테고리나 인기 템플릿을 대신 보인다. 빈 화면에서 떠나지 않게 하는 것이 목적이다 |
| 빠른 미리 보기 | 카드에 마우스를 올리면 미리 보기, 누르면 모달 상세 |
| 목록의 꼴 | 탐색 화면은 끝없는 스크롤, SEO 대상인 카테고리 화면은 `?page=` 쪽 나눔 |

## 7. 검증 지표가 는다

| 모드 | 지표 |
|---|---|
| 검색 | 검색 뒤 클릭률 · 결과 0건 비율 |
| 탐색 | 거름을 쓴 뒤 상세 진입률 |
| 전환 | 상세 → 사용하기 전환율 · 사용하기 → 첫 편집까지 걸린 시간 |

분석 모듈이 있으면 이 지표의 이벤트를 `packages/analytics` 의 카탈로그에 먼저 더한다. 검색어는 사람을 가리키는 값이 아니어도
그대로 보내지 않는다(개인 정보가 섞인다). 길이 · 결과 수 같은 성질만 보낸다.
