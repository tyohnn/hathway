# 예시

## 꼴마다 하나씩

### 관리형: 근무 관리(Flex 같은 제품)

- **루프.** 구성원: 출근 누르기(홈에서 1) · 휴가 신청(홈에서 2). 관리자: 승인 대기 처리(홈에서 1).
- **객체.** 구성원 · 근무 기록 · 휴가 신청 · 휴가 정책. 근무 기록과 휴가 신청은 구성원에 딸린다.
- **역할별 보기.** 같은 휴가 신청을 구성원은 「내 휴가」로, 관리자는 「승인할 것」으로 본다. 메뉴가 역할마다 다르다.

```
(app)/
├─ page.tsx                     홈: 구성원은 출근 단추와 남은 휴가, 관리자는 승인 대기
├─ me/                          내 근무 · 내 휴가(구성원)
│  └─ @modal/(.)leave/new/      휴가 신청 다이얼로그(칸 넷)
├─ approvals/                   승인할 것(관리자) ?type=leave|overtime
│  └─ ?selected=<id>            옆 시트로 훑고 바로 승인
└─ people/[id]/                 구성원 상세. 탭: 근무 · 휴가 · 인사 정보
```

### 생성형: 목소리 생성(ElevenLabs 같은 제품)

- **루프.** 글 넣기 → 목소리 고르기 → 만들기 → 듣기 · 받기. 홈에서 3.
- **객체.** 도구(TTS · 목소리 복제 · 효과음)는 독립적이라 메뉴가 도구별이다. 결과물(생성물)과 목소리가 객체다.

```
(app)/
├─ page.tsx                     홈: 최근 생성물 + 도구 셋의 진입점
├─ speech/                      TTS 도구(워크벤치처럼 판 전체: 왼쪽 글, 오른쪽 설정)
├─ voices/                      목소리 목록 · voices/[id] 상세. 목소리 고르기는 도구 안의 시트
├─ sound-effects/
└─ history/                     모든 생성물. ?tool=&voice= · 줄을 누르면 시트로 듣기
```

### 생성형 + 워크벤치: 프롬프트로 앱 만들기(v0 · Lovable 같은 제품)

- **루프.** 프롬프트 → 만들기 → 미리 보기 → 고치기 되풀이. 홈에서 1(홈이 곧 프롬프트 칸).
- 상세(프로젝트)에 들어가는 순간 **워크벤치 셸**로 바뀐다. 왼쪽 대화, 오른쪽 미리 보기, 탭 대신 패널.

```
(app)/page.tsx                  홈: 큰 프롬프트 칸 + 최근 프로젝트
(app)/projects/                 목록
(workbench)/p/[id]/             대화 + 미리 보기. ?panel=code|preview · 공유 주소 /share/[token]
```

### 탐색형: 유튜브 분석(Viewtrap · Viewstats 같은 제품)

- **루프.** 검색 → 채널 · 영상 목록 → 상세 분석 → 저장. 홈에서 2.
- **다시 오게 하는 장치.** 저장한 채널 · 컬렉션 · 알림(구독한 채널이 떴을 때).

```
(app)/
├─ page.tsx                     홈: 검색 칸 + 저장한 채널의 새 소식
├─ search/                      ?q=&type=channel|video&sort=
├─ channels/[id]/               탭: 개요 · 영상 · 성장 · 비슷한 채널
├─ videos/[id]/                 영상 분석
└─ saved/                       저장한 것 · 컬렉션
```

## 클리닉북을 이 방법으로 다시 그리면

2026-10-05 의 `/scaffold-fit` 시운전은 템플릿 화면을 재료로 지도를 그렸다(오늘 예약 · 진료 일정 · 환자 찾기 · 예약 상세 · 예약 통계).
같은 제품을 이 스킬의 차례로 다시 그리면 다음이 달라진다.

**루프.**

| 역할 | 루프 | 예산 |
|---|---|---|
| 접수 직원 | 전화를 받는다 → 환자를 찾는다 → 예약을 잡는다 | 홈에서 3 |
| 원장 | 오늘 진료를 본다 → 예약을 연다 → 진료 기록을 쓴다 | 홈에서 2 |

**객체.** 환자(독립, 공유된다) · 예약(환자에 딸리지만 날마다 혼자 다룬다) · 진료 기록(예약에 딸린다, 부모 없이 뜻이 없다) · 의사.

**지도가 달라지는 자리.**

| 시운전의 지도 | 이 방법으로 | 까닭 |
|---|---|---|
| 환자 찾기가 메뉴 하나(`/patients`) | 메뉴는 두고, **⌘K 팔레트가 환자를 찾는다** | 접수의 루프는 전화를 받는 중에 시작한다. 메뉴 → 검색 칸보다 키 하나가 짧다 |
| 예약 상세가 페이지(`/appointments/[id]`) | 오늘 예약에서 누르면 **시트**(가로챈 라우트), 주소로 오면 페이지 | 접수는 목록을 떠나지 않고 훑는다. 원장은 링크로 바로 연다 |
| 예약 잡기를 미룸 | **다이얼로그**(`@modal/(.)new`, 칸 넷: 환자 · 의사 · 시각 · 진료) | 칸이 다섯 안팎이다 |
| 진료 기록이 예약 상세의 한 칸 | 예약 시트 · 페이지 안의 칸 그대로, 환자 상세에서는 **탭**(`/patients/[id]/records`) | 부모 없이 뜻이 없는 종속 객체다 |
| 예약 통계가 메뉴 하나 | 원장의 메뉴에만. 지금 셸은 역할로 거르지 못하므로 지도에 「셸 늘리기(비싸다)」를 적는다 | 역할별 보기 |
| 사이드바에 「쪽지」가 남음 | 예시 도메인을 걷거나 숨기는 일을 지도의 「걷는 것」에 올린다 | 메뉴가 객체가 아닌 것을 들고 있다 |
| 템플릿 화면은 사이드바를 접고 상세는 펴서 판이 바뀜 | 한 셸 안에서는 판을 바꾸지 않는다. 판 전체가 필요한 것(진료 일정)만 `ScreenFrame` | 셸이 바뀌는 자리는 사람이 다른 일로 들어간다는 신호다. 같은 일 안에서 바뀌면 길을 잃는다 |

**검증.** 「핵심 루프: 접수는 홈에서 세 번 눌러 예약을 잡는다」 · 「핵심 루프: 원장은 홈에서 두 번 눌러 진료 기록 칸에 닿는다」 두 e2e 와,
트리 테스트 질문 다섯(「지난주에 노쇼한 환자는 어디서 보나요?」 등).
