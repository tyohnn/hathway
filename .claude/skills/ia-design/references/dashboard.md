# SaaS 대시보드의 정보 구조

Linear · Flex · Notion 의 워크스페이스 · ElevenLabs · Figma 의 파일 목록 같은 제품이다. 스토어가 「남이 만든 것을 찾아 가져오는」 IA 라면
대시보드는 **「내가(우리가) 만든 것을 날마다 다시 열어 일을 이어 가는」 IA** 다. SKILL.md 의 1 ~ 7번에 더해 여기서는 화면마다의
해부도를 정한다. 셸 · 홈 · 목록 · 상세 · 만들기 · 설정 · 역할 · 알림이다.

## 1. 사용자는 네 가지 모드로 들어온다

| 모드 | 얼마나 자주 | 묻는 것 | 받는 자리 |
|---|---|---|---|
| **이어 하기** | 날마다 여러 번 | 「어제 하던 거 어디 있지?」 | 홈의 최근 항목 · 사이드바의 고정 항목 |
| **처리하기** | 날마다 | 「나한테 온 게 뭐지?」 | 받은 것(Inbox) · 승인 대기 · 내게 맡겨진 것 |
| **만들기** | 날마다 | 「새로 하나 시작하자」 | 어디서든 닿는 만들기 단추 · ⌘K · 홈의 루프 진입점 |
| **관리하기** | 가끔 | 「사람을 초대하고 요금제를 바꾸자」 | 설정 하나 |

- 앞의 셋이 핵심 루프의 입구다. **홈은 이 셋을 한 화면에서 받는다.** 관리하기는 홈에 두지 않는다.
- 관리하기가 날마다 일어나면 IA 가 틀렸다는 신호다. 설정에 있어야 할 것이 아니라 객체의 동작이었던 것이다.

## 2. 셸의 해부

사이드바는 **「어디로 가나」**, 화면의 머리는 **「여기서 무엇을 하나」** 를 맡는다. 둘을 섞지 않는다.

```
┌─ 사이드바 ─────────────┐┌─ 위 띠: 위치(빵 부스러기) · 이 화면의 주 동작 ───────────┐
│ 조직 이름 ▾            ││                                                          │
│ 찾기 ⌘K     + 만들기   ││  화면                                                     │
│────────────────────────││                                                          │
│ 홈                     ││                                                          │
│ 받은 것  3             ││                                                          │
│ 내 일                  ││                                                          │
│────────────────────────││                                                          │
│ 프로젝트               ││   ← 객체 메뉴 다섯에서 일곱                               │
│ 고객                   ││                                                          │
│ 문서                   ││                                                          │
│────────────────────────││                                                          │
│ 고정한 것              ││   ← 사람이 고른 것. 사람마다 다르다                       │
│────────────────────────││                                                          │
│ 설정 · 도움말 · 계정   ││   ← 맨 아래. 가끔 가는 곳                                 │
└────────────────────────┘└──────────────────────────────────────────────────────────┘
```

- **맨 위:** 조직(작업 공간) 이름과 전환, 찾기(⌘K), 전역 만들기. 어느 화면에서든 같은 자리다.
- **개인 묶음:** 홈 · 받은 것 · 내 일. 「나」를 기준으로 거른 관점이고 객체가 아니다. 셋을 넘기지 않는다.
- **객체 묶음:** SKILL.md 2번의 객체가 서는 자리다. 다섯에서 일곱. 숫자 배지는 처리할 것이 있는 메뉴 하나에만 단다. 모든 메뉴에 숫자가 붙으면 아무것도 읽히지 않는다.
- **고정 묶음:** 사람이 즐겨찾기한 객체(프로젝트 하나 · 저장한 보기). 이어 하기의 가장 짧은 길이다. 비어 있으면 묶음째 숨긴다.
- **맨 아래:** 설정 · 도움말 · 계정. 설정은 **한 줄**이다. 팀 · 내 계정 · 요금제를 사이드바에 따로 세우지 않는다(7번).
- **이 저장소의 셸은 이 해부도대로 서 있다**(2026-10-06). 블록 `app-shell` 이 도구 줄(`tools`)과 발치 메뉴(`footerGroups`)를 받고,
  앱(`apps/web/src/app/(app)/_components/`)이 찾기 ⌘K · 만들기 · 「설정」 · 「제품 문서」를 넘긴다. 메뉴의 자리는 `NavEntry.place` 가 정한다
  (`personal` · `objects` · `settings`). 개인 묶음에는 홈 한 줄이 서 있다(받은 것 · 내 일이 서면 `place: "personal"` 로 더한다).
  고정 묶음과 숫자 배지는 아직 없다. 지도가 그것을 쓰면 셸을 늘리는 일이 지도에 들어간다.

## 3. 홈의 해부

```
┌ 루프 진입점 ───────────────────────────────────────────┐  ← 맨 위. 생성형이면 큰 입력 칸 하나
│ + 새 프로젝트         또는   [ 무엇을 만들까요?      ] │
└────────────────────────────────────────────────────────┘
┌ 처리할 것 (3) ──────────────┐ ┌ 최근에 연 것 ──────────────┐
│ 승인 대기 · 나를 언급함 …   │ │ 프로젝트 A · 어제          │
└─────────────────────────────┘ └────────────────────────────┘
```

- 위에서부터 **루프 진입점 → 처리할 것 → 최근에 연 것**이다. 환영 문구 · 기능 소개 · 꾸미는 지표 카드를 두지 않는다.
- 지표가 일인 제품(분석 · 모니터링)만 홈에 차트를 둔다. 그 밖의 제품에서 차트는 객체의 관점(상세의 탭, 목록의 보기)이다.
- **첫날의 홈은 다르다.** 최근이 비어 있으므로 그 자리에 시작 점검표(초대하기 · 첫 객체 만들기 · 연결하기)를 세우고, 다 하면 사라진다.
- 역할마다 루프가 다르면 홈도 역할마다 다르다(구성원은 출근 단추, 관리자는 승인 대기). 한 주소에서 역할로 갈라 그린다.
- **이 저장소의 홈은 이 해부도대로 서 있다**(2026-10-06, `apps/web/src/app/(app)/home/`). 로그인하면 여기로 온다. 무엇이 어느 칸에 서는지는
  순수 함수 `usecases/home.ts` 의 `planHome` 이 정하고 `home.test.ts` 가 잰다. 처리할 것은 초대받고 아직 로그인하지 않은 사람 하나이고 팀을 관리하는
  사람에게만 선다. 역할로 갈라 그리는 본보기다. 최근은 「연 것」이 아니라 새로 쓴 쪽지 순이다. 연 기록을 남기는 표가 없어서다. 제품이 그
  기록을 두면 그 순서로 바꾼다. 첫날의 점검표는 첫 쪽지 쓰기 · 멤버 초대하기(관리하는 사람만) · Claude에 연결하기(앱이 알 수 없어 「선택」)다.

### 갤러리 홈

사람의 일이 **카탈로그에서 하나를 골라 시작하는** 제품(템플릿 · 서식 · 에셋 · 공고)은 홈을 갤러리로 세운다(Figma Community · v0 의 템플릿 홈).
루프 진입점이 「만들기」가 아니라 「고르기」이기 때문이다.

```
둘러보기                                       [처리할 것 2] [+ 새로 만들기]
새로 나온 것                                                      모두 보기 ›
┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐
│그림 │ │그림 │ │그림 │ │그림 │   ← 묶음마다 그림 카드 한 줄(넓은 화면 넷 · 좁은 화면 둘)
└─────┘ └─────┘ └─────┘ └─────┘
제목 두 줄 · 보조 한 줄
많이 쓰는 것                                                      모두 보기 ›
…
종류별로 보기   [문서 ▤▤▤] [보드 ▤▤▤] [양식 ▤▤▤]     ← 종류 타일. 맨 아래라 늦게 와도 위를 밀지 않는다
```

- 묶음마다 제목과 「모두 보기」 가 서고, 「모두 보기」 는 그 묶음 전체를 연다(주소 값, 예 `?list=popular`).
- 카드는 그림 · 제목 · 보조 한 줄이 전부이고 **카드 전체가 링크 하나**다. 제목 칸은 늘 두 줄 높이라 카드 높이가 같다.
- 처리할 것은 사라지지 않고 **머리의 알약**으로 올라간다. 처리할 것이 없는 날은 알약도 없다.
- 첫날에 고를 것이 없으면 그 자리에 시작 점검표를 세운다(위와 같다).
- 이 저장소의 본보기는 `/explore`(대시보드 모듈, 블록 `GallerySection`)다. 홈으로 쓸 때는 `/home` 의 본문을 그 화면의 본문으로 바꾼다.
  먼저 쓴 제품은 hwp-pilot 의 홈이다(공고 · 서식 묶음, 2026-10-17).

## 4. 목록 화면의 해부

```
머리       프로젝트  24                                         [+ 새 프로젝트]
보기 탭    전체 · 내 것 · 최근 · 보관                           (저장한 보기는 여기에 는다)
거름 띠    [찾기    ]  [상태 ▾] [담당 ▾]  정렬 ▾                  [표 | 보드 | 달력]
몸         표의 줄 · 마우스를 올리면 줄 끝에 동작 · 고르면 아래에 일괄 동작 띠
발치       24개 중 1–20 · 이전 · 다음
```

- **보기 탭**은 미리 정한 거름이다(`?view=mine`). 사람이 거름을 저장하면 탭이 하나 는다(Linear 의 보기). 저장한 보기는 객체라서 고정할 수 있다.
- **거름 띠**에서 자주 쓰는 거름 둘셋만 칩으로 내놓고 나머지는 「거름 더하기」 뒤에 둔다. 거름이 걸려 있으면 「조건 지우기」가 선다.
- **보기 전환**(표 · 보드 · 달력)은 같은 사람의 같은 일이다. 메뉴를 늘리지 않는다.
- **줄을 누르면** 상세로 가거나(오래 머문다) 시트로 훑는다(목록으로 돌아올 일이 많다). 둘 다면 시트에 「전체 화면으로」를 둔다.
- **빈 상태는 셋이다.** 섞지 않는다.

  | 경우 | 보이는 것 |
  |---|---|
  | 아직 하나도 없다 | 무엇을 담는 자리인지 한 줄 + 만들기 단추 + 템플릿 · 본보기 |
  | 거름에 맞는 것이 없다 | 「조건에 맞는 것이 없어요」 + 조건 지우기 |
  | 볼 수 있는 것이 없다 | 첫째와 같게 보인다. 남의 행이 있다는 사실을 드러내지 않는다(부재) |

- 재료: tyohnn 블록 `data-table-card`(보기 탭의 건수 · 도구줄의 거름 · 일괄 동작 띠까지 한 벌), `filter-bar`, 블록 층 `item-list` · `action-bar` · `empty-state`.
- **이 저장소에서는 둘로 나눠 본보기를 둔다**(2026-10-06). 목록의 겉(지표 · 보기 탭 · 거름 칩 · 쪽 넘기기의 모양)은 본보기 데이터로 도는 `/orders` 이고,
  실제 데이터 위의 배관(질의에서 자르는 쪽 넘기기와 찾기 · 주소에 남는 상태 · 빈 상태 셋 · 만들기 다이얼로그)은 `/notes` 다. 새 명사의 목록은 겉을
  `/orders` 에서, 배관을 `/notes` 에서 가져온다. 배관을 짜는 법은 `nextjs.md` 「거름 · 정렬 · 검색어」 · 「가로챈 라우트」에 있다.

## 5. 상세 화면의 해부

```
빵 부스러기   프로젝트 › 봄 개편
머리          봄 개편  [진행 중]                           [주 동작 하나] [⋯]
탭            개요 · 작업 · 활동 · 설정
몸            본문(왼쪽)                         │ 속성 기둥(오른쪽): 담당 · 기한 · 라벨
              활동과 댓글(본문 아래)             │ 누르면 그 자리에서 고친다
```

- **주 동작은 하나**만 단추로 세운다. 나머지는 `⋯` 메뉴다. 지우기는 메뉴의 맨 아래이고 알림 다이얼로그를 거친다.
- **탭의 차례:** 개요가 처음, 설정이 마지막. 탭은 다섯을 넘기지 않는다. 넘치면 그 객체가 둘로 갈라져야 한다는 신호다.
- **속성 기둥**은 목록에서 거르던 속성과 같은 이름 · 같은 차례다. 속성 하나를 고치는 일은 팝오버 · 제자리 편집이다(SKILL.md 3번).
- **활동**(누가 언제 무엇을 바꿨나)은 협업 제품의 신뢰다. 개요의 아래나 탭에 둔다.
- 시트로 연 상세는 위아래 키(j · k)로 앞뒤 항목을 넘긴다. 목록을 훑는 일이 시트 안에서 끝난다.
- 재료: tyohnn 블록 `record-heading` · `detail-heading` · `page-tabs` · `detail-sections` · `activity-feed`, 블록 층 `property-list`.
- **이 저장소의 본보기는 쪽지 상세다**(2026-10-06, `apps/web/src/app/(app)/notes/[noteId]/`). `detail-heading` 의 제목 옆에 상태, ⋯ 메뉴(`NoteMenu`)에
  링크 복사하기와 맨 아래 묶음의 보관하기(확인 창), 오른쪽 기둥에 `property-list` 로 공개 범위 · 쓴 사람 · 쓴 날이다. 주 동작 단추는 없다. 요약은 본문의
  기능이라 본문 아래에 둔다. 탭과 활동은 없다. 나눌 내용도, 바뀐 기록을 쌓는 표도 없어서다. 협업 객체라면 기록 표(스키마)가 먼저 서고 활동이 따른다.

## 6. 만들기의 세 층

| 크기 | 그릇 | 만든 뒤 |
|---|---|---|
| 이름 하나 | 목록 맨 위 한 줄 입력(빠르게 더하기) | 목록에 그대로 선다 |
| 칸 다섯 안팎 | 다이얼로그(가로챈 라우트) | 상세로 가거나, 목록에 남고 알림에 「열기」 링크 |
| 길거나 단계가 있다 | 전용 페이지 · 단계 화면, 쓰는 동안 저절로 저장 | 상세로 간다 |

- **전역 만들기**(사이드바 맨 위 · ⌘K)는 「무엇을 만들까요?」로 객체를 고르게 하고 그 객체의 만들기 그릇을 연다.
- **템플릿으로 시작하기**는 만들기 다이얼로그의 첫 화면이다. 템플릿을 고르는 다이얼로그는 공개 스토어와 같은 조회를 부른다(`store.md` 5번).

## 7. 설정의 정보 구조

설정은 사이드바의 **한 줄**이고, 들어가면 제 옆 메뉴를 가진 화면이다.

```
settings/
├─ account/        개인: 이름 · 얼굴 · 알림 받는 법 · 테마
├─ team/           조직: 멤버 · 역할 · 초대
├─ integrations/   조직: 연동(Claude · 슬랙 …)
├─ security/       조직: 로그인 방식 · 감사 기록
└─ billing/        결제: 요금제 · 청구서 · 크레딧
```

- **개인 → 조직 → 결제** 차례로 묶는다. 조직과 결제 묶음은 그 권한이 있는 사람에게만 선다(판정은 도메인 술어).
- **객체 하나의 설정은 그 객체의 설정 탭이다.** 전역 설정에 「프로젝트 A 의 설정」을 두지 않는다.
- 되돌릴 수 없는 일(조직 지우기 · 소유권 넘기기)은 그 화면의 맨 아래 「위험한 일」 칸에 모으고 알림 다이얼로그를 거친다.
- 이 저장소는 이 규칙대로 서 있다. 사이드바 발치의 「설정」 한 줄로 들어가면 `settings/layout.tsx` 의 옆 메뉴가 개인 · 조직 · 결제 갈래로
  선다. 설정 화면을 더할 때는 메뉴 줄에 `place: "settings"` 와 `settingsGroup` 을 단다. 모듈의 설정 화면(요금제 · 알림)도 같다.
- 재료: 블록 층 `settings-list`, tyohnn 블록 `settings-section` · `section-card`.

## 8. 역할과 권한이 IA 에 드러나는 법

| 상황 | 화면 |
|---|---|
| 볼 수 없는 행 | **부재.** 목록에서 빠지고 상세는 404. 거부라고 말하지 않는다 |
| 볼 수는 있지만 할 수 없는 동작 | 숨긴다. 이 역할이 할 일이 아니면 단추가 없다 |
| 요금제 때문에 막힌 동작 | 끈 채로 보이고 까닭과 올리는 길을 단다(`PlanLimits`). 숨기면 살 까닭을 모른다 |
| 역할마다 다른 일 | 메뉴 · 홈이 역할마다 다르다. 판정은 도메인 술어에 두고 셸은 그 답을 그린다 |

- 같은 객체를 역할마다 다르게 보는 것(「내 휴가」 · 「승인할 휴가」)은 두 메뉴다. 일이 다르기 때문이다(SKILL.md 3번).

## 9. 알림과 받은 것

- 알림은 **객체 상세로 가는 링크**다. 알림 화면 안에서 일을 끝내게 하지 않는다(승인처럼 한 번 누르면 끝나는 일만 예외).
- **받은 것(Inbox)** 은 「나에게 온 일」의 목록이다. 읽음 · 끝냄 · 미루기가 있고, 비우는 것이 목표다. 알림 종 아이콘과 받은 것을 둘 다 두지 않는다. 하나다.
- 알림을 받는 법(메일 · 앱 · 슬랙)은 설정의 개인 묶음이다.

## 10. 생성형과 워크벤치

**생성형(ElevenLabs 같은 제품).**

- 사이드바는 객체가 아니라 **도구**로 짓고, 결과물을 모으는 **기록(History · Library)** 을 하나 둔다. 결과물이 객체가 되는 자리다.
- 홈은 입력 칸이 주인공이다. 홈에서 바로 만들 수 있으면 클릭 예산이 1 이 된다.
- 결과물의 상세에는 **만들 때의 설정**(목소리 · 모델 · 글)을 남기고, 「이 설정으로 다시 만들기」가 그 도구를 그 값으로 연다(`?from=<id>`).
- 프리셋 · 목소리처럼 다시 쓰는 재료는 객체다. 목록 · 상세를 갖고, 도구 안에서는 고르는 시트로 열린다.

**워크벤치(Figma · v0 · Lovable).**

- 상세로 들어가는 순간 **셸이 바뀐다.** 사이드바 대신 위 띠 하나: 대시보드로 돌아가기 · 이름 · 공유 · 판(버전) · 계정.
- 판을 패널로 나눈다. 왼쪽 도구 · 대화, 가운데 캔버스 · 미리 보기, 오른쪽 살피기(inspector). 탭 대신 패널이고, 열린 패널은 주소에 담는다(`?panel=code`).
- **저절로 저장하고 판을 남긴다.** 저장 단추를 두지 않는다. 판 기록이 되돌리기의 길이다.
- **공유 주소는 보기 전용 화면**으로 열린다. 로그인하지 않은 사람에게 무엇을 보일지(캔버스만 · 대화까지) 정한다. 그 화면이 새 사용자가 들어오는 문이다.

## 11. 라우트 나무

```
app/
├─ (site)/                         공개 셸
├─ (app)/                          대시보드 셸
│  ├─ page.tsx                     홈: 루프 진입점 · 처리할 것 · 최근
│  ├─ inbox/                       받은 것
│  ├─ projects/
│  │  ├─ page.tsx                  목록 ?view=&q=&status=&sort=&layout=board
│  │  ├─ @modal/default.tsx
│  │  ├─ @modal/(.)new/            만들기 다이얼로그
│  │  ├─ new/                      만들기(주소로 바로)
│  │  └─ [id]/                     상세: layout(머리 · 탭) · page(개요) · activity/ · settings/
│  └─ settings/                    한 줄 메뉴, 안에 옆 메뉴: account · team · integrations · billing
├─ (workbench)/p/[id]/             편집기: 위 띠 하나, 패널
└─ share/[token]/                  공유한 결과물의 보기 전용 화면(로그인 없음)
```

## 12. 검증 지표가 는다

| 지표 | 무엇을 보나 |
|---|---|
| 활성화 | 가입한 날 핵심 루프를 한 바퀴 끝낸 사람의 비율 |
| 첫 가치까지 걸린 시간 | 가입에서 첫 루프의 끝까지 |
| 다시 오기 | 주 단위로 다시 연 사람(WAU/MAU) · 이어 하기 입구(최근 · 고정)로 들어온 비율 |
| 길 찾기 | 메뉴로 간 비율과 ⌘K 로 간 비율. ⌘K 만 늘면 메뉴가 길을 못 알려 준다 |
| 설정 방문 | 설정에 자주 오면 객체의 동작이어야 할 것이 설정에 숨어 있다 |

분석 모듈이 있으면 이 이벤트를 `packages/analytics` 의 카탈로그에 먼저 더한다.
