# ChatGPT 플러그인의 유저플로우와 화면 짓는 법

2026-10-18 · 오픽뉴런과 한글파일럿을 붙이며 배운 것을 모았다. 9절의 넷은 사용자가 정했다.
근거 문서는 맨 끝 「출처」에 있고, `/mnt/project-files/…` 경로는 Pax Humana 프로젝트 안에서만 열린다.
이 파일이 정본이다. 다듬을 때는 이 파일을 고치고 scaffold 에 PR 을 낸다. ⚠ 표시는 실물 ChatGPT 에서 아직 확인하지 않은 것이다.

## 0. 한 줄로

**대화가 제품이고, 화면은 대화의 다음 한 걸음을 돕는 부품이다.**
웹 앱을 ChatGPT 안에 옮겨 심는 것이 아니다. 사람이 말로 시작한 일을 모델이 도구로 받고, 화면은 그 일이
말보다 빨라지는 순간에만 선다. 그리고 화면의 단추는 언제나 대화로 돌아간다.

---

## 1. 등장인물은 셋이다

웹 앱에는 사람과 화면 둘뿐이다. 플러그인에는 **모델**이 하나 더 있고, 대부분의 일은 모델이 한다.

| 누구 | 할 수 있는 것 | 할 수 없는 것 |
|---|---|---|
| **사람** | 말하기, 파일 붙이기, `@` 멘션, 사이드바 열기, 화면의 단추 누르기 | 모델이 어떤 도구를 부를지 고르기 |
| **모델** | 도구 부르기, 말로 답하기, 스킬 읽기 | 화면을 직접 그리기. 화면은 도구에 묶여 있다 |
| **화면(위젯)** | 도구 결과를 그리기, 대화에 말 보내기(`ui/message`), 맥락 붙이기(`ui/update-model-context`), 크기 바꾸기, 옆 탭 열기(`openai/files/open`), 화면 전용 도구 부르기 | 모델 몰래 대화를 바꾸기. 우리 API 를 로그인 토큰으로 직접 부르기(토큰은 ChatGPT 가 쥔다) |

흐름을 그릴 때는 걸음마다 **누가 움직이는지**를 적는다. 화면이 모델의 일을 대신하거나, 모델이 화면의 일을
말로 늘어놓으면 흐름이 무거워진다.

## 2. 쓸 수 있는 자리

| 자리 | 무엇 | 언제 쓰나 | 규칙 | 우리 예 |
|---|---|---|---|---|
| **글** | 모델의 말 | 설명 · 사실 하나 · 고를 것이 없는 답 | 화면이 더하는 게 없으면 글로 끝낸다 | 「묘사 문제인데 경험처럼 답해도 돼?」 |
| **인라인 카드** | 대화 안 작은 화면 | 결정 하나, 작은 구조 데이터, 다음 한 걸음 | 단추 **둘까지**(주 하나 · 보조 하나). 파고들기 · 탭 · 여러 화면 · 안쪽 스크롤 금지. 입력창을 흉내 내지 않는다 | 오픽 채점 카드, 한글 파일 여는 작은 카드(hwp-pilot#38) |
| **캐러셀** | 대화 안 가로 줄 | 비슷한 것 3~8개에서 하나 고르기 | 항목마다 그림 · 제목 · 두세 줄, 단추 하나 | 오픽 약한 유형 셋 |
| **크게 보기** | 전체 화면 | 카드에 안 들어가는 것(보고서 · 긴 목록 · 편집) | 위에 입력창이 남아 말로 계속 시킬 수 있다. 카드에서 넓혀 들어간다 | 오픽 모의고사 보고서 |
| **PiP** | 떠 있는 작은 화면 | 진행 중인 세션(퀴즈 · 학습 · 긴 작업) | UI 지침에는 있지만 확장 명세는 「ChatGPT supports inline and fullscreen, but not pip」라고 적는다(2026-10-18 다시 확인). 호스트가 `availableDisplayModes` 에 `pip` 을 줄 때만 청하고, 아니면 카드 + 맥락으로 선다 | (오픽 문항 카드가 기다리는 자리) |
| **사이드바 앱** (`global`) | 왼쪽 사이드바에서 여는 전체 화면 | 대화 없이 둘러보는 곳: 홈, 서고, 갤러리 | 그 안에서 목록 · 상세를 끝낸다. 웹으로 내보내지 않는다. 카드마다 「대화에 추가」 | 한글파일럿 홈(#37 · #40), 오픽 공략집 |
| **스레드 패널** (`thread`) | 대화 옆 탭 | 지금 대화로 끌어올 것이 있는 서랍 | 고르면 이 대화의 맥락에 들어간다 | 한글파일럿 팀 한글 파일, 오픽 표현 서랍 |
| **파일 탭** (`file`, 확장자) | 대화 옆 문서 탭 | 사람의 파일을 열고 고치기 | 데스크톱에서 「항상 이 앱으로 열기」가 도구 이름에 묶인다. 위젯만 탭을 연다 | 한글파일럿 `open_hwp` 편집기 |
| **폼** | 도구가 되묻는 구조화 입력 | 모델이 꼭 받아야 하는 값이 여럿일 때 | ⚠ 옛 연결에서는 안 뜬다. 글로 묻는 길을 같이 둔다 | 오픽 서베이 주제 고르기 |
| **설정** | 플러그인 상세의 설정 | 오래 가는 선호 | 같은 값을 카드 · 사이드바에 보일 때 한 곳이 정본이다 | 오픽 목표 등급 · 시험일 |
| **멘션** | 입력창 `@` 검색 | 말하는 중에 우리 것을 집어 붙이기 | ⚠ 데스크톱만 | 오픽 유형 · 표현, 한글파일럿 한글 파일 |

자리를 고르는 질문은 이 차례다. 위에서 걸리면 거기서 멈춘다.

1. 고를 것도, 볼 구조도 없나? → **글**
2. 지금 이 대화에서 한 번 결정하나, 단추 둘이면 되나? → **인라인 카드**
3. 비슷한 것 여럿에서 하나 고르나? → **캐러셀**
4. 카드에 안 들어가나(보고서, 편집, 긴 목록)? → 카드에서 **크게 보기**로 넓힌다. 사람의 파일이면 **파일 탭**
5. 여러 턴에 걸친 세션인가? → 매 턴 같은 모양의 **카드** + **맥락**. PiP 는 열리면 옮긴다
6. 대화 밖에서 둘러보는 곳인가? → **사이드바**
7. 지금 대화로 끌어올 것들의 서랍인가? → **스레드 패널**
8. 모델이 값을 여럿 받아야 하나? → **폼**(글로 묻는 길과 함께)
9. 다음 대화에도 남을 선호인가? → **설정**

## 3. 기술 제약이 곧 디자인 규칙이다

아래는 취향이 아니라 플랫폼의 사실이다. 흐름을 그리기 전에 먼저 건다.

- **화면은 도구마다 고정이다.** 호출마다 다른 화면을 낼 수 없다. 그래서 「이 순간 이 화면」은 도구를 나눠서 만든다.
  같은 화면을 여러 도구가 함께 쓸 수는 있다(`open_home` · `open_team_forms` 가 같은 홈 화면).
- **화면이 없는 도구도 있다.** `fill_form` · `read_form` · `edit_form` 은 화면이 없다. 이런 도구는 옆 탭을 열 수 없다.
  탭은 위젯만 연다(`openai/files/open`).
- **데이터는 도구 결과로만 온다.** 화면이 우리 API 를 직접 부르지 않는다. 화면이 더 필요하면 **화면 전용 도구**
  (`visibility: ["app"]`, 예: `browse_gallery`)를 부른다. 모델은 그 도구를 보지 못한다.
- **도구 이름은 한번 내보내면 영구다.** 데스크톱은 파일 열기 선택을 `<앱 id>.<도구 이름>` 으로 저장한다.
  `open_form` → `open_hwp` 로 바꾼 뒤 「…을(를) 표시하지 못했습니다」가 떴다. 이름은 처음에 사람 말로 짓는다.
- **음성 모드에서는 화면이 안 뜨는 것으로 보인다.** ⚠ 공식 답 없음. 음성 흐름은 스킬의 말만으로도 끝나야 한다.
- **웹과 데스크톱이 다르다.** 멘션 · 파일 탭은 데스크톱, 첨부(`openai/fileParams`)는 웹에서도 된다. 데스크톱은 위젯을
  `app:` 안 `codex-sandbox:` 로 겹쳐 CSP 가 두 스킴을 허락해야 한다. 흐름마다 어느 클라이언트에서 되는지 적는다.
- **iframe 안 캔버스는 화면 읽기 도구에 안 보인다.** 편집기 확인은 사진이나 로컬 미리보기로 한다. 로컬 미리보기는
  실물을 대신하지 못한다.

## 4. 글 답을 흐름으로 바꾸는 법

### 4-1. 흐름은 사람의 말로 시작해서 모은다

화면 목록부터 그리지 않는다. 사람이 대화창에 칠 말, 누를 곳, 붙일 파일을 먼저 모은다. 오픽은 52개를 모았다
(`/mnt/project-files/플러그인-사용-흐름-50.md`). 갈래는 「처음 설정 · 찾아보기 · 핵심 루프 · 결과 · 기록」 꼴이 두 제품에서 같았다.

### 4-2. 흐름 하나를 이 칸으로 적는다

| 칸 | 적는 것 | 예(오픽 33번 「한 번 더」) |
|---|---|---|
| 시작 | 말 · 클릭 · 파일 · 멘션 중 무엇으로 | 연습 답을 말로 보낸 직후 |
| 지금 | 지금 무엇이 뜨나(글 / UI) | 글. 「한 번 더 · 다음 유형 · 끝」을 글로 묻는다 |
| 모델이 부르는 도구 | 이름과 화면 유무 | `save_answer` → 채점 카드 도구 |
| 자리 | 2절의 질문으로 고른 자리 | 인라인 카드 |
| 보여 줄 것 | **하나만** 먼저 | 가장 큰 고칠 점 하나(내 문장 → 고친 문장), 예상 등급 |
| 주 단추 → 대화로 | 단추가 대화에 보내는 말 · 맥락 | 「다시 말해 보기」 → 같은 문항 다시 |
| 보조 단추 | 있으면 하나 | 「다음 문제」 |
| 모델이 덧붙일 말 | 카드를 되풀이하지 않는 한 줄, 또는 없음 | 없음 |
| 끝 상태 | 무엇이 저장되나 | 답 · 평가 저장 |
| 클라이언트 | 웹 · 데스크톱 · 음성 | 음성에서는 글만 |

「지금」이 글이고 이 칸들이 글보다 나아지지 않으면 **글로 둔다.** 오픽 52개 가운데 4 · 12 · 32 · 38 · 39번은 글이 답이었다.

### 4-3. 이 질문에 「예」가 하나라도 있어야 화면을 세운다

- 말로 쓰면 세 줄이 넘는 구조인가(지도, 표, 비교, 진행)?
- 사람이 바로 고르거나 누를 것이 있나?
- 숫자를 한눈에 보여야 하나(발화량 막대, 등급 사다리)?
- 다음 턴에도 같은 자리에서 바뀌어야 하나(진행 카드)?
- 사람의 파일 · 문서를 보여야 하나?

### 4-4. 화면 하나는 「하나 보여 주고, 대화로 돌려보낸다」

- 먼저 보여 줄 것은 **하나**다. 나머지는 크게 보기에 둔다.
- 주 단추는 대화를 잇는 말 하나다. 「다시 말해 보기」 · 「이 세트 연습」 · 「ChatGPT에서 열기」.
- 모델은 카드가 한 말을 다시 읊지 않는다. 도구 결과의 `content`(모델이 읽는 글)에 「카드가 무엇을 보였는지, 다음에 무엇을
  하면 되는지」만 적는다.

## 5. 도구 하나마다의 점검표

도구를 세우거나 고칠 때 차례대로 답한다. 답은 도구 정의 옆 주석이나 PR 본문에 남긴다.

1. **누가 부르나?** 모델만 / 화면만(`visibility: ["app"]`) / 둘 다.
2. **화면이 필요한가?** 4-3 의 질문으로 판정한다. 없으면 `content` 만 낸다.
3. **어느 자리인가?** 2절의 차례로 고른다. 들머리(`global` · `thread` · `file`)도 여기서 정한다.
4. **처음 크기는?** 인라인부터 시작한다. 넓히는 것은 넓힐 까닭(열 문서가 있다, 보고서다)이 있을 때만이다.
5. **`content` 와 `structuredContent` 를 나눴나?** 모델은 짧은 요약과 다음 할 일을, 화면은 칸이 살아 있는 데이터를 받는다.
   서버에서 글 덩이로 납작하게 펴지 않는다(오픽 `Card.body` 의 교훈).
6. **단추는 둘 이하인가?** 각 단추가 `ui/message`(대화에 말), `ui/update-model-context`(맥락만), 화면 전용 도구,
   `openai/files/open` 가운데 무엇인지 적는다.
7. **확장 밖으로 나가는가?** 나간다면 원문 링크처럼 우리 것이 아닌 곳뿐인가.
8. **빈 상태 · 실패 · 기록이 적을 때**의 얼굴이 있나. 같은 컴포넌트의 다른 상태로 그린다.
9. **이름이 영구해도 되나?** 특히 파일 들머리가 붙은 도구.
10. **어느 클라이언트에서 되나?** 웹 · 데스크톱 · 음성, 안 되는 곳의 대신할 길.
11. **스킬이 이 도구를 안내하나?** 도구가 있어도 스킬이 없으면 모델이 잘 고르지 못했다(hwp-pilot#20).

## 6. 패턴

### 6-1. 인라인 먼저, 넓히기는 까닭이 있을 때

한글파일럿 `open_hwp` 는 처음에 대화 안 작은 카드로 서고, 열 문서가 있을 때만 옆 탭으로 넓힌다(hwp-pilot#38).
처음부터 큰 탭을 열면 아직 무엇을 할지 정하지 않은 사람에게 화면이 앞선다.

### 6-2. 확장 안에서 끝낸다

사이드바 카드를 누르면 웹이 열리던 것을, 사이드바 안의 목록 · 상세 · 「뒤로」로 바꿨다(hwp-pilot#40). 밖으로 나가는 것은
원문 공고 링크 하나다. 사람은 ChatGPT 를 떠나는 순간 대화를 잃는다. ⚠ 실물 사이드바에서 도구 부르기와 맥락 넣기가 되는지는
아직 확인하지 않았다. 안 되면 웹을 여는 길로 물러선다.

### 6-3. 「대화에 추가」와 「보내기」를 가른다

| 단추 | 하는 일 | 쓸 때 |
|---|---|---|
| 대화에 추가 (`ui/update-model-context`) | 맥락만 붙인다. 사람이 이어서 말한다 | 고를 것을 모으는 중일 때. 여러 개를 담을 수 있다 |
| 보내기 (`ui/message`) | 대화에 말을 넣어 모델을 바로 움직인다 | 다음 행동이 하나로 정해졌을 때(「이 유형 연습하기」) |
| 새 대화에서 (`ui/message` + `target: "new"`) | 새 대화로 시작한다 | 지금 대화와 섞이면 안 되는 일 |

### 6-4. 화면은 작업대, 모델은 손

한글파일럿 편집기는 화면이 문서를 쥐고, 모델은 화면 없는 도구(`read_form` · `fill_form` · `edit_form` · `verify_form` · `undo`)로
세션 키를 들고 고친다. 화면은 문서의 개요와 쪽 그림을 대화에 붙여 모델의 눈이 된다. 사람과 모델이 같은 문서를 함께
만지고, 사람이 편집기에서 고친 것도 모델이 다시 읽는다.

### 6-5. 다음 한 걸음 카드

오픽 채점 카드는 고칠 점 **하나**와 「다시 말해 보기」를 보인다. 기준 여섯과 나머지는 보고서로 미룬다(Praktika 처럼 줄마다
피드백 단추를 달지 않는다). 같은 원리를 한글파일럿에 옮기면 「채운 뒤 검사 카드」가 된다. 넘친 칸 하나와 「고쳐 줘」.

### 6-6. 요약 카드 → 크게 보기 보고서

오픽 모의고사가 끝나면 대화 안에 예상 등급과 고칠 점 셋, 단추 「가장 약한 문항 다시」 「보고서 크게 보기」. 보고서는 전체 화면이다.
카드 안에서 목록 → 펼침으로 파고들던 옛 모양을 걷었다.

### 6-7. 화면 전용 도구

화면 안에서 목록을 넘기거나 상세를 여는 데이터는 모델을 거치지 않고 화면 전용 도구로 받는다(`browse_gallery`).
모델의 도구 목록이 가벼워지고, 둘러보기가 대화를 어지럽히지 않는다.

### 6-8. 사이드바는 홈, 패널은 지금 대화의 서랍

사이드바(한글파일럿 홈, 오픽 공략집)는 대화 없이 와서 둘러보는 곳이다. 패널(팀 한글 파일, 표현 서랍)은 지금 대화에 끌어올 것을
고르는 곳이다. 같은 데이터라도 패널의 주 단추는 「대화에 추가」, 사이드바의 주 단추는 「ChatGPT에서 열기」 · 「이걸로 연습하기」처럼
새 일을 시작하는 쪽이다.

### 6-9. 웹과 같은 데이터, 다른 그릇

사이드바 홈은 웹 홈과 같은 묶음 · 차례를 서버의 같은 조각에서 받는다(hwp-pilot#37). 모양(디자인 시스템 vellum)도 같다.
다른 것은 그릇이다. 웹은 페이지를 넘기고, 사이드바는 그 안에서 열고 대화로 보낸다.

## 7. 피할 것

| 피할 것 | 겪은 일 | 대신 |
|---|---|---|
| 카드 안 목록 → 펼침 · 탭 | 오픽 초기 `PluginView` 네 화면이 모두 이 꼴이었다 | 요약 카드 + 크게 보기 |
| 단추 셋 이상 | 오픽 펼침에 연습하기 · 새 대화에서 · 닫기 + 크게 보기 | 주 하나 · 보조 하나 |
| 서버에서 글 덩이로 펴기 | 전략의 뼈대 · 문법 · 팁이 `- 1. …` 글이 되어 그릴 재료가 없었다 | 칸을 살려 싣는다 |
| 웹으로 내보내기 | 사이드바 카드가 웹을 열었다 | 확장 안에서 목록 · 상세 |
| 모델이 카드를 다시 읊기 | 같은 내용이 두 번 보인다 | `content` 에 다음 할 일만 |
| 화면 없는 도구로 탭 열기 | 도구는 위젯이 아니라 열 수 없다 | 위젯 있는 도구를 거친다 |
| 도구 이름 바꾸기 | 데스크톱 「항상 이 앱으로 열기」가 깨졌다 | 처음에 사람 말로 짓는다 |
| 처음부터 큰 탭 | 할 일을 정하기 전에 화면이 앞선다 | 인라인 먼저(6-1) |
| 같은 값을 두 곳에서 따로 | 설정과 카드의 목표 등급이 어긋날 수 있다 | 정본 하나, 나머지는 보이기만 |
| 시험 · 세션 중 끼어드는 피드백 | 말하기 연구와 Duolingo 사례 | 끝난 뒤 하나부터 |

## 8. 확인하는 법

- 흐름 표(4-2)의 「클라이언트」 칸대로 데스크톱 · 웹 · 모바일에서 한 번씩 누른다. 사진을 PR 에 붙인다.
- 실물에서 먼저 볼 것: 사이드바에서 화면 전용 도구 · 맥락 넣기가 되는가, 폼이 뜨는가, 음성 모드에서 화면이 뜨는가,
  카드가 턴마다 새로 쌓이는가 한 장이 바뀌는가.
- 로컬 미리보기(`preview/server.mjs`)는 레이아웃 확인용이다. 호스트 동작은 실물로만 확인한다.

## 9. 같이 정할 것

1. ✓ **흐름 표를 어디에 둘까.** 제품마다 `docs/` 에 흐름 표 한 장을 정본으로 두고, 도구 점검표(5절)는 PR 본문 칸으로 넣는다(2026-10-18 결정).
2. ✓ **주 단추.** 패널의 주 단추는 「대화에 추가」, 사이드바의 주 단추는 일을 시작하는 「보내기」다(2026-10-18 결정).
3. ✓ **진행 중 세션의 그릇.** 화면은 PiP 를 먼저 청하게 짓는다. 호스트가 PiP 를 주지 않는 동안에는 매 턴 카드를 새로 쌓고, 실물에서 호스트 동작을 본 뒤 바꿀 수 있다(2026-10-18 결정).
4. ✓ **웹이 할 일.** 웹에도 실제 기능이 있어도 된다(2026-10-18 결정). 「확장 안에서 끝낸다」는 확장이 웹으로 내보내지 않는다는 뜻이지, 웹에서 기능을 빼라는 뜻이 아니다. 같은 데이터를 두 그릇이 함께 쓴다(6-9).
