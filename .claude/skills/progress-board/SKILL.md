# 진행 도식

> **이식 메모.** `.pr-check/progress` 는 상태 파일을 두는 자리다. 여러 스레드가 한 폴더를 함께 읽는 환경(Claude Projects 의
> `/mnt/project-files/progress`)이면 그 폴더를, 혼자 쓰는 저장소면 `.pr-check/progress` 를 쓴다. 「위젯으로 올린다」는 Claude
> Projects 의 `post_widget` 을 전제한 말이다. 위젯이 없는 환경이면 SVG 를 파일로 두고 PR 본문이나 코멘트에 링크하거나,
> 도식을 빼고 `pr:check` 의 표만 붙인다. 단계 일곱과 검사 일곱 상태가 이 스킬의 알맹이이고 붙이는 길은 환경의 몫이다.

여러 스레드가 함께 돌면 사람은 스레드에 들어가서야 그 세션이 어디까지 했는지 안다. 체크리스트는 한 줄씩
읽어야 하고, 테스트를 무엇까지 돌렸는지는 답글 사이에 흩어져 있다. 이 스킬은 그 둘을 한 장에 모은다.

- **위 줄**은 이슈에서 머지까지 일곱 단계다. 끝난 것은 초록 실선, 하는 중은 파랑, 막힌 것은 빨강, 남은 것은
  점선, 이번 일에 해당 없는 것은 흐리게 그린다.
- **가운데**는 테스트 현황이다. 검사마다 통과 · 실패 · 남의 빨강 · 못 돌림 · 아직을 색과 기호로 보이고, 못
  돌렸으면 왜 못 돌렸는지를 옆에 적는다.
- **아래**는 이번에 더한 테스트 이름과 그 색, 그리고 사람에게 지금 필요한 것 한 줄이다.

⚠ **체크리스트를 대신하지 않는다.** `update_status` 는 지금처럼 단계마다 고친다. 도식은 메시지라서 붙일 때마다
알림이 가므로, 아래 「언제 붙이나」의 자리에서만 붙인다.

## 언제 붙이나

- PR 을 열었다고 알리는 답글. 이때가 첫 도식이다.
- 테스트의 색이 바뀌어 알리는 답글. 빨강이 새로 생겼거나, 빨강을 고쳐 초록이 됐을 때다.
- 규약 점검을 마치고 리뷰를 청하는 답글.
- 사람이 진행이나 테스트를 물었을 때. 「어디까지 했어」에는 말보다 이 그림이 먼저다.

도식은 그 답글과 **같은 턴에** 붙인다. 답글 본문에서는 도식에 있는 것을 되풀이하지 않고, 그림만으로는 모르는
것(왜 그렇게 정했는지, 무엇을 골라 달라는지)만 적는다.

## 상태 파일

스레드마다 하나를 **`.pr-check/progress/<이슈 키>.json`** 에 둔다(예: `progress/WIT-45.json`). 공유
폴더에 두는 까닭은 코디네이터가 여러 스레드를 한 장에 모으기 때문이다. 단계나 테스트가 바뀔 때마다 그 파일을
통째로 다시 쓴다. 이 파일은 그 스레드만 쓴다.

```json
{
    "issue": "WIT-45",
    "title": "자문 감사 조회",
    "pr": 300,
    "updated": "2026-10-14T06:01:00Z",
    "needs": "PR #300 리뷰",
    "stages": {
        "issue": "done", "spec": "done", "redGreen": "done", "local": "done",
        "review": "done", "pr": "done", "merge": "todo"
    },
    "checks": [
        { "name": "감사 조회 계약", "state": "pass", "passed": 7, "total": 7, "detail": "메모리와 Postgres 가 같은 7건을 지남" },
        { "name": "적재 대조", "state": "foreign", "passed": 0, "total": 3, "detail": "새 DB 에 적재 뷰가 없어서이고 이번 변경과 무관" },
        { "name": "CI", "state": "skipped", "detail": "GitHub Actions 결제가 막혀 러너가 뜨지 않음" }
    ],
    "newTests": [
        { "name": "볼 수 없는 자문의 감사를 물으면 빈 목록으로 답한다", "state": "pass" }
    ]
}
```

온전한 예시는 `examples/` 에 셋 있다.

| 칸 | 무엇 |
|---|---|
| `issue` · `title` | Linear 이슈 키와 짧은 제목. 제목은 스레드 제목과 같게 둔다 |
| `pr` | PR 번호. 아직 없으면 뺀다 |
| `updated` | 이 파일을 쓴 때(UTC). 그림에는 한국 시간으로 찍힌다 |
| `needs` | 사람에게 지금 필요한 것 한 줄. 없으면 뺀다. 그림에 「필요한 것 없음」으로 선다 |
| `stages` | 일곱 단계의 상태. 아래 표 |
| `checks` | 테스트와 검사의 현황. 아래 「검사를 적는 법」 |
| `newTests` | `spec-by-test` 로 지은 `it(...)` 이름과 그 색. 열 개를 넘으면 「외 n개」로 줄인다 |

**단계**는 루트 `CLAUDE.md` 「개발 과정」의 순서를 그대로 따른다. 상태는 `done` · `doing` · `blocked` · `todo` · `na` 가운데 하나다.

| 키 | 그림의 이름 | 끝난 때 |
|---|---|---|
| `issue` | 이슈 | 이슈를 읽고 In Progress 로 옮겼다 |
| `spec` | 테스트 이름 | `it(...)` 목록을 사용자에게 보였다 |
| `redGreen` | 빨강→초록 | 이번에 더한 테스트가 모두 초록이다 |
| `local` | 로컬 테스트 | `npm run pr:check` 에 이번 변경 때문인 빨강이 없다. 남의 빨강과 못 돌린 칸은 까닭이 적혔다 |
| `review` | 규약 점검 | 보안 · 코드 규약 · 화면 글 점검을 지나고 지적을 고쳤다 |
| `pr` | PR | 초안 PR 을 열고 이슈를 In Review 로 옮겼다 |
| `merge` | 머지 | PR 이 머지됐다 |

`na` 는 묻기만 하는 질문의 이슈처럼 그 단계가 없는 일에만 쓴다. `todo` 로 남기면 아직 안 한 일로 읽힌다.

## 검사를 적는 법

상태는 일곱이다.

| `state` | 그림 | 언제 |
|---|---|---|
| `pass` | ● 초록 | 돌렸고 통과했다 |
| `fail` | ✕ 빨강 | 돌렸고 이번 변경 때문에 깨졌다. `detail` 에 무엇이 깨졌는지 적는다 |
| `foreign` | △ 노랑 「남의 빨강」 | 빨갛지만 이번 변경과 무관하다. `detail` 에 왜 무관한지 적는다 |
| `running` | ◐ 파랑 | 지금 돌고 있다 |
| `skipped` | ◌ 노랑 「못 돌림」 | 돌려야 하는데 못 돌렸다. `detail` 에 까닭을 적는다 |
| `todo` | ○ 회색 | 아직 돌리지 않았다 |
| `na` | – 흐린 회색 | 이번 일에는 돌릴 것이 없다 |

스크립트는 `fail` · `foreign` · `skipped` 에 `detail` 이 없으면 그리지 않는다. 그 셋은 까닭이 그림의 알맹이다.

- **돌리지 않은 것도 적는다.** typecheck · 단위 · 계약 · build · e2e · Vercel 빌드 · 규약 점검 가운데 이번 일에 걸리는
  것은 모두 한 줄씩 둔다. 줄이 빠지면 보는 사람은 그것을 돌렸는지 알 수 없다.
- **수는 실제 출력에서 옮긴다.** vitest 와 Playwright 가 찍은 통과 수와 전체 수를 `passed` · `total` 에 적는다.
  출력을 보지 않은 수는 적지 않고, 그때는 두 칸을 빼고 상태만 둔다.
- **CI 는 GitHub Actions 결제가 풀리기 전까지 `skipped` 다.** 까닭은 「GitHub Actions 결제가 막혀 러너가 뜨지
  않음」으로 적는다. 로컬에서 같은 것을 돌렸으면 그 줄들이 초록으로 따로 선다.
- **키나 스택이 없어 못 돌린 것**도 `skipped` 다. 계약 테스트를 로컬 Supabase 없이 건너뛰었거나, 외부 API 키가
  없어 어댑터 검사를 못 돌렸으면 그 까닭을 그대로 적는다(「MODUSIGN_API_KEY 가 없어 실 API 검사 건너뜀」).
- 남의 빨강과 내 빨강을 섞지 않는다. 같은 패키지의 검사라도 이번 변경과 무관한 실패는 따로 한 줄로 떼어
  `foreign` 으로 둔다.

## 그리는 법

```
node .claude/skills/progress-board/scripts/render.mjs .pr-check/progress/WIT-45.json
```

찍힌 SVG 를 `post_widget` 으로 스레드에 붙인다.

- `family` 는 `visualize`, `widget` 은 `show_widget` 이다.
- `input.title` 은 `<이슈 키>-progress` 로 둔다(예: `WIT-45-progress`). 위젯 제목은 영문 · 숫자 · `-` · `_` 만 받는다.
- `input.widget_code` 에 SVG 를 그대로 넣는다. 색은 위젯이 밝은 화면과 어두운 화면에 맞춰 입히므로 손대지 않는다.
- `text` 에는 그림을 못 보는 자리에서 읽힐 한 줄을 적는다(「WIT-45 진행: PR 열림, 계약 7/7 통과, CI 못 돌림」).

체크리스트 머리에는 테스트 현황을 한 줄로 넣어 둔다. 그림을 다시 붙이지 않는 사이에도 스레드 카드에서 보인다.

```
node .claude/skills/progress-board/scripts/render.mjs --summary .pr-check/progress/WIT-45.json
# typecheck ● · 감사 조회 계약 7/7 ● · 적재 대조 0/3 △ · build ○ · CI ◌
```

## 여러 스레드를 한 장에

코디네이터가 「다들 어디까지 했나」에 답할 때는 상태 파일을 모아 넘긴다. 스레드마다 한 줄씩, 일곱 단계의
점과 테스트 요약과 필요한 것이 선다.

```
node .claude/skills/progress-board/scripts/render.mjs .pr-check/progress/*.json
```

스레드를 닫을 때 그 상태 파일을 지운다. 남겨 두면 모아 그린 그림이 끝난 일로 길어진다.

⚠ **그림은 상태 파일만큼만 맞다.** 파일을 고치지 않고 일을 진행하면 그림이 거짓말을 한다. 단계나 테스트가
바뀌는 턴에는 `update_status` 와 함께 상태 파일도 고친다.
